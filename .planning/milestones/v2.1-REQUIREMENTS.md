# Requirements: United Tactical Forces - v2.1 Server Experience Reimagined

**Defined:** 2026-11-18
**Core Value:** Authorized users can operate cloud game servers through durable, auditable lifecycle jobs with a clearly assigned cost owner, including reliable recovery and verified provider cleanup.

## v2.1 Requirements

All UI requirements target `sources/ReactApp` only. The UI is game-agnostic and driven by server capabilities.

### Foundations

- [x] **FND-01**: Server screens use shared semantic design tokens for state, cost, spacing, elevation, and motion
- [x] **FND-02**: A server shows the same status on the fleet, workspace header, and notifications, derived from one shared state model
- [x] **FND-03**: A server that may still incur cost is never labelled as off or stopped
- [x] **FND-04**: Every cost-bearing action (start, create and start, cost-stop) opens one confirmation showing estimated cost, cost owner, and how to stop
- [x] **FND-05**: An `?action=` deep link to a cost-bearing action opens the same confirmation, or shows why the action is unavailable
- [x] **FND-06**: Redesigned screens are fully keyboard operable and pass automated accessibility scans (axe, WCAG AA)
- [x] **FND-07**: A parity matrix confirms no existing server capability is lost in the redesign

### Localization

- [x] **L10N-01**: The React app owns its English and German translations as JSON inside `sources/ReactApp` and no longer reads the Blazor RESX files
- [x] **L10N-02**: A check fails the build when any English key lacks a German value
- [x] **L10N-03**: Redesigned server screens contain no hard-coded user-facing text

### Access

- [x] **ACC-01**: A member holding the `sv` or `sv:view` claim can open the server section and see the servers they may view, verified end to end including the API response
- [x] **ACC-02**: A member can find the server section from the main navigation without going through admin-oriented framing
- [x] **ACC-03**: An action the member cannot perform is shown disabled with the reason

### Fleet

- [x] **FLT-01**: User sees every visible server with status, owner, cost indicator, and primary action in one scan
- [x] **FLT-02**: User can search and filter servers (mine, running, off)
- [x] **FLT-03**: Off servers are grouped but remain visible
- [x] **FLT-04**: User can start or stop a server from the fleet through the cost confirmation
- [x] **FLT-05**: The fleet is usable at 320px width

### Workspace

- [x] **WSP-01**: A persistent server header shows status, owner, cost strip, connection endpoint with copy, and the primary action
- [x] **WSP-02**: User navigates server sections through deep-linkable section navigation; retired `?tab=` values open Overview (D-02)
- [x] **WSP-03**: Section navigation does not clip on mobile (UI-60-001 resolved)
- [x] **WSP-04**: User sees a progress strip with the current stage during long lifecycle jobs
- [x] **WSP-05**: A failed job shows what failed, whether the server may still cost money, and the next step
- [x] **WSP-06**: User sees breadcrumbs from fleet to server to section

### Cost

- [x] **CST-01**: Cost strip shows owner, hourly and monthly rate, and whether the server is costing now
- [x] **CST-02**: User can run the cost-stop in plain words ("shut down and stop billing"), using one consistent vocabulary across the UI
- [x] **CST-03**: User sees accrued cost for the current session (control plane calculates it)
- [x] **CST-04**: Cost owner receives an in-app alert when a configured cost threshold is reached
- [x] **CST-05**: Cost owner receives the same alert as a Discord DM through the existing bot
- [x] **CST-06**: Cost owner receives the same alert by email through a new email channel

### Create

- [x] **CRT-01**: User creates a server through a guided flow with at most three decisions and advanced options behind disclosure
- [x] **CRT-02**: User sees a live cost estimate while creating
- [x] **CRT-03**: Creation is blocked early, with the reason, when the cost owner cannot pay
- [x] **CRT-04**: User chooses "create and keep off" or "create and start"
- [x] **CRT-05**: User can pick a create preset, and presets default to keep off
- [x] **CRT-06**: Create steps are generated from server capabilities, not game-specific code

### Change

- [x] **CHG-01**: User changes a server's mods through a capability-driven picker using existing mod pack capabilities
- [x] **CHG-02**: User changes configuration through settings grouped into Common and Advanced
- [x] **CHG-03**: User stages several changes, reviews them, and applies them explicitly
- [x] **CHG-04**: The UI states when changes take effect (next start)
- [x] **CHG-05**: User is warned before leaving a section with unsaved changes
- [x] **CHG-06**: User manages server files with the current folder reflected in the URL (`?path=`)
- [x] **CHG-07**: Secrets stay hidden unless the user is allowed to see them, and are never logged

### Activity

- [x] **ACT-01**: User sees one timeline merging jobs, logs, and audit events in readable language
- [x] **ACT-02**: Logs remain available with a visible freshness indicator

### Automation

- [x] **AUT-01**: Owner can set an idle shutdown after N minutes without players or activity
- [x] **AUT-02**: Owner can set a maximum runtime after which the server stops
- [x] **AUT-03**: Owner can schedule start and stop times
- [x] **AUT-04**: Owner is warned shortly before an automatic stop
- [x] **AUT-05**: Automatic stops run as durable lifecycle jobs with an audit entry and verified non-billable teardown
- [x] **AUT-06**: Schedules and idle timers survive API restarts

### Metrics

- [x] **MET-01**: User sees uptime (running since) for a running server
- [x] **MET-02**: User sees current player count where the game exposes it
- [x] **MET-03**: User sees CPU and memory usage of the server machine
- [x] **MET-04**: User sees a short retained history of these metrics as charts
- [x] **MET-05**: Metrics arrive through the worker protocol, and unavailable metrics are shown as unavailable, never as fake values

### Consistency

- [x] **CON-01**: React pages share one page header rhythm
- [x] **CON-02**: React pages share common loading, empty, and error state panels
- [x] **CON-03**: Navigation labels, spacing, and badge tones are consistent across React pages on an agreed closed list

### Verification

- [x] **VER-01**: Route certification tests stay green and are updated whenever routes or URL parameters change
- [x] **VER-02**: End-to-end journeys pass for create then start, change mods, and German locale
- [x] **VER-03**: Playwright runs mobile (320 and 390) in English and German, with visual baselines for key screens

## Future Requirements

- **FUT-01**: Mod catalog search and install
- **FUT-02**: Truthful "restart required" drift badge (needs API signal)
- **FUT-03**: Server-defined presets
- **FUT-04**: Undo or revert of applied changes

## Out of Scope

| Feature | Reason |
|---------|--------|
| Changes to `sources/WebApp` (classic UI) | Outdated; kept only as rollback variant |
| New game implementations (e.g. Minecraft) | UI is game-agnostic; examples only |
| Full redesign of non-server pages | Light consistency pass only |
| Kill button / live-applying config | Unsafe: leaves billing or corrupts running state |
| Console-first layout | Wrong default for non-expert members |
| Budgeting inside the server UI | Belongs to hosting finance |
