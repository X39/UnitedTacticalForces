Create the reusable spending-policy gate and integrate it before billable cloud action execution.

Purpose: Existing provisioning, teardown, and cloud runtime endpoints currently proceed after authorization without using the Phase 21 evaluator. This plan adds the gate boundary and returns visible policy results before execution for non-allow outcomes.
Output: Gate status contract, gate result DTO, gate service, controller integration, and focused tests proving blocked outcomes do not call mutation/enqueue services.
</objective>

## Task 1: Add gate result contract and RED tests

- Add failing tests for a gate service that maps:
  - dry-run provisioning to `ECloudBillableActionKind.CloudProvisioning`
  - cloud runtime start to `RuntimeStart`
  - cloud runtime restart to `RuntimeRestart`
  - cloud runtime install/update/upgrade to `RuntimeUpdate`
  - provider teardown to `ProviderTeardown`
  - future resize extension call to `ProviderResize`
- Add failing tests that `Warn`, `ApprovalRequired`, and `Deny` return a visible gate result and do not invoke fake provisioning/lifecycle/teardown services.
- Add reflection tests that the gate service has no provider mutation or generated client dependencies.

## Task 2: Implement gate service and DTO mapping

- Add `ECloudSpendingPolicyGateStatus` contract enum with stable values for `Allowed`, `WarningAcknowledgementRequired`, `ApprovalRequired`, and `Denied`.
- Add `CloudSpendingPolicyGateResultDto` and `Transform.ToDto(...)`.
- Add `ICloudSpendingPolicyGateService` and implementation that:
  - resolves billing/session/scope inputs from dry-run plan, cloud session, or game server
  - builds a `CloudSpendingPolicyEvaluationPayload`
  - delegates to `ICloudSpendingPolicyEvaluationService`
  - classifies gate status from the persisted decision
  - keeps future resize available through a service method without adding a production endpoint

## Task 3: Integrate gate before existing mutation/enqueue paths

- Inject the gate service into `CloudInventoryController` and `GameServersController`.
- Run the gate before `ProvisionDryRunPlanAsync`, `TeardownSessionAsync`, and cloud-session lifecycle enqueueing.
- Return `Conflict(gateResultDto)` for warning acknowledgement required, approval required, and denied statuses.
- Preserve existing local game-server lifecycle behavior when no active cloud session exists.
- Verify `dotnet build sources/Api/Api.csproj --no-restore --verbosity minimal`.

</tasks>
