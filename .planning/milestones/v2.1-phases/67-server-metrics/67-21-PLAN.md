<objective>
Close the one blocking gap of `67-VERIFICATION.md` (truth 5a, review finding CR-01), tracer-first: in an open workspace, a server that is stopped or restarted shows the control plane's reason on its metric tiles instead of the previous run's values. The tracer proves it end to end on the REST path: the panel holds a running reading, the fleet signal refetches, the API answers with no as-of time and `server-not-running`, and all four tiles read "Unavailable" with the not-running sentence. The expansion moves the live frame path onto the same rule and removes the old one, so the rule lives in one place.

Purpose: the merge treated a reading without an as-of time as older than any cached reading. The API sends exactly that shape for a stopped server and for a new deployment before its first sample, so the tiles kept showing the last CPU, memory, player and running-since values as current. They then switched to the generic "too old" sentence, never to "The game is not running". This breaks roadmap criterion 5 ("A stopped server ... shows metrics as unavailable, never as ... a fake value") and the open UAT step 7. The same merge also re-stamped an unchanged reading on every refetch (WR-12), which could keep a value on screen for up to twice the stale threshold. The new rule fixes that as a side effect.

Output: one shared merge rule `replacesCachedReading` in `metricsFrames.ts`, used by `useServerMetrics` and `FleetLiveUpdatesProvider`. The old helpers in `metricsModel.ts` and `metricsFrames.ts` are deleted. The plan adds panel regression tests for stop, restart and the kept receive stamp, a unit matrix for the rule and updated frame tests, and marks CR-01 and WR-12 fixed in the review disposition.
</objective>

Claude's discretion recorded here (the rule details; the CR-01 proposal in 67-REVIEW.md is the source):
- A reading without an as-of time always replaces the cached one when the facts differ. The control plane sends it only when the active deployment has no snapshot: stopped, provisioning, or a new run before its first sample. Such a reading is the current truth, never an older sample.
- A reading that is older by as-of time is refused only if it still holds a value (running since, CPU, memory used or player count). An older reading of reason codes only replaces the cached one. It can turn tiles unavailable until the next frame, but it can never show an old number as live, which is the safe direction for D-09.
- Equal facts keep the cached entry and its receive stamp, for REST and frames alike (closes WR-12; frames already behaved this way since plan 67-17).
- The rule lives in `metricsFrames.ts`, because `metricsModel.ts` already imports `historyBucketMs` from it and the reverse import would create a cycle.
