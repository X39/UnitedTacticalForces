# Phase 67 - UI Design Contract

> Visual and interaction contract for Phase 67: Server Metrics.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Scope: `sources/ReactApp` plus the API, shared-contract and database changes this feature needs (`67-CONTEXT.md`, `AGENTS.md`: the API is not a frozen contract). The worker transport rewrite (D-01, D-02), the samplers and the retention job are control-plane and worker work with no UI contract beyond the data semantics below. `sources/WebApp` (legacy Blazor) is not updated and the generated Kiota client under `sources/WebApp/UtfApi` is never hand-edited. Regenerate the OpenAPI snapshot and `src/generated/api.ts` (`npm run contracts:generate`).
> Requirements covered: MET-01, MET-02, MET-03, MET-04, MET-05 (the React surface of them).
> Inherits without change: `61-UI-SPEC.md` (design system, spacing, typography, color, state and cost model, localization, token rules, copy rules, German "du"), `63-UI-SPEC.md` (workspace shell, Overview section, the reserved `data-slot="metrics"` panel) and `66-UI-SPEC.md` (the live-socket display rules: the 3 s anti-flicker disconnect delay, "the browser displays, it never calculates", no `refetchInterval`, the toast and live-region discipline, panel and card styling). This file only adds or overrides what server metrics need. Anything not stated here is exactly as in Phases 61, 63 and 66.

A member opening a running server should see in one glance whether it is up, who is on it and whether the machine is coping, and be able to look back over the last hour, day or week without leaving the page. The page stays a quiet working tool: a value is shown exactly as the control plane sent it, a value that could not be measured says "Unavailable" and why (never zero, never a dash, never an interpolated line), and the history is a plain line with its gaps left open. The browser displays; it never samples, extrapolates or invents.

## Research Findings That Shape The Contract

Verified in code on 2026-11-21 (`67-RESEARCH.md` plus this session's reads). They resolve the discretion items in `67-CONTEXT.md` for the UI.

| Question | Finding | Consequence |
|----------|---------|-------------|
| What occupies the metrics slot today? | `OverviewSection.tsx` renders `SlotPlaceholder variant="panel" slot="metrics"` in the right cell of `.workspace-overview__row`, a `2fr 1fr` grid at >= 800px (`sections.css`). The right cell is about 350px wide at 1280px. | Four tiles plus three charts do not fit a one-third column. The panel becomes full width below the details panel; the row grid is one column at every width. `data-slot="metrics"` moves onto the new panel `section`. DOM order is unchanged: details, metrics, recent activity, more actions. |
| Is there a chart library? | No. `package.json` has no chart dependency, and the research recommends none (three single-series lines with gap breaks). | Hand-built SVG chart components. No new npm package, so no package-legitimacy checkpoint and no third-party registry. |
| Is there a range switcher control? | Yes: `FilterChipGroup` (`@/components/FilterChipGroup`): real buttons with `aria-pressed`, a check icon plus stronger border for the pressed chip, never disabled, Tab order only. | The 1 hour / 24 hours / 7 days switcher is a `FilterChipGroup`. No new control, no `<select>`, no `<details>` (owner dislike, Phase 65 UAT). |
| How are stale and disconnect shown today? | `useDelayedDisconnect()` (3 s continuous disconnect) drives the carried sentence `Server_Live_StaleReason_Disconnected`; `useNow(intervalMs)` is the shared clock hook; `formatInstant(instant)` formats a clock time, adding a short date when the instant is not today. | The metrics panel reuses all three. Nothing new is invented for freshness. |
| Which colors can a data line use? | `--info`, `--success`, `--warning`, `--danger` and `--gold` carry state or accent meaning; gold is reserved for the primary action and the focus ring. Status colors are reserved for state in the dataviz method. The info blue (`#79a9df`, OKLCH L 0.76) is also outside the validated dark chart band (0.48 to 0.67). | One new data hue is added as a token (`--utf-chart-line`), validated with `validate_palette.js` against the panel surface (see Color). All three charts use it; identity comes from each chart's own title, not from color. |
| Do the units match the app? | `Server_Create_Size_Option` prints "{{memory}} GiB RAM" in both languages. | Memory shows GiB (binary, divide by 1024^3), never "GB". |
| Which wording exists for the machine? | The UI already says "worker" ("Waiting for worker", "dedicated worker") and German "Arbeitsspeicher" for memory. | Reason copy may say "worker"; German memory is "Arbeitsspeicher". |
| What does the API decide? | `67-RESEARCH.md` Pattern 4 and Pitfall 6: the API evaluates availability (server state, worker liveness, sample age, game capability) and sends `null` plus a reason code; the browser maps codes to EN/DE copy and only re-ages the last sample against a server-sent threshold. | The panel never derives a reason from server status strings. A new code it does not know shows a generic sentence (fixed fallback, never `ApiText`). |

## Data The UI Needs (API changes)

The contract names the semantics; exact names, DTO shapes, routes and frame types are the planner's call (`67-RESEARCH.md` proposes `GET game-servers/{id}/metrics?range=` and a `GameServerMetricsMessage` frame). Regenerate the OpenAPI snapshot and the clients, add tests in the owning layer (AGENTS.md).

| Need | Where | Semantics |
|------|-------|-----------|
| Current readings | REST read model, and the same object in a pushed frame keyed by server id | `asOf` (API time of the newest accepted sample, null when none ever arrived), `staleAfterSeconds` (the API's threshold, three report intervals), and four readings. `runningSince`: instant or null. `cpu`: percent 0 to 100 or null. `memory`: `usedBytes` and `totalBytes` or null. `players`: `count` and `capacity` (capacity may be null) or null. Every reading is either a value or a reason code, never both and never a default value. Reason codes (closed list, lower-case strings): `server-not-running`, `worker-offline`, `stale`, `game-does-not-report` (players only), `query-failed`, `measuring`, `unsupported-platform`. The API decides availability from server state, worker liveness, sample age and game capability (D-09); the browser never derives a reason from status strings. |
| History series | REST, `range` = `1h`, `24h` or `7d` | `from`, `to` (API instants), `bucketSeconds` (15, 60 or 300 for the three ranges), and `points`: per bucket `t` (bucket start instant) plus `cpu`, `memoryUsed`, `players`, each `{ avg, min, max }` or null when the bucket holds no reading for that metric. Also `memoryTotalBytes` and `playerCapacity` (nullable). Min and max survive downsampling (D-05). A bucket the worker never reported is simply absent from `points`; the API never fills gaps with zeros. History comes from PostgreSQL, so a reload shows the same series (MET-04). |
| Live frame | update stream, the viewer's per-user path | The current-readings object for one server, sent about once per report interval to viewers with the server view permission only (same audience as the fleet and accrued cost). The client writes it into the query cache by server id; it never extrapolates between frames. |
| Players semantics | worker via the API | `count` is human players only: Arma 3 headless clients and CS2 bots are excluded by the worker (`67-RESEARCH.md` Pitfalls 7 and 8). A game that cannot report it sends `game-does-not-report`. |
| Authorization | API | The metrics read requires the server view claim, like the workspace. No new visibility rule (per-member metric visibility is deferred in `67-CONTEXT.md`). |

Assumptions the planner confirms or amends (they do not change the visual contract unless stated):

| Id | Assumption | If wrong |
|----|-----------|----------|
| M1 | Report interval 15 s, stale threshold 45 s (3 x), sent as `staleAfterSeconds`; the heartbeat is independent (`67-RESEARCH.md` A6). | The browser reads the threshold from the API, so nothing changes in the UI. |
| M2 | Tier buckets are 15 s (1 hour), 60 s (24 hours) and 300 s (7 days), so a series holds at most 240, 1,440 and 2,016 points. | The gap rule is 2 x `bucketSeconds` from the response, so any tier values work. The performance backstop below uses the real maximum. |
| M3 | Memory is reported container-bounded (`memory.max` or machine total) in bytes (`67-RESEARCH.md` A4). | The tile and chart label stay "Memory"; only the description sentence may change. |
| M4 | `runningSince` is the game process start of the primary host. | A restart moves the time; the tile copy is unchanged. |
| M5 | Only the primary host is shown. Headless client hosts are not metered in v1. | Out of scope; recorded below. |
| M6 | ASKA may never report players; its players tile and chart then read "This game does not report player counts." (D-06 allows exactly this). | Copy is unchanged; the tile simply shows a value instead. |

## Surface Anatomy

### 1. Metrics panel (MET-01 to MET-05)

`<section className="workspace-panel" data-slot="metrics" aria-labelledby={headingId}>` in the Overview section, full width, directly after the details panel. DOM order:

| Order | Element | Renders when | Notes |
|-------|---------|--------------|-------|
| 1 | `h2` "Server metrics" (carried key) | always | Heading 20/700 from `.workspace-panel h2`. |
| 2 | Description `p.workspace-panel__muted` | always | One sentence (see Copywriting). |
| 3 | Paused notice `p` with `Warning16Regular` (`aria-hidden`) and the carried sentence `Server_Live_StaleReason_Disconnected` | `useDelayedDisconnect()` is true | Body 14/400 in `--utf-state-warning-fg`, same look as the accrued stale line; not a live region (matches Phase 66). Tiles and charts keep their last values. |
| 4 | Status region `p.sr-only`, `role="status"` | always mounted | The only announcement of the panel: the range change (see Interaction Contract). |
| 5 | Tiles `dl` | readings loaded | Four tiles (below). |
| 6 | Toolbar `div` | readings loaded | Range `FilterChipGroup` on the left, view toggle on the right. |
| 7 | Views region `div#{viewsId}` | readings loaded | Three charts (default) or three tables. |

While the readings are loading, items 5 to 7 are replaced by one `StatePanel kind="loading"` ("Loading metrics..."). When the readings fail to load and no data is cached, they are replaced by one `StatePanel kind="error"` with a "Try again" button (carried `Server_Settings_Retry`); a failed background refetch with data held changes nothing visible. A cached value of another server is never shown (the query key carries the server id).

### 2. Tiles (MET-01, MET-02, MET-03, MET-05)

`dl.server-metrics__tiles`; each tile is a `div.metric-tile` holding a `dt` and a `dd`. DOM and visual order: Running since, Players, CPU, Memory. The four tiles are always rendered together (no tile is hidden when unavailable).

| Part | Element | Content |
|------|---------|---------|
| Term | `dt` | Label 12/700 in Barlow Condensed, uppercase, 0.06em tracking, `--utf-text-muted` (same rule as the cost strip `dt`). |
| Value | first line of `dd` | Heading 20/700, `font-variant-numeric: tabular-nums` (tile values update live and must not jitter), `overflow-wrap: anywhere`. Or the unavailable word (below). |
| Detail | second line of `dd` | Body 14/400 `--utf-text-muted`. |
| Reason | second line of `dd` instead of the detail | Body 14/400 `--utf-text-muted`, the mapped reason sentence. |
| Last reading | third line of `dd` | Body 14/400 `--utf-text-muted`, "Last reading: {{time}}" in `<time datetime>`, only for the reasons `worker-offline` and `stale` and only when `asOf` is known. |

Tile surface: `--utf-surface-base` background, 1px `--utf-border-divider` border, `--utf-radius`, `--utf-space-md` padding, `--utf-space-xs` between lines. All tiles in a row stretch to the same height.

Values (all through `Intl` with `currentLocale()`):

| Tile | Value | Detail |
|------|-------|--------|
| Running since | `<time datetime>` with `formatInstant(runningSince)`: a clock time today, a short date and time otherwise. No ticking "up for" duration (D-07, and the browser does not calculate). | none |
| Players | the integer count; `0` is a valid reading and renders `0` | "of {{count}} slots" (plural keys) when `capacity` is known, otherwise none |
| CPU | `Intl.NumberFormat(locale, { style: "percent", maximumFractionDigits: 0 })` of `cpu / 100` | none |
| Memory | `usedBytes / 1024^3` with at most one decimal and the unit key `Server_Metrics_Memory_Value` ("{{value}} GiB") | "of {{total}}" with the same GiB format when `totalBytes` is known |

Unavailable rule, first match wins (the same for all four tiles):

| Order | Condition | Value | Second line |
|-------|-----------|-------|-------------|
| 1 | The reading is null with a reason code | `Info16Regular` (`aria-hidden`) then "Unavailable" in `--utf-text-muted` | the reason sentence for the code (`Map` lookup in `metricsModel`) |
| 2 | The reading is null with an unknown or missing code | the same | the generic sentence "No reading is available." |
| 3 | The reading holds a value but the browser's age check says stale (below) | the same | the `stale` reason sentence and the last-reading line |
| 4 | Otherwise | the formatted value | the detail, if any |

Browser stale check: the tile is stale when the elapsed time since the response or frame carrying the reading was received (measured with `performance.now()`, not the wall clock against the API timestamp, so a skewed browser clock cannot fake freshness) exceeds `staleAfterSeconds`. It is re-evaluated by `useNow(5000)`. Charts do not use this check; they show the series as the API sent it.

The word "Unavailable" is a fact, not an alarm: no warning or danger color, no badge. The paused notice and the server state elsewhere on the page carry attention.

### 3. Toolbar (MET-04)

One row directly above the views, scoping everything below it:

| Part | Control | Notes |
|------|---------|-------|
| Range | `FilterChipGroup`, group label "Time range", chips "1 hour", "24 hours", "7 days" | One chip is pressed (default "1 hour"). Selecting the pressed chip is a no-op. State is React state only; a reload returns to 1 hour (the history itself comes from the API, not from the state). |
| View | `ActionButton variant="ghost"` "Show data as tables" while charts show, "Show charts" while tables show; `aria-controls` the views region | A text-swapping toggle without `aria-pressed` (the label already states the result). Focus stays on the button after activation. Applies to all three metrics at once. |

The toolbar never renders inside a chart card and has no per-chart controls.

### 4. Charts (MET-04, MET-05)

Three charts in the views region, in order: CPU load, Memory used, Players. Each is its own `section` with `aria-labelledby`:

| Order | Element | Content |
|-------|---------|---------|
| 1 | `h3` chart title | Body 14/700, the metric name ("CPU load", "Memory used", "Players"). |
| 2 | Summary `p` | Body 14/400 `--utf-text-muted`: "Highest: {{value}}, {{time}}" selecting the largest `max` in the series (a selection, not arithmetic). Omitted when the series has no point. |
| 3 | Plot | A focusable `div[role="group"]` (see Interaction Contract) containing the SVG, the tooltip and, when there is nothing to plot, the empty sentence. Height `--utf-metric-chart-height`, width 100%. |
| 4 | Gap note `p` | Body 14/400 `--utf-text-muted`, "Gaps mean no reading was available. Nothing is estimated." Rendered only when the plotted range contains at least one broken segment or an empty stretch. |

Plot geometry (hand-built SVG, measured width through `ResizeObserver`; all insets are multiples of 4px: left gutter = the widest y tick label plus 8px, bottom inset 24px, top and right inset 8px):

| Aspect | Rule |
|--------|------|
| X domain | `[now - range, now]` where `now` comes from `useNow(bucketSeconds * 1000)`, so an old last sample leaves a visible empty stretch at the right edge. The browser clock only places the edge. |
| X ticks | Four at widths of at least `--utf-metric-chart-min`, three below. Labels Label 12/400 `--utf-text-muted`. 1 hour and 24 hours: clock time (`timeStyle: short`); 7 days: short weekday plus short date. All through `Intl.DateTimeFormat(currentLocale())`. |
| Y domains | CPU: fixed 0 to 100 percent. Memory: fixed 0 to `memoryTotalBytes` (when null, 0 to the highest `max`, rounded up to a nice number). Players: 0 to the nice ceiling of the larger of `playerCapacity` and the highest `max`, integer ticks only. |
| Y ticks | Three: bottom, middle, top, each with a horizontal gridline. Labels Label 12/400 `--utf-text-muted`; one number style per axis (percent, GiB with at most one decimal, integer). Axis lines are not drawn; the bottom gridline is the baseline. |
| Grid | 1px solid `--utf-chart-grid`, horizontal only, recessive. |
| Line | 2px `--utf-chart-line`, round join and cap. CPU and memory are straight segments between consecutive points; players is a stepped line (`step-after`) because a count is an integer that holds until it changes. |
| Band | The min-max band behind the average line, filled with `--utf-chart-band` (a 12 percent wash of the line hue). Drawn only where `max` is above `min`. It follows the line's interpolation, including the step for players. This is how a spike survives downsampling (D-05). |
| Gaps | A segment ends and a new one starts when a point is null for that metric or the distance to the previous point is more than `2 x bucketSeconds`. Nothing is drawn across a gap and no zero is ever drawn. `buildSegments` in `metricsModel.ts` is the only place that decides this. |
| Isolated point | A segment of one point renders an 8px marker (r 4) filled `--utf-chart-line` with a 2px ring in `--utf-surface-raised`, not a zero-length line. |
| Data end | The line ends at the last accepted point; there is no end label (the tile carries the current value). |

Empty plot (no point at all in the range): the plot keeps its full height (no layout shift) and shows two centered lines instead of the axes: "No readings in this time range." and, muted, "Readings are collected while the server is running." For the Players chart, when the current readings say `game-does-not-report`, the first line is instead the sentence "This game does not report player counts." and no second line.

Tooltip (a hover and focus enhancement; every value in it is also in the table view): a small box inside the plot, `--utf-surface-overlay` background, 1px `--utf-border-divider` border, `--utf-radius-small`, `--utf-space-sm` padding, `max-width: var(--utf-metric-tooltip-width)`, `pointer-events: none`, `aria-hidden="true"`. Content, top to bottom: the bucket time (Body 14/400 muted); the average with a short 2px stroke key in `--utf-chart-line` and the value in Body 14/700 ("Average 37%"); and, when `min` differs from `max`, "Lowest {{low}}, highest {{high}}" in Body 14/400 muted. The box flips to the other side of the crosshair near the right edge and is clamped inside the plot. The crosshair is a 1px solid `--utf-border-control` vertical line that snaps to the nearest point of the series (nearest in X, so the pointer never has to land on the line); a point inside a gap is not selectable.

### 5. Table view (MET-04, accessibility path)

The same three metrics as three tables in the views region, stacked in one column. Each table sits in `div[role="region"][tabindex="0"]` with `aria-label` equal to the caption, `max-height: var(--utf-output-max-height)`, `overflow: auto`, so it never widens the page and a keyboard user can scroll it.

| Part | Rule |
|------|------|
| Caption | `<caption>` "{{metric}}, {{range}}" (the same sentence as the chart's accessible name). Visible, Body 14/700, left aligned. |
| Columns | Time, Average, Lowest, Highest. Header cells are `th scope="col"`, Label 12/700; values are Body 14/400 with `font-variant-numeric: tabular-nums`, right aligned. |
| Rows | One row per bucket that has a reading, newest first. The time cell uses `formatInstant`, with the short date added when the range is 7 days. |
| Gap rows | Each contiguous gap (more than `2 x bucketSeconds` between consecutive buckets, or between the last bucket and now) is one row with one cell spanning all columns: "No readings from {{from}} to {{to}}", Body 14/400 muted. A bucket with no reading for this metric inside a reporting run is part of the gap. |
| Empty | The same two sentences as the empty plot, in one row. |
| Header | The header row is `position: sticky; top: 0` on `--utf-surface-raised` so it stays visible while the region scrolls. |

## Interaction Contract

### Live behavior and freshness (MET-05, D-09)

- The first value comes from REST with the workspace; later values arrive as socket frames on the shared fleet socket and are written into the query cache by server id. Nothing in the metrics files polls, runs its own `setInterval` (the only clock is `useNow`) or reads the worker. The browser opens no second socket. A source-scan test asserts the absence of `refetchInterval`, a raw `setInterval`, a chart-library import and an unchanged `package.json` dependency list.
- A frame updates the tiles and appends its reading to the 1 hour series. The 24 hour and 7 day series change by one coalesced refetch of the active range at most once per bucket interval (60 s and 300 s), triggered by a frame, and on open and on reconnect (`67-RESEARCH.md` open question 6; the planner may simplify to refetch-on-frame throttled to the bucket interval, but may not add a timer or a worker poll).
- Disconnected: the tiles and charts keep their last values; after 3 s of continuous disconnect the paused notice appears; reconnect removes it and refetches the current readings and the active range once. A short blip never flickers.
- A reading that arrives without a value turns its tile to the unavailable state in place; the chart records a gap, never zero.
- Values are never animated: the number changes in place, the chart repaints without a transition (also under `prefers-reduced-motion`).

### Range and view

- Selecting a range sets the pressed chip, requests that range, and announces "Showing the {{range}}." once through the panel status region. While the new range loads, the previous charts stay in place at `--utf-metric-refetch-opacity`, the views region has `aria-busy="true"`, and nothing jumps. When the load fails, the views region shows the history error panel (the tiles and toolbar remain) and "Try again" refetches the same range.
- The view toggle swaps the three charts for the three tables and back. Focus stays on the toggle. The range applies to both views.

### Chart reading (mouse, touch, keyboard)

- Pointer and touch: moving or dragging over the plot places the crosshair at the nearest selectable point and shows the tooltip; leaving or lifting hides it after the pointer ends (touch keeps it until the next tap outside the plot).
- Keyboard: the plot group is focusable (`tabIndex={0}`, focus ring per token). Left and Right move the crosshair to the previous and next selectable point, Home and End jump to the first and last, Escape hides the tooltip. Arrow keys are intercepted only while the plot has focus. The tooltip content is not a live region; screen-reader users read values from the tables.
- Tooltip and crosshair show only values from the series; they are decoration over data that the summary and the table already expose.

### Keyboard and focus

- Every interaction is reachable by keyboard in DOM order (chips, view toggle, then each plot, or each table region); no positive `tabindex`; the focus ring is `--utf-focus-ring`.
- Chips are real buttons (Tab order, Enter and Space); arrow keys are not intercepted by the chip group.

## Accessibility and Responsive Contract (FND-06 gate for this phase)

- One live region in the panel: the visually hidden status `p` (`role="status"`), which announces only the range change. The tiles, the charts and the paused notice are not live regions (a 15 s update would announce continuously). The panel load error and the history error are `StatePanel kind="error"` (`role="alert"`); the loading panel is polite status as in every other panel. No nested live regions.
- Each plot: `role="group"` with the plot group label as `aria-label`; the SVG inside is `role="img"` with `aria-label` equal to "{{metric}}, {{range}}" and `aria-describedby` the summary line (when present); the tooltip and crosshair are `aria-hidden`. Decorative SVG parts (grid, band) carry no text.
- The table view is the full-fidelity path for screen readers and keyboard users: real `<table>`, `<caption>`, `th scope="col"`, a labelled and focusable scroll region, gap rows that say what is missing.
- Color is never the only signal: charts are separately titled; unavailable tiles carry the word "Unavailable" and a reason; the pressed chip carries a check icon; the paused notice carries text and an icon.
- Contrast: line on the panel 5.81:1 (at least 3:1 for graphics); all text pairs are guarded tokens; no text uses the series color.
- Touch targets: 44px at <= 800px for chips and the view toggle; the plot hit area is the whole plot (nearest-in-X snapping, so no 24px pinpoints); minimum 24px everywhere.
- `Intl` for every number, percent, size, time, weekday and list; German uses comma decimals.
- 320px: no horizontal page scroll; tiles in two columns, reasons wrap, the toolbar stacks, charts are one column, tables scroll inside their region; verified at 320x568 in English and German in unit or e2e tests for the new components. Full Playwright mobile baselines arrive in Phase 69.
- Automated check: an `axe` scan (`@axe-core/playwright` 4.13.0, already a dev dependency) of the Overview section with metrics available (chart view and table view), with all tiles unavailable, and with the paused notice; zero violations at WCAG 2.1 AA tags; the scan asserts at least one rule evaluated and records unmocked requests as in Phase 61 plan 13.
- Performance backstop: rendering a 2,016 point series at 320px completes within 200 ms and creates no more than one path per segment per layer (line and band), asserted in a held-out test.
