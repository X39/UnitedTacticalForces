# Phase 69 - UI Design Contract

> Visual and interaction contract for Phase 69: Consistency, Accessibility & Verification.
> Generated by gsd-ui-researcher (autonomous mode: `69-CONTEXT.md` has no locked decisions, every decision below is made at the researcher's discretion and recorded with its rationale), verified by gsd-ui-checker.
> Scope: `sources/ReactApp` only. `sources/WebApp` (legacy Blazor) and the generated Kiota client are not touched. `sources/Common/Ui/routes.json` changes only if a route changes (this contract changes none). No API, database or worker change is part of this phase.
> Requirements covered: CON-01, CON-02, CON-03, FND-06, L10N-03, VER-01, VER-02, VER-03.
> Inherits without change: `61-UI-SPEC.md` (design system, `--utf-*` tokens, four type sizes, two weights, state and cost model, shared cost confirmation, unavailable-action pattern, localization rules, German "du", copy rules), and the accumulated contracts of Phases 62 to 68 for the server screens. This file only adds or overrides what a cross-app consistency, accessibility, localization and verification closure needs. Anything not stated here is exactly as in Phases 61 to 68.

Phase 61 to 68 gave the server section one visual language. Phase 69 makes the rest of the React app speak it, then proves the whole milestone: every redesigned server screen is keyboard operable and axe-clean, shows no English in German, is route-safe, and holds its layout at 320 and 390 px in both languages with pixel baselines for the screens that matter most. It is a closure phase: it defines closed lists (header kinds, state panels, navigation labels, spacing, badge tones, button labels) and the verification surfaces that keep those lists closed. It adds no new product capability and no new color.

## Decisions

| Id | Decision | Rationale |

| D-01 | Convergence is tiered. Tier A (full): every file under `src/features/hosting`, `src/components/server`, the two layouts, `ProfileMenu`, `primitives.tsx`, `FormFields.tsx`, `Disclosure.tsx`. Tier B (light pass): every `src/features/admin` list, detail and create page plus `features/events-member` pages. Tier C (light pass, public): `src/pages/*`, `features/wiki`. Anything not converged sits on a visible ratchet allowlist with a reason; the allowlist may only shrink. | "Light pass" in the roadmap means headers, states, controls, tones and labels, not a rewrite of 7,445 lines of legacy CSS. A ratchet makes the remainder measurable and prevents regression. |
| D-02 | Exactly three header kinds exist: `PageHeader` (command center and member pages), `PublicHero` (the public community pages with an image hero), `WorkspaceHeader` (the server workspace). Every routed page renders exactly one `h1`, through one of them, as its first heading. `PageHeader` is normalized to the Display token (28px, 700, 1.2, no `clamp`, not uppercase). `PublicHero` keeps its marketing title scale as the single documented type exception (E-01). | One rhythm without flattening the public pages' branded hero. | D-09 | `SelectField` (native `<select>` styled by `form-field__control--select`) stays the only select. It gets a custom chevron, `appearance: none`, `padding-inline-end: var(--utf-space-xl)` and the control height token, on every page. A custom listbox is rejected. | The native popup gives the correct mobile picker, keyboard behavior and screen reader semantics; the dislike was the unpadded native look, which the shared style fixes once. |
| D-10 | Every dialog is `ConfirmDialog` (native `<dialog>` with `showModal()`) or a documented variant of its shell. All dialog content shares one left edge, actions are right-aligned above 520px and stacked full width with the confirm action first at or below 520px. | The owner's "misaligned dialog" complaint (Phase 65 UAT) is a shell-level property; fixing the shell fixes all 22 dialog users, and a geometry test keeps it fixed. |
| D-11 | The generic dismiss labels "Cancel" and "Abbrechen", "OK", "Submit", "Confirm" and bare "Save" are banned for every dialog button and every editor leave control in Tier A to C. | D-12 | FND-06 is proven by registry-driven audits: for every server screen, overlay and notice in the screen registry, an axe scan (WCAG 2.0 and 2.1 A and AA plus `wcag22aa`), a keyboard walk, a 320px reflow check and a text-spacing check, in English and German, in three projects (desktop 1280, mobile 390, mobile 320). | Per-phase specs scanned what their phase touched; closure needs one source of truth that also covers Phase 68 and the adjacent pages. |
| D-13 | L10N-03 is proven twice: a static AST scan fails on any literal user-facing text in Tier A files, and a German walk of every registry screen fails on any rendered text that matches an English locale value, or contains English function words, outside `lang="en"`, `<bdi>`, `<code>`, `<kbd>` and `<time>`. | The static scan catches strings that never render in a fixture; the walk catches strings the scan cannot see (API text, interpolation, fallbacks). |

## Spacing Scale

Inherited from Phase 61 without change (all multiples of 4, rem, 1rem = 16px). Control height `--utf-control-height` 40px, `--utf-control-height-touch` 44px at <= 800px.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Kicker to title gap, icon to label gap, badge inner gap |
| sm | 8px | Title to description gap, description to meta gap, chip gap, button row gap |
| md | 16px | Panel inner padding at <= 520px, gap inside a panel, dialog section gap, form field gap |
| lg | 24px | Header to first block, gap between page blocks (`page-stack`), panel padding above 520px, dialog padding above 520px |
| xl | 32px | Page top padding above 800px, `SelectField` end padding for the chevron |
| 2xl | 48px | Major section breaks on public pages only |
| 3xl | 64px | Not used by shared primitives |

Page rhythm (the CON-01 and CON-03 spacing closed list; every value is a token):

| Slot | > 800px | <= 800px | <= 520px |
|------|---------|----------|----------|
| Space above the header (page top padding) | `--utf-space-xl` | `--utf-space-lg` | `--utf-space-lg` |
| Kicker to title | `--utf-space-xs` | same | same |
| Title to description | `--utf-space-sm` | same | same |
| Description to meta chips | `--utf-space-sm` | same | same |
| Header to first content block | `--utf-space-lg` | same | same |
| Between page blocks (`page-stack` gap) | `--utf-space-lg` | same | `--utf-space-md` |
| Panel padding | `--utf-space-lg` | `--utf-space-lg` | `--utf-space-md` |
| Between panels in a panel group | `--utf-space-md` | same | same |
| Header actions | right of the title block, vertically end-aligned, gap `--utf-space-sm` | stacked below the title block, wrapping | full-width buttons, 44px |

Exceptions: 1px borders and dividers, the 2px focus ring (2px offset), the 16px inline icon size, `PublicHero` internals (E-01). No other off-grid value in `shared-primitives.css`, `components/server/*.css`. No raw pixel or rem spacing literal in either; the style guard fails on one. Breakpoints (constants): `520px` compact, `800px` narrow (44px targets). Minimum supported width 320px with no horizontal page scroll. The two mobile Playwright projects (320, 390) both sit in the compact range; the narrow range is covered by the desktop project's own layout assertions.

## Typography

Exactly four sizes and two weights, as in Phase 61, now applied to the shared primitives and to every converged page header.

| Role | Size | Weight | Line Height | Where in this phase |
|------|------|--------|-------------|---------------------|
| Body | 14px (0.875rem) | 400 (700 where Phase 61 to 68 declare it) | 1.5 | Descriptions, state panel bodies, dialog text, nav labels, form text |
| Label | 12px (0.75rem) | 700 | 1.35 | Kickers, badges, `dt` terms, button text (not uppercase), nav group labels |
| Heading | 20px (1.25rem) | 700 | 1.2 | State panel title, dialog title, panel `h2`, cost figures |
| Display | 28px (1.75rem) | 700 | 1.2 | Every `PageHeader` `h1` at every width (was clamp 33 to 54px, weight 800, uppercase); `WorkspaceHeader` title above 800px (unchanged) |

- Weights 400 and 700 only. The legacy 800 weight and the 600 weight of `.state-panel h2` are removed from the shared primitives.
- No `clamp()` or viewport-relative type in shared primitives. `WorkspaceHeader` keeps its Phase 63 step down to Heading at <= 800px; `PageHeader` stays Display at every width and wraps (`overflow-wrap: anywhere`, no clamping lines).
- The `PublicHero` title keeps its existing scale (E-01) and still obeys the slot order kicker, `h1`, lede, actions. It is the only element with a size outside the four.
- German expands up to roughly 35%: every title, badge, button, nav label and panel wraps (`white-space: normal`); no `text-overflow: ellipsis` on a state, cost or reason string, and none in the shared primitives. Server names and user-entered titles sit in `<bdi>` with `overflow-wrap: anywhere`.
- Numbers, currency and dates always go through `Intl` with `currentLocale()`.

## Color

Existing dark palette and `--utf-*` tokens are kept. No new colors and no new foreground/background pair except the one correction below (the contrast guard needs one changed value, no new entry).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#090c11` canvas, `#0e131a` surface | Page background, page body, list and form areas |
| Secondary (30%) | `#141b25` raised, `#1a2330` overlay | Panels, cards, state panels, dialogs, badge tints, header and nav surfaces |
| Accent (10%) | `#baa05a` gold, `#dec982` gold-bright | Listed below, nothing else |
| Destructive | `#e47777` (`--danger`) | `danger` tone badges and state panels, destructive confirm buttons (delete, remove, terminate), field errors. Never on a primary non-destructive action. |

Accent reserved for:
1. The single primary action of a view (`ActionButton variant="gold"`), at most one per view, unchanged from Phase 61 and Phase 63.
