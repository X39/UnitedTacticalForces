<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| claim presence in the browser to data access | `hasClaim` ignores the claim value; only the API decides which servers a member may view |
| fleet query to API | a query issued for a user with no server claim is wasted at best and probing at worst |
| link construction from API ids | server and action ids are placed into a URL |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-61-32 | Information Disclosure | fleet query issued for a user with no server claim | medium | mitigate | useFleetQuery is enabled only when auth finished loading and accessServers is true; member-access test asserts zero calls for a no-claim user |
| T-61-33 | Elevation of Privilege | operate or create controls presented as usable to a read-only member | high | mitigate | the card and Create controls render aria-disabled with visible reasons from the API projection and the creation claim; the UI never recomputes enabled; tests cover sv:view and member shapes |
| T-61-34 | Tampering | ids injected into the card navigation URL | low | mitigate | server and action ids pass through encodeURIComponent; the target pathname is a fixed /command/servers prefix |
| T-61-SC | Tampering | npm/pip/cargo installs | high | accept | no package installs in this plan |
</threat_model>
