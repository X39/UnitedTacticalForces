<objective>
Give the control plane one durable fact the UI needs for CHG-04: which kinds of applied change still wait for the next start (D-09). The API, DTO and database changes are in scope without separate approval (D-00a). The tracer threads the signal through every backend layer: a flags enum in the shared hosting contracts, two columns on `GameServer`, the `GameServerDto` projection, and the configuration endpoints that mark it. Then the migration is scaffolded with the AGENTS.md command and proven in sync (blocking schema gate), and the first consumption point (deployment creation at Start) plus live propagation through the fleet interceptor land.

Purpose: a timestamp comparison cannot distinguish a configuration change from a title change, and "next start" is not one moment for every area (RESEARCH Pitfall 5): the mod pack is frozen into the deployment content snapshot at Start, while configuration and credentials are re-read at every command creation. Per-area flags with area-specific consumption make the banner truthful; plan 65-04 adds the command-creation consumption and the credential marks, plan 65-05 the mod pack mark.

Output: `EGameServerChangeArea`, `PendingStartChanges`, the two columns and their migration, the DTO fields, configuration marks, Start consumption, interceptor relevance, and tests.
</objective>

<assumption_delta_decision>
decision: add-alongside
rationale: The UI copy keeps the single conservative statement "takes effect the next time the server starts" for every area (true for all of them), and the API adds per-area flags alongside it so the banner disappears after a restart that already consumed configuration and credentials while a mod pack change still waits for a start.
</assumption_delta_decision>

Known limitations accepted for this phase (write them into the XML remarks of `PendingStartChanges`): a configuration or credential change committed after a command resolved the configuration but before the executor saved the consumption is cleared without being applied (narrow race, accepted, change endpoints take no server lock); a server that follows a profile whose latest revision changes is not flagged (no server-side write, FUT-02 territory); existing rows start at None (no backfill).

</reversibility>
