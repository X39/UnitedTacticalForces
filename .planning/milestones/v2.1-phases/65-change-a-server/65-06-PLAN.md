<objective>
Let every game declare its own Common and Advanced settings (D-06) and make the configuration contract visible to the generated client. The tracer threads one Arma 3 Common entry from the game definition through the DTO projection and an annotated endpoint; then ASKA and Counter-Strike 2 get their Common sets, the profile endpoints get annotations and every profile summary carries its latest revision id.

Purpose: `GameConfigurationDto` is absent from the OpenAPI snapshot today (grep count 0) because the configuration controller has no `ProducesResponseType`, and `types.ts` hand-maintains the entry type; without the annotation the tier never reaches the client (RESEARCH Pitfall 1). The profile options return `LatestRevisionNumber` but no id, so "Stay on revision n" cannot be offered for a newly chosen profile (RESEARCH A6).

Output: `EGameConfigurationTier`, the tier on definitions and DTO entries, Common sets per game, annotations, `LatestRevisionId`, tests.
</objective>
