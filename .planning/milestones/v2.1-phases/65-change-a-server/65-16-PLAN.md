<objective>
Close the API half of UAT gap G-65-6, so the React plans 65-17 to 65-19 build on a stable contract.

1. Rotating a credential returns the newly generated value once to the acting member (G-65-6 item 2).
2. Games declare per credential whether a generated credential also accepts a member-chosen value, and which value format the game can use. The API enforces both (G-65-6 item 1).

Purpose: UAT test 6 failed because members could not choose any value and a rotated value stayed invisible unless the member held the reveal claim, which most server managers lack. The diagnosis traced the API side to `RotateAsync`, which returns no value, and to `SetAsync`, which rejects every generated credential. The G-65-6 plan set is split along this seam to keep each plan within the context budget: 65-16 API and contract, 65-17 the one-time value in the UI, 65-18 chosen values in the UI, 65-19 fixed-slot rows with end-to-end proof and parity.

Output: a rotate endpoint that returns the generated value once with no-store, game-declared chosen-value and value-format rules enforced by the API, service and controller tests, and a refreshed OpenAPI snapshot and generated types.
</objective>
