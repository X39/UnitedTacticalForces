# Phase 66 Plan 14: Cost alerts stay until the viewer dismisses them Summary

**Dismiss all now sends the ids of the alerts the viewer sees and the API dismisses only those (400 for an empty or oversized list), a failed refetch no longer hides the banner, and a late raised frame can no longer resurrect or toast an alert the viewer dismissed; every path that can remove or hide an alert is audited below and pinned by a test.**

## Performance

- **Duration:** about 25 minutes
- **Completed:** 2026-11-21
- **Tasks:** 2 (task 1 is the tracer)
- **Commits:** 3 (measured from the persisted ledger, base `f94a8dbc`)

## Accomplishments

- Tracer (task 1): `CostAlertDismissAllPayload` has a required `CostAlertIds` (MinLength 1, MaxLength 50). `ICostAlertService`/`CostAlertService.DismissAllForServerAsync` take the ids, throw `HostingValidationException` outside 1 to `MaxListedAlerts`, and restrict the existing query to `costAlertIds.Contains(PrimaryKey)` next to the server, viewable-owner and not-yet-dismissed filters. The controller wraps the call in `TryMapException`, which now maps `HostingValidationException` to 400. The OpenAPI snapshot and `api.ts` were regenerated by the tooling (diff: the payload field with min/max items, the 400 response and the changed summaries, nothing else). `hostingService.dismissServerCostAlerts(serverId, costAlertIds)` posts `{ gameServerId, costAlertIds }`; `dismissAll` passes the ids it reads from the cache of that server.
- API tests (7 new, 18 in the class): only the submitted ids are dismissed and published (an alert raised after the list loaded stays listed), an id of another server is ignored, an id of an unviewable owner or unknown id is ignored without a row or a frame, a repeated call is idempotent, and 0 or 51 ids throw the validation exception.
- Client fixes (task 2): `loaded` is `data !== undefined`; `markCostAlertsDismissed` is part of `FleetLiveUpdatesValue` (no-op default); `FleetLiveUpdatesProvider` keeps a ref set of dismissed ids, fills it from `markCostAlertsDismissed` and from dismissed frames before touching the cache, and returns from the raised branch before any cache write or listener call when the id is in the set. `useDismissCostAlerts` calls `markCostAlertsDismissed(ids)` after the API accepted a dismissal and before the cache filter, for `dismiss` and `dismissAll`.
- Audit tests: `cost-alert-persistence.test.tsx` mounts the real provider, `CostAlertBanner` and `ProfileMenu` on one cache with the socket fake, 8 tests with a header pinning D-17. A mutation check (reverting `loaded` to `isSuccess`, and removing the raised-frame guard) makes exactly the intended tests fail.
- Provider tests: `fleet-live-updates.test.tsx` gained the no-op default case, the marked-id drop case (plus a control that an unrelated alert still lands and calls the listener with `wasCached=false`) and the dismissed-frame-remembers case.
