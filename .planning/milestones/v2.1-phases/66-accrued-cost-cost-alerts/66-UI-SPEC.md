# Phase 66 - UI Design Contract

> Visual and interaction contract for Phase 66: Accrued Cost & Cost Alerts.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Scope: `sources/ReactApp` plus the API, shared-contract and database changes this feature needs (`66-CONTEXT.md`, `AGENTS.md`: the API is not a frozen contract). `sources/WebApp` (legacy Blazor) is not updated and the generated Kiota client under `sources/WebApp/UtfApi` is never hand-edited. Regenerate the OpenAPI snapshot and `src/generated/api.ts` (`npm run contracts:generate`). URLs are not a stable contract (65-CONTEXT D-00b): the one new route changes `sources/Common/Ui/routes.json` and the route tests together and they stay green.
> Requirements covered: CST-03, CST-04, CST-05, CST-06 (the React surfaces of them; delivery to Discord and email is control-plane work with no UI beyond the settings below).
> Inherits without change: `61-UI-SPEC.md` (design system, spacing, typography, color, state and cost model, shared cost confirmation, unavailable-action pattern, localization, token rules), `63-UI-SPEC.md` (workspace shell, cost strip, shell notice slot, live region) and `65-UI-SPEC.md` (draft-then-save form conventions, `useLeaveGuard`, banned generic button labels, German "du"). This file only adds or overrides what accrued cost and cost alerts need. Anything not stated here is exactly as in Phases 61, 63 and 65.

A cost owner should be able to glance at a running server and know what the session has cost, and trust that they will hear about it before it gets expensive. The page stays a quiet working tool: the number is shown exactly as the control plane sent it with the time it was true, an alert is a persistent, dismissible fact (not a flashing interruption), and "no alerts are set" is stated as plainly as "three are set". The browser displays; it never calculates.

## Data The UI Needs (API changes)

The contract names the semantics; exact names, DTO shapes, routes and frame types are the planner's call. Regenerate the OpenAPI snapshot and the clients, add tests in the owning layer (AGENTS.md).

| Need | Where | Semantics |
|------|-------|-----------|
| Accrued cost | server DTO (or a value frame keyed by server id) | One `accruedCost` object or null. Fields: `amount` (number or null), `currency`, `asOf` (instant the amount was true), `isFinal` (the session's cost has stopped, `amount` will not change), `unavailableReason` (a code, null when the amount is known). Null means there is no session (the server never started). Calculated by the control plane from charged ledger slices plus the prorated in-progress slice (D-01). The amount is never a client calculation and never defaulted to zero. |
| Accrued live push | update stream | While a session is costing, a frame carries the same object. The client writes it into the query cache; it never extrapolates between frames. Cadence and smoothing are the planner's call but must not require client polling (D-02). |
| Alert record | REST list, push on create and on dismiss | `id`, `serverId`, `serverName`, `thresholdAmount`, `accruedAmount` (amount at the crossing), `currency`, `createdAt`, dismissed or not. The list is the viewer's undismissed alerts, newest first. A frame on dismissal clears the alert on the viewer's other tabs and devices. |
| Dismiss alert | REST | Dismisses one alert by id; idempotent. |
| Alert settings per cost owner | REST get and put | `thresholds` (ascending amounts), `discordEnabled`, `emailEnabled`, `currency`, `maxThresholds` (default 10), `canManage`, `audience` (`Self` or `Group`), `discord` and `email` availability (`Deliverable`, `NotLinked` or `NoAddress`, `ChannelUnavailable`), `messageLanguage`. The put carries the viewer's current UI language, which the API records (D-12). A stale put returns 409. |
| Alert summary on the server | server DTO | `costAlertThresholds` (ascending amounts) and `canManageCostAlerts`, present only for viewers who may see the owner's alert settings; absent otherwise so unauthorized viewers learn nothing. |
| In-app channel | none | Always on; never a field. |

If an addition is not yet available when a plan lands, the UI degrades without inventing data: no `accruedCost` field renders "No session yet" only when the server has no deployment and otherwise "Not available for this session"; no alert summary omits the Cost alerts row; no alert list renders no banner and no menu rows.

Assumptions the planner confirms or amends (they do not change the visual contract):

| Id | Assumption | If wrong |
|----|-----------|----------|
| A1 | A threshold at or below a running session's current accrued cost counts as reached and alerts on the next evaluation. The copy says "reaches", which holds either way. | Add one sentence to `Server_Alerts_Amounts_Description`. |
| A2 | Dismissal hides the alert for the dismissing viewer; the API decides whether a group owner's dismissal is per viewer or shared. | Copy unchanged; the dismiss frame scope changes. |
| A3 | The client records the current language on save and also when a signed-in user changes language (fire and forget, no visible error). | Page line stays correct because it shows the recorded value. |
| A4 | `canManage` for a non-personal owner (Verein, external organization) is computed by the API from the owner type; the UI only reads the flag. | None; the flag is the contract. |
| A5 | After a session ends the API keeps returning the final amount of the most recent session until a new session starts. | The row shows "No session yet" after the end; the ended state and its tests are dropped. |

## Surface Anatomy

### 1. Cost strip: accrued row and cost alerts row (CST-03, CST-04)

The Phase 63 five-row `dl` becomes six rows, with the new row only for viewers who may see the owner's alert settings. DOM order of rows: Cost owner, Per hour, Per month if left running, Cost now, This session so far, Cost alerts. Layout, `dt` and `dd` styling and the two-column list at <= 520px are unchanged.

**Accrued row** (`dt` and `dd`, `dd` wrapper keeps `data-slot="accrued-cost"`). The `dd` holds up to three stacked lines with `--utf-space-xs` between them:

| Line | Element | Content |
|------|---------|---------|
| 1 | Value | The amount, Body 14/700, `font-variant-numeric: tabular-nums`, `overflow-wrap: anywhere`; or a state sentence (below). |
| 2 | Time or state | Body 14/400 muted: `<time datetime>` with "As of {{time}}" while costing, "Cost stopped: {{time}}" when final. Absolute clock time through `Intl.DateTimeFormat(currentLocale(), { timeStyle: "short" })`, with `dateStyle: "short"` added when the instant is not today. No ticking relative time. |
| 3 | Notes | Body 14/400 muted, only when applicable: "Still counting..." for cost state `maybe`; the stale line while the socket is down (warning text with `Warning16Regular`, `aria-hidden`). |

Accrued value states, first match wins. `derived` is `deriveServerState(server)`; the accrued object is `a`.

| Order | Condition | `dt` | Line 1 | Line 2 | Line 3 |
|-------|-----------|------|--------|--------|--------|
| 1 | accrued not yet loaded (the server is loaded, the accrued value is not) | active | "Loading cost so far..." | none | none |
| 2 | `a` is null | active | "No session yet" | none | none |
| 3 | `a.amount` is null | active | "Not available for this session." | none | the mapped reason sentence when `unavailableReason` is known (`Map` lookup, fixed fallback: no sentence) |
| 4 | `a.isFinal` and `derived.cost` is `none` | final | the amount | "Cost stopped: {{time}}" | none |
| 5 | `a.isFinal` but `derived.cost` is not `none` | active | the amount | "As of {{time}}" | none (the API says cost stopped but the state model says it may still run: the state model wins, FND-03; the value is shown as a still-valid lower bound) |
| 6 | costing and `derived.cost` is `maybe` | active | the amount | "As of {{time}}" | "Still counting until the cloud machine is confirmed gone." |
| 7 | costing, `derived.cost` is `live` | active | the amount | "As of {{time}}" | none |

`dt` active is "This session so far"; `dt` final is "Last session total". Stale line: after the shared socket has been disconnected for 3 s in a row (same epoch-keyed delay as `LiveBadge`), states 4 to 7 gain, when costing, the existing carried sentence `Server_Live_StaleReason_Disconnected`. A recovered connection removes it and refetches the accrued value once.

Accrued amount rule (`formatAccruedAmount`): at least 0.01 renders with `formatMoney(amount, currency)`; more than 0 and below 0.01, or exactly 0 while the state is costing, renders "Less than {{amount}}" with `formatMoney(0.01)`; exactly 0 in a final state renders `formatMoney(0)` (nothing was charged, which is true). `formatMoney`'s "—" is never shown for accrued.

**Cost alerts row.** `dt` "Cost alerts". `dd`: when `costAlertThresholds` is empty, "None set"; otherwise the first three amounts joined with `Intl.ListFormat(currentLocale(), { type: "unit" })` and, beyond three, "and {{count}} more". When `canManageCostAlerts`, an `ActionLink variant="ghost" size="compact"` follows on its own line: "Set an alert" when none, otherwise "Manage alerts", to `/command/servers/cost-alerts?owner={costOwnerId}`. Viewers who may see but not manage see the summary and no link.

### 2. Workspace cost alert banner (CST-04, D-07, D-08)

Renders in the Phase 63 shell notices slot (slot 4), as the first notice, above the paused, archived, pending-start and deep-link notices, because it concerns money. It renders in every section and for every viewer who is authorized on the cost owner and has at least one undismissed alert for this server. It does not render while loading and never from a stale cache of another server.

One `StatePanel kind="warning"` (single polite status region):

| Part | Content |
|------|---------|
| Title (h2) | "Cost alert" (one) or "{{count}} cost alerts" (many). |
| List | A `<ul>` with up to three rows, newest first. Row: line 1 "{{name}} reached {{threshold}}" (Body 14/700, name in `<bdi>`), line 2 "{{amount}} this session, as of {{time}}." (Body 14/400 muted), and a `ActionButton variant="ghost" size="compact"` "Dismiss alert" at the row end. |
| Overflow line | When more than three: "and {{count}} older alerts" (Body 14/400 muted). |
| Ended line | Only when `deriveServerState(server).cost` is `none`: "This session has ended and billing has stopped." (Body 14/400). Never shown while cost may still run. |
| Panel action | The cost-stop button, rendered once for the panel (all rows are the same server): `ActionButton` with the label from `ActionLabel` ("Shut down and stop billing"), the variant the workspace header uses for that action, opening the shared confirmation with source `alert-banner`. When no cost-stop action exists, nothing renders. When it exists but is unavailable, it renders disabled with the mapped reason through `UnavailableReason` (ACC-03). |
| Dismiss all | When two or more alerts exist: `ActionButton variant="ghost" size="compact"` "Dismiss all alerts" (`aria-label` "Dismiss all {{count}} alerts") after the list. Dismisses hidden rows too. |
| Dismiss error | A `role="alert"` Body line in `--utf-state-danger-fg` inside the panel: "The alert could not be dismissed. Try again." The alert stays. |

There is no auto-dismiss and no timer. The banner stays after the session ends until the viewer dismisses each alert (D-08). It is not sticky; it scrolls with the notices.

### 4. Cost alerts page and panel (CST-04, D-03 to D-06)

Route `/command/servers/cost-alerts` (member page, inside the command layout, Servers nav item stays active through its `startsWith` rule; add a context title `Shared_CommandCenter_CurrentArea_CostAlerts` at priority 115). Query parameter `owner` is a cost owner id. Without it the page edits the viewer's own personal cost owner. A malformed or unknown `owner` shows the not-found panel; a cost owner the viewer may not view shows the forbidden panel; no personal owner shows the "no cost owner yet" panel.

DOM order:

| Order | Element | Renders when | Notes |
|-------|---------|--------------|-------|
| 1 | `Breadcrumbs`: Servers, Cost alerts | always | |
| 2 | `PageHeader` h1 "Cost alerts", description, `meta` "Cost owner: {{name}}" (`<bdi>`) | settings loaded | |
| 3 | Read-only notice (`StatePanel kind="info"`) | `canManage` is false | Every control below is disabled and says so once here, not per control (Phase 65 pattern). Uses carried `Server_Change_ReadOnly`. |
| 4 | Panel "Alert amounts" (h2) | settings loaded | Description, then either the no-alerts-set state or the amount rows, then Add and the counter. |
| 5 | Panel "Where alerts go" (h2) | settings loaded | Three channel rows and the language line. |
| 6 | Save row | `canManage` | Save, Discard, reserved status line. |
| - | Leave dialog | the form is dirty and a navigation is blocked | |

The same panel renders on `HostingFinanceAccountPage` as an h2 section "Cost alerts" between the metrics and the protocol list, for `permissions.view` viewers; it hides the breadcrumbs and `PageHeader` and keeps everything else. It lets finance staff see (and, when `canManage`, edit) an owner's alerts.

**Alert amounts panel.**
- No-alerts-set state (D-05): while the list has no rows, a `StatePanel kind="info"` with title "No alerts set" and the body "You will not be alerted about cost until you add an amount." renders above the Add control. It is the empty state and the reminder in one; the page never implies a default.
- Rows: each row is one `TextField` (`type="text"`, `inputMode="decimal"`, `autoComplete="off"`, `maxLength` 12, `spellCheck` false) with label "Alert amount {{index}} ({{currency}})" and a `trailing` "Remove amount" `ActionButton variant="ghost" size="compact"` (`aria-label` "Remove amount {{index}}"). The field is `width: min(100%, var(--utf-alert-amount-width))`. Rows are flat, separated by `--utf-space-md`, no cards.
- Add: `ActionButton variant="ghost"` "Add an amount" with a leading `Add16Regular` (`aria-hidden`). Below it an always-rendered muted counter line "{{count}} of {{max}} amounts set". At the limit the button is `aria-disabled` and `aria-describedby` the counter line, so no second reason line appears and nothing shifts.
- Order: rows keep entry order while editing (no re-sorting under the cursor); after a successful save the list is shown ascending.
- Parsing (`alertSettingsModel`): trim; accept digits with at most one decimal separator `.` or `,`; no grouping separators; at most two decimals; the value must be above 0 and at most 10000 (the API enforces the same range); duplicates compare on the parsed value. Validation messages show after blur or a save attempt, never while the first character is being typed.

**Where alerts go panel.** Three rows with the same structure (`CheckboxField`, hint under the label):

| Channel | Control | Hint |
|---------|---------|------|
| In the app | checked and `disabled` | "Always on..." Disabled checkboxes are not focusable, so the hint is the visible reason, linked by `aria-describedby`. |
| Discord direct message | `CheckboxField`, enabled | One sentence from the availability table in Copywriting. |
| Email | `CheckboxField`, enabled | One sentence from the availability table in Copywriting. |

A channel that cannot deliver right now (not linked, no address, not set up) stays selectable and its hint says plainly that nothing can be sent yet, because the preference should survive until the account is linked and D-09 guarantees the in-app alert regardless. The Discord not-linked hint contains a link `ActionLink variant="ghost" size="compact"` "Open account settings" to `/settings` on its own line below the hint. ## Interaction Contract

### Accrued value and live behavior (CST-03, D-02)

- The strip shows only what the API sent. There is no client timer that advances the amount, no extrapolation from the hourly rate and no animation of the number. The value updates in place.
- Initial value comes from REST with the server; later values arrive as socket frames and are written into the query cache by server id. Refetch happens on socket reconnect, on window focus after a disconnect, and on "Refresh server". The accrued queries have no `refetchInterval` and no `setInterval` exists in the accrued files; a source-scan test asserts both.
- The value is not a live region (it would announce every push). The only announcements are: cost stopped (once, when a costing session turns to cost `none` while the workspace is open, never on first load), and the alert toast (below). The shell's existing visually hidden polite region carries the cost-stopped sentence.
- The as-of time is the time the API says the value was true, not the time the browser received it.
- Disconnected: the value stays visible with its as-of time; the stale line appears after the 3 s delay; nothing flickers on a short blip.

### Alert arrival (CST-04)

- A frame for a new alert adds it to the alerts cache by id (no duplicate if the REST list already has it). The banner and the menu rows appear without a reload; the badge count updates.
- One warning toast per newly arrived alert id, never for alerts loaded on first fetch or after a reconnect refetch (a ref of announced ids). The toast is a pointer only; it has no action.
- The banner is the persistent surface: it does not auto-hide, steal focus or move other content once rendered (it is above the cost strip's neighbors in the notice slot and mounts as part of the same render that adds the alert).

### Dismissal (D-08)

- Dismiss is one request per alert and removes the row optimistically only after the API accepts; while pending the button is `aria-disabled` (focus stays, no extra reason text). On failure the row stays and the inline `role="alert"` line shows.
- Focus after a successful dismiss: to the Dismiss button of the next row; if none remains, to the cost-stop button if the banner remains for other reasons, otherwise to the workspace `h1` (`tabIndex={-1}`). In the profile menu the focus goes to the next row's first control, else to the menu close button. A polite announcement "Alert dismissed." follows through the surface's status region.
- Dismiss all dismisses every alert for the server in one request; focus goes to the workspace `h1`.
- A dismissal frame removes the alert on the viewer's other tabs without a toast.

### Cost-stop from an alert (D-07)

- The banner and menu button call `useCostConfirmation().request({ serverId, actionId, source: "alert-banner" | "alert-notification", returnFocus })`. It never executes the action. The dialog adds the fact "This session so far" for cost-stopping actions when the amount is known (same `serverCostFacts`-style helper, so strip and dialog cannot disagree).
- Availability follows the shared rule: usable graceful stop first, then usable destructive, then a disabled one with its reason. Nothing is rendered when the server has no cost-stop action; the ended line explains why only when the cost state is `none`.

### Settings form (D-03 to D-06, D-09)

- One in-memory draft of `thresholds`, `discordEnabled`, `emailEnabled`. React state only: never written to storage, the URL, router state or a log (source-scan test as in Phase 65).
- Dirty means the normalized, ascending, parsed list or either channel flag differs from the saved settings. A blank new row alone is not dirty until it holds a value; it is invalid on a save attempt (blank rows are not silently dropped).
- Save validates every row; on errors it does not send, shows the plural invalid status, and moves focus to the first invalid field. On success it replaces the draft with the returned settings (ascending), shows the saved status and toast, and keeps focus on Save. On 409 it keeps the draft, shows the conflict status and the Reload button; Reload replaces the draft with the latest saved settings after the viewer chooses it.
- Add moves focus to the new field. Remove moves focus to the next row's field, else the previous, else the Add button. Discard changes restores the saved settings, announces the discarded status and moves focus to the Save button.
- While saving, every control is `aria-disabled` and focusable (no extra reason text); the form cannot change mid-save.
- `useLeaveGuard({ dirty })` blocks in-app navigation and `beforeunload` while dirty; the dialog has two actions (Stay here as initial focus, Discard and leave).
- Read-only (`canManage` false): all controls disabled once, the notice explains; Save and Discard do not render.
- When the alert settings change elsewhere while the page is open and the form is pristine, the draft follows the new saved values; when dirty the draft is kept and the next save returns 409.

### Keyboard and focus

- Every interaction is reachable by keyboard in DOM order; no positive `tabindex`; the focus ring is `--utf-focus-ring`.
- Amount fields: Enter inside a field does not submit; the form saves only through the Save button (a stray Enter must not save). Escape does nothing special.
- The banner list and menu rows are plain lists of links and buttons; no roving tabindex.

### Accrued row billing line (D-15)

UAT gap 1 (D-15): after a Hetzner session starts, the row shows a full hour after five minutes and the amount stays put while "As of" keeps moving. Without an explanation that reads like a wrong or frozen number. The accrued row therefore says how the provider bills.

**Overrides.** The Data table row "Accrued cost" no longer says "plus the prorated in-progress slice": the accrued value follows the provider's billing unit, so a provider that bills every started hour reports the full started hour. **Data.** Two additive, nullable fields on the REST accrued value and on the pushed accrued frame, both calculated by the control plane (D-02) and null whenever `amount` is null, including for a viewer who may not view the cost owner:

| `billedThrough` | The instant the last started unit ends at as of `asOf`, which the amount covers; the next unit starts then. |

The browser only formats these values. It never derives the unit or the next billing instant from times or rates.

**Placement.** Line 3 of the accrued row `dd`: `p.accrued-cost__line`, Body 14/400 muted, between the time line and the notes. It is not a live region and is not announced when it changes. The instant sits in a `<time datetime>` with `formatInstant`.
