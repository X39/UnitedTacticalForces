<objective>
Make sure nothing but the viewer dismisses a cost alert (D-17, UAT gap 3), tracer-first: Dismiss all sends the ids of the alerts the viewer sees and the API dismisses only those, end to end through the contract. Then close the client paths that hide or resurrect an alert without a dismissal and pin every remaining path with an audit test.

Purpose: In the UAT the user could not tell whether the alert dismissed itself. Planning found three real causes: the banner reads "loaded" from the query's success flag, so a failed background refetch hides it; Dismiss all dismisses every undismissed alert of the server on the API, including one raised after the viewer's list loaded; and a late raised frame can re-add an alert the viewer just dismissed. Visible feedback for a dismissal is plan 66-17.

Output: the dismiss-all contract with explicit ids, the client fixes, `cost-alert-persistence.test.tsx`, and the audit table in the summary.
</objective>

Verified facts (read at planning time, HEAD 555144c0):
- `useCostAlerts()` returns `loaded: query.isSuccess`; the query has `staleTime: Infinity`, `retry: false`, `refetchOnWindowFocus: false`. In TanStack Query v5 a failed refetch sets the status to error while keeping `data`, so the success flag turns false. `CostAlertBanner` returns null while `!loaded`; `ProfileMenu` reads `costAlerts.alerts` (the data) and keeps its rows, which is why the banner and the menu can disagree.
- `useDismissCostAlerts().dismissAll(serverId)` reads the cached alerts of the server and calls `hostingService.dismissServerCostAlerts(serverId)`, which posts `{ gameServerId }` to `/cost-alerts/dismissals`. `CostAlertService.DismissAllForServerAsync(gameServerId, principal, ct)` dismisses every visible undismissed alert of that server and publishes one dismissed frame per added dismissal to the caller only. `CostAlertsController.DismissAllForServerAsync` does not map exceptions; `TryMapException` maps only `HostingNotFoundException`. `HostingValidationException(string message)` exists in `Services/GameServerLifecycle`.
- `FleetLiveUpdatesProvider.onMessage`: a raised frame for an id not in the cache is inserted with `insertAlert` and every `subscribeCostAlerts` listener is called with `wasCached`; a dismissed frame removes the id; `onOpen` and `reconnectNow` invalidate the alerts query exactly. `useFleetLiveUpdates.ts` defines `FleetLiveUpdatesValue` and a no-op default context.
- `CostAlertService.ListAsync` lists the viewer's undismissed alerts of viewable owners, newest first, at most `MaxListedAlerts` (50), with no time window; `PublishDismissedAsync(userId, ids)` sends only to the dismissing user's path; `CostAlertEvaluator` raises only rows it inserted in the current pass.
- `CostConfirmationProvider` invalidates fleet, server, jobs, operations and notifications after a submitted action and never the alerts key; `hostingQueryKeys.costAlerts` is `["hosting", "cost-alerts"]`, not a prefix of any per-server key.
- Tests: `tests/hosting/cost-alert-services.test.ts` line 70 asserts the dismiss-all body; `tests/hosting/cost-alert-banner.test.tsx` line 407 spies on `dismissServerCostAlerts`; `tests/Api.Tests/GameServerHosting/CostAlertServiceTests.cs` has the DismissAllForServer tests at lines 196-293.
