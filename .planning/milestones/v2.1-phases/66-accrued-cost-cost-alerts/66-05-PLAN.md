<objective>
Expose the in-app alert to the people who may see it and make cost values live without polling (tracer-first): a per-viewer alert list and dismissal API, then per-socket send serialization in the update stream (a second producer now writes to the same user paths), then value, raised and dismissed frames published to fail-closed, cost-aware audiences by the worker and the dismissal endpoint.

Purpose: D-07 requires a persisted alert visible in the menu and the workspace and pushed, not polled; D-08 requires per-alert dismissal that survives the session; D-02 requires the accrued value to be pushed while costing. The existing fleet signal is id-only by design, so cost values travel in new frames to a narrower audience (RESEARCH Pattern 3, Pitfall 5).

Output: `CostAlertDto`, `CostAlertDismissAllPayload`, `ICostAlertService`/`CostAlertService`, `CostAlertsController`, `GetViewableCostOwnerIdsAsync`, the update-stream send lock, three WebSocket messages, `ICostAlertPublisher`/`CostAlertPublisher`, worker publishing, and tests.
</objective>

Cross-cutting change and its justification (AGENTS.md architecture rule): `UpdateStreamService.SendUpdateAsync` currently calls `WebSocket.SendAsync` without per-socket serialization and removes any socket whose send throws. A WebSocket allows one outstanding send, so the fleet notifier loop and the new cost publisher writing to the same user path at the same moment would make the second send throw and silently drop the subscriber. The update stream is the push channel the user explicitly requested for this feature (D-02, D-07), and the owning layer for socket safety is the update stream service itself, so a per-socket send lock is added there. Behavior for single producers is unchanged.
