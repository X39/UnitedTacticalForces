<objective>
Add the smallest backend projection the activity timeline needs so each entry can name who acted (D-10, Post-Research Decision "actor data"): a nullable `RequestedByName` on `LifecycleJobDto` and a nullable `ActorName` on `HostingOperationDto`, then refresh the React OpenAPI snapshot and generated types.

Purpose: the database already records `LifecycleJob.RequestedByFk` and `HostingAuditRecord.ActorFk`, but neither DTO projects them, so the React app cannot write "Requested by Falcon One" or tell a member action from a platform action. The fields expose only a nickname to viewers who already see the job and operation lists, withhold deleted users behind one placeholder, and leave every other layer untouched (AGENTS.md: frontend-driven API change, minimal, in the layer that owns the data).

Output: two documented DTO members, the projection rule with its placeholder constant, actor includes on the read queries, focused xunit tests, a regenerated `utf-api.json` and `api.ts`, and one typed React test fixture updated for the new required member.
</objective>
