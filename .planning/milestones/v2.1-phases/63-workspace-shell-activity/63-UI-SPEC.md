# Phase 63 - UI Design Contract

> Visual and interaction contract for Phase 63: Workspace Shell & Activity.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Scope: `sources/ReactApp`, plus the minimal actor projection on the job and operation DTOs approved in
> 63-CONTEXT "Post-Research Decisions" (OpenAPI snapshot and generated TypeScript types refreshed). `sources/WebApp`,
> generated Kiota output and `sources/Common/Ui/routes.json` are not touched. No new pathnames.
> Requirements covered: WSP-01, WSP-02 (amended by D-02), WSP-03, WSP-04, WSP-05, WSP-06, CST-01, CST-02, ACT-01, ACT-02.
> Inherits without change: `61-UI-SPEC.md` (design system, spacing, typography, color, state and cost model, cost
> confirmation, unavailable-action pattern, localization, token rules) and `62-UI-SPEC.md` (filter chip visuals,
> live update client, live notice behavior). This file only adds or overrides what the workspace needs. Anything not
> stated here is exactly as in Phase 61 and 62.

Opening a server answers "what state is it in, who pays, how do I connect, what is happening, what do I do next" without
switching tabs. The workspace is a working tool inside the Command Center (Phase 62 D-01): quiet surfaces, one accent
action, failure and cost information stated plainly.

## Shell Anatomy (WSP-01, WSP-06, D-04)

Route `/command/servers/:serverId` (unchanged). Top to bottom, one column, inside the existing `next-hosting-page`
container. The shell renders in every section; only the section content below the navigation changes.

| Order | Element | Renders when | Scroll behavior |
|-------|---------|--------------|-----------------|
| 1 | `Breadcrumbs`: Servers › {server name} › {section} | server loaded | scrolls away |
| 2 | `WorkspaceHeader` (`<header>`): `h1` server name, `ServerStateSummary`, primary action | server loaded | **sticky** at every width |
| 3 | Details block: `CostStrip`, `ServerEndpoint`, Refresh server | server loaded | scrolls away |
| 4 | Shell notices: paused-by-operator, archived, deep-link notice, request error | each when its condition holds | scrolls away |
| 5 | `JobProgressStrip` | an active job exists | scrolls away |
| 6 | `JobFailurePanel` | newest terminal job is `Failed` | scrolls away |
| 7 | `SectionNavigation` | server loaded | scrolls away (not sticky) |
| 8 | Section content | per `?tab=` | normal flow |
| - | Visually hidden polite live region | always mounted | - |

Removed from the old header: kicker (`gameIdentifier · runtimeProviderIdentifier`, moved to Overview facts), the
description paragraph `Hosting_Detail_Description`, the "Back to fleet" button (becomes the breadcrumb), the Delete
server button (moved to Settings, see Settings section), the overview "next action" panel (its button is the header
primary action).

### Breadcrumbs (WSP-06)

- `<nav aria-label={Server_Workspace_Breadcrumb_Label}><ol>`; three items: "Servers" (a plain react-router `Link`, not
  button-styled, to `/command/servers`), server name (`Link` to `/command/servers/{id}` with no search), section label (plain
  text, `aria-current="page"`). On Overview the third item is "Overview".
- Separator: `ChevronRight16Regular`, `aria-hidden`, rendered by the component between items (not in the text).
- Body 14/400. Links `--utf-text-muted`, underline on hover and focus; current item `--utf-text`. Gap `--utf-space-xs`.
- The server name wraps with `overflow-wrap: anywhere` and is never clamped here; this is where a long name is read in
  full (see the header clamp).

### WorkspaceHeader (compact sticky bar)

- `<header>` containing the page `h1` (keeps `heading.closest("header")` working, Pitfall 10).
- `position: sticky; top: var(--command-header-height); z-index: 10` (the command topbar is `z-index: 15`, 64px at
  every width). Exactly one sticky element in the shell; the legacy `.command-shell .next-hosting-tabs` sticky rule in
  `commandCenter.css` is deleted.
- Surface `--utf-surface-raised`, 1px `--utf-border-divider` border, radius `--utf-radius`, elevation `--utf-elevation-1`,
  padding `--utf-space-sm` block / `--utf-space-md` inline. Opaque background so content never shows through.
- Layout:

| Width | Layout |
|-------|--------|
| > 800px | Two columns: left stacks `h1` (Display 28/700) then `ServerStateSummary`; right holds the primary action, vertically centered. Title clamps at 2 lines. |
| 521-800px | Same two columns; `h1` drops to Heading 20/700; primary action 44px tall. Title clamps at 2 lines. |
| <= 520px | One column: `h1` (Heading 20/700, clamped to 1 line), `ServerStateSummary` (wraps), primary action full width, 44px. Measured budget: 8 + 24 + 8 + 24 + 8 + 44 + 8 = 124px, plus the 64px topbar = 188px, under one third of a 568px viewport. |

- Title clamp is a declared exception to the "never ellipsize a server name" rule (Phase 61/62), justified because the
  bar is sticky: `display: -webkit-box; -webkit-line-clamp: N; overflow: hidden` with `overflow-wrap: anywhere`. The
  full text stays in the DOM (screen readers read it all) and the breadcrumb shows it unclamped. No `title` tooltip.
- Primary action: `primaryServerAction(server.actions, possibleCost)` (unchanged rule; prefers a graceful cost-stop when
  cost may remain). Variant: `gold` for `start`, `danger` for `stop` and `terminate`, `primary` otherwise. Pending:
  label `Server_Action_InProgress`, `ghost`, disabled with `Server_Reason_Pending`. Disabled: `ActionUnavailableReason`
  below it (inside the bar, wraps). No primary action: the bar shows title and state only. Activation:
  `request({ serverId, actionId, source: "workspace-header" })` and nothing else.
- Exactly one button with the primary action's name in the shell header. The Overview "More actions" list excludes it.

### Details block (scrolls away)

Flat (elevation 0, no background), bottom 1px `--utf-border-divider`, padding-block `--utf-space-md`, internal gap
`--utf-space-md`. Contains, in order: `CostStrip`, `ServerEndpoint`, and a right-aligned row with "Refresh server"
(`ghost`, disabled while any workspace query is fetching; invalidates fleet, exact server, jobs, operations and
notifications as today). `<section aria-label={Server_Workspace_Details_Label}>`.

### CostStrip (CST-01, D-05, D-06)

A `<dl>` with five rows, always all rendered (a missing value shows its fallback, never an empty cell):

| Row | `dt` | `dd` value | Fallback |
|-----|------|-----------|----------|
| 1 | Cost owner (`Hosting_Common_CostOwner`) | `ownerFor(server.costOwnerName)` (maps API placeholders to `Server_Confirm_OwnerHidden` / `Server_Confirm_OwnerUnknown`; never the raw API placeholder) | `Server_Confirm_OwnerUnknown` |
| 2 | Per hour | `formatHourlyRate(deployment?.estimatedHourlyCostEur ?? server.estimatedHourlyCostEur)` (same rule as the confirmation dialog, extracted into one shared `serverCostFacts(server)` helper) | No estimate |
| 3 | Per month if left running | `formatMoney(server.estimatedMonthlyCostEur)` | No estimate |
| 4 | Cost now | `CostIndicator` for `deriveServerState(server)` (a server that may still cost is never shown as not costing; FND-03 invariant) | n/a (always a value) |
| 5 | This session so far | `SlotPlaceholder` inline variant: muted "Not available yet", wrapper `data-slot="accrued-cost"` | Phase 66 replaces the text with the real figure; never `0`, never an invented amount |

Layout: > 520px a grid `repeat(auto-fit, minmax(min(100%, var(--utf-workspace-fact-min)), 1fr))`, `dt` above `dd`,
column gap `--utf-space-lg`, row gap `--utf-space-md`. <= 520px a two-column list (`dt` left, `dd` right, each
`minmax(0, 1fr)`), row gap `--utf-space-sm`, matching the dialog facts. `dt` Label 12/700 muted (`--font-label`,
uppercase, 0.06em); `dd` Body 14/400 `--utf-text`, amounts `font-variant-numeric: tabular-nums`. All amounts through
`Intl` with `currentLocale()`.

### ServerEndpoint (WSP-01)

- Label `dt`-style "Server address". When `deployment.connectionEndpoint` is non-null: the value in `<code>` (Body
  14/400 monospace, `overflow-wrap: anywhere`, `user-select: all`) followed by `CopyButton` "Copy address".
- When null: Body 14/400 muted line "Available while the server is running." Visibility is decided only by the field's
  presence, never by `deployment.status` in React.
- The administrative SSH command stays in Machine (operator-only, already gated by the API).

### CopyButton (shared)

- `ActionButton variant="ghost" size="compact"`, leading `Copy20Regular` (aria-hidden), visible caller-supplied label
  ("Copy address", "Copy output"). 40px tall, 44px at <= 800px.
- Success: icon swaps to `Checkmark16Regular` and the label to `Shared_Copy_Done` "Copied" for 2 seconds, then reverts;
  a polite `role="status"` sibling announces the caller-supplied message ("Server address copied.").
- Failure (no `navigator.clipboard`, insecure context, `NotAllowedError`): label unchanged, the status region shows
  `Shared_Copy_Failed` as visible Body text below the control (muted, wraps) for as long as the component is mounted
  or until the next attempt. The value stays selectable.
- Copies only on explicit activation; never on focus, hover or load.

### Shell notices

| Notice | Condition | Variant | Copy |
|--------|-----------|---------|------|
| Paused | any action's `unavailableReason` equals the paused reason | `StatePanel kind="info"`, `role="status"` | `Server_Reason_Paused` (existing) |
| Archived | `server.isArchived` | `StatePanel kind="info"` | `Server_Workspace_Archived` |

## Section Navigation and Deep Links (WSP-02 amended, WSP-03, D-01..D-03)

### Sections

| Order | Id (`?tab=`) | Label key | Content | Visible to |
|-------|--------------|-----------|---------|-----------|
| 1 | (none) `overview` | `Server_Workspace_Section_Overview` | facts, metrics slot, recent activity, more actions | everyone with view access |
| 2 | `activity` | `Server_Workspace_Section_Activity` | merged timeline (jobs + logs + audit) | everyone with view access |

| 5 | `machine` | `Server_Workspace_Section_Machine` | cloud machine facts, resources, diagnostics, runtime settings | everyone with view access |

  stale deep link never re-fires). Parse with a whitelist (`workspaceSectionFromSearch`): unknown, empty or retired
  values (`runtime`, `cloud`, `logs`, `configuration`, `credentials`, `jobs`, `audit`) render Overview and the URL is
  left unchanged. No mapping table (D-02). WSP-02 and roadmap SC-2 are amended at plan time to "retired `?tab=` values

- Every item is a react-router `Link` (`to={{ pathname: "/command/servers/{id}", search }}`), not a button, so links can
  be opened in a new tab or copied. Inside `<nav aria-label={Hosting_Detail_WorkspaceNavigation}><ul>`. The current
  item has `aria-current="page"`. No `role="tab"`.
- Activating a link keeps focus on the link and does not scroll the page. The section content renders immediately below.

### Visual

- Each link: min-height `--utf-control-height` (40px; `--utf-control-height-touch` 44px at <= 800px), padding-inline
  `--utf-space-md`, Label 12/700 `--font-label` uppercase 0.06em, color `--utf-text-muted`, centered text, no icon.
- Hover: text `--utf-text`, background `--utf-surface-overlay`, transition `--utf-motion-fast`.
- Current: text `--utf-text` and a bottom indicator `--utf-indicator-width` (2px) solid `--gold` (accent use 2 of 3).
  The indicator is a shape cue, so current state is not carried by color alone.
- Focus: `--utf-focus-ring`, `--utf-focus-offset`.
- The `<ul>` has a 1px `--utf-border-divider` bottom border; margin-bottom `--utf-space-lg` before the section content.

### Narrow widths (D-03, UI-60-001)

Mechanism decided: **wrap, never scroll.** `display: flex; flex-wrap: wrap; gap: var(--utf-space-xs)`; `overflow-x`
removed. At <= 520px each link is `flex: 1 1 auto` so wrapped rows fill the width evenly. German labels are the width
driver ("Einstellungen", "Aktivität"); at 320px and 390px all five links are visible on at most two rows with no
horizontal page scroll and no link outside the viewport. Tab order follows DOM order (Overview, Activity, Settings,
Files, Machine).

### Activity deep link ("Open activity details")

- Target: `?tab=activity#activity-job-<jobPk>` (entry ids: `activity-job-<pk>`, `activity-log-<commandPk>`,
  `activity-audit-<pk>`).
- On arrival with data loaded: reset the type filter to All and Problems only to off, page in until the entry is
  rendered, expand it, scroll it into view (`behavior: "auto"`, so no motion), and move focus to the entry
  (`<article tabIndex={-1}>`). Matched with `Array.find` against entry ids, never by indexing with the fragment.
- If no entry matches: a `StatePanel kind="info"` line `Server_Activity_EntryMissing` at the top of the timeline; focus
  is not moved.

## Progress Strip (WSP-04, D-08)

Shows the newest active job (status `Queued`, `Running`, `WaitingForWorker` or `RetryPending`; newest by
`timeStampCreated`). Absent when no job is active. A pure `deriveJobProgress(job)` produces `{ steps, currentStep,
mode }`; it is exhaustive over `ELifecycleJobKind` x `ELifecycleJobStatus`, and an unknown stage string never throws.

### Step lists (labels are keys `Server_Progress_Step_*`)

| Job kind | Steps in order |
|----------|----------------|
| Start | Waiting to begin → Preparing the cloud machine → Waiting for the server software → Working on the server → Finishing up |
| Stop | Waiting to begin → Saving server data → Releasing the cloud machine → Finishing up |
| Terminate | Waiting to begin → Releasing the cloud machine → Finishing up |
| Restart, Install, Update, CollectLogs, Custom | Waiting to begin → Working on the server → Finishing up |

### Current-step derivation (first match wins)

| Condition | Current step |
|-----------|--------------|
| status `Queued` | Waiting to begin |
| status `RetryPending` | mode `retry` (see below) |
| status `WaitingForWorker`, or stage `waiting-for-worker` | Waiting for the server software (Start); otherwise Working on the server |
| stage starts with `provider-` or equals `claimed` / `recovered`, and no command is `Received`/`Running`/`Succeeded` | Start: Preparing the cloud machine; Stop and Terminate: Releasing the cloud machine; others: Working on the server |
| any command `Received` or `Running` | Stop: Saving server data; others: Working on the server |
| Stop or Terminate, stage contains `preservation` | Saving server data (Stop) |
| Stop or Terminate after the worker command succeeded, stage starts with `provider-` | Releasing the cloud machine |
| a command `Succeeded` and the job is not terminal | Finishing up |
| anything else | mode `generic`: no step list; current line "Working" plus the raw stage token in `ApiText` (muted) |

Steps before the current one render as done; after it as upcoming. `progressPercent` is never rendered (no bar, no
number); the existing `<progress>` in the job view is removed.

### Anatomy

`<section aria-labelledby>` with surface `--utf-surface-raised`, 1px `--utf-state-info-border` border, radius
`--utf-radius`, elevation `--utf-elevation-1`, padding `--utf-space-md`, inner gap `--utf-space-sm`.

| Order | Element | Typography | Rule |
|-------|---------|-----------|------|
| 1 | Kicker with `ArrowSync16Regular` (rotates only under `prefers-reduced-motion: no-preference`) | Label 12/700, `--utf-state-info-fg` | `Server_Progress_Kicker` |
| 2 | Title line (`id` for `aria-labelledby`): action label, then current step | Body 14/700 action label, Body 14/400 step | Action label from the job kind (`Server_Action_*_Label`, Custom → `Server_Activity_Kind_Custom`). Two elements joined by a CSS separator, not one combined key. |
| 3 | Steps `<ol aria-label={Server_Progress_StepsLabel}>` | Body 14/400 | > 800px horizontal row, wraps; <= 800px vertical list. Marker icons 16px: done `CheckmarkCircle16Regular` (`--utf-state-success-fg`), current `ArrowSync16Regular` (`--utf-state-info-fg`; label `--utf-text` at weight 700), upcoming `Circle16Regular` (`--utf-text-subtle`). Current item `aria-current="step"`; each item has a visually hidden state word (done / current step / not started). |
| 4 | Meta line | Body 14/400 muted | "Started 4 minutes ago" (`Server_Progress_Started` with `Intl.RelativeTimeFormat`, from `timeStampStarted`) or "Requested 4 minutes ago" (`Server_Progress_Requested`, from `timeStampCreated`, while `Queued`), then "Requested by {{actor}}". Refreshed on a 15s clock while mounted. |
| 5 | Lag note | Body 14/400 muted | `Server_Progress_Lag` (honest about the ~30s fallback poll; Pitfall 1) |
| 6 | Queue line | Body 14/400 | Only when more than one job is active: `Server_Progress_MoreQueued_one/_other` |
| 7 | Link "Open activity details" | `ActionLink variant="ghost" size="compact"` | to the job's entry (see Activity deep link) |

Note on weights: the current step uses weight 700, done and upcoming use 400. Only weights 400 and 700 exist.

### Retry mode (`RetryPending`, Pitfall 8)

Border and kicker switch to `--utf-state-warning-*` with `Warning16Regular`. No step list. Title line: action label +
"Waiting to retry". Body: `Server_Progress_RetryBody`, the failure reason in `ApiText` when present, then the cost
sentence (same keys as the failure panel). When the active job is not itself a cost-stop (`Stop`/`Terminate`) and cost
is not `none`, show "Shut down and stop billing" (`danger`, `source: "workspace-failure"`). When it is a cost-stop job,
show `Server_Failure_Next_Wait`. The failure panel never renders for a `RetryPending` job.

## Failure Panel (WSP-05, D-09)

### When it shows

Only when the newest terminal job (newest by `timeStampCreated` among jobs whose status is `Succeeded`, `Failed`,
`Skipped`, `CancelledByCostStop`) is `Failed` **and** no job is active. A newer job of any kind supersedes it. It is not
dismissible; it clears when the job is retried, skipped or superseded. While a job is active, the progress strip owns
the space.

### Anatomy

`<section aria-labelledby>`; surface `--utf-surface-raised`, 1px `--utf-state-danger-border` border;
a leading `ErrorCircle20Regular` icon in `--utf-state-danger-fg`; radius `--utf-radius`; padding `--utf-space-md`;
inner gap `--utf-space-md`. Not a live region on mount (a pre-existing failure is not shouted at page load); a failure
that happens while the page is open is announced once through the shell live region (`Server_Workspace_Announce_JobFailed`).

| Order | Element | Typography | Rule |
|-------|---------|-----------|------|
| 1 | Title `h2` | Heading 20/700, `overflow-wrap: anywhere` | `Server_Failure_Title` with the job's action label |
| 2 | Facts `<dl>` (same layout rules as the cost strip <= 520px list, two columns above) | `dt` Label 12/700 muted; `dd` Body 14/400 | Rows below, each always rendered |
| 3 | Actions row | buttons per table below | wraps; <= 520px stacked full width in the listed order |
| 4 | Request error slot | Body 14/400, `--utf-state-danger-fg`, `role="alert"` | empty until retry/skip fails |

| `dt` | `dd` |
|------|------|
| What failed (`Server_Failure_WhatFailed`) | `Server_Failure_FailedAt` with the step derived from the job's last stage (generic step allowed), then the reason in `ApiText` (`failureReason`), or `Server_Failure_NoReason`. Time below in muted Body: relative time with `<time dateTime>`. |

## Activity Section (ACT-01, ACT-02, D-10, D-11)

### Data and model

`buildActivityEntries(jobs, operations)` is pure and unit-tested. Inputs: jobs (newest 100 with commands) and
operations (request `take=200`, the API maximum, to align the windows; Pitfall 7).

| Type | One entry per | `at` (sort key) | Problem when | Actor |
|------|---------------|-----------------|--------------|-------|
| job | lifecycle job | `timeStampCompleted ?? timeStampUpdated` | status `Failed`, or `RetryPending` with a failure reason | job requester (API projection) |
| log | worker command | `completed ?? started ?? created` | command `Failed` or `CancelledByCostStop` | "The server" (system actor) |
| audit | hosting operation | `timeStampCreated` | `hostingAuditTone` is `danger` or `warning` | operation actor (API projection) |

### LiveBadge (ACT-02, D-11)

`deriveFreshness({ status, dataUpdatedAt, now, hasActiveJob })`; `dataUpdatedAt` is the newer of the jobs and
operations queries.

| State | Condition | Visual | Text |
|-------|-----------|--------|------|
| connecting | socket `connecting` and never opened in this page session | neutral pill (`--utf-state-neutral-*`), `ArrowSync16Regular` | "Connecting" |
| live | socket `open` and (no active job, or data age <= 60s) | success pill (`--utf-state-success-*`), `Live16Regular` | "Live" |
| stale (disconnected) | socket `reconnecting` or `unavailable` | warning pill (`--utf-state-warning-*`), `PlugDisconnected16Regular` | "Not up to date" + reason line `Server_Live_StaleReason_Disconnected` + "Reconnect now" (`ghost` compact, `reconnectNow`) |
| stale (old) | socket `open`, a job is active, data age > 60s | warning pill, `Warning16Regular` | "Not up to date" + `Server_Live_StaleReason_Old` + "Refresh activity" (`ghost` compact, refetches jobs and operations) |

- Beside the pill, always: "Updated {{relative}}" (Body 14/400 muted, `<time dateTime>`).
- The state word sits in a polite live region that changes only on state transitions; the ticking relative time is
  outside it, so nothing is announced every tick.
- The stale disconnected state appears only after 3s of continuous disconnection (Phase 62 anti-flicker rule).
- The badge never claims "Live" for output that arrives by the 30s fallback poll: while a job is active, freshness
  depends on data age, not on the socket alone.

### Live update behavior (D-07, contract for the UI)

- One socket (the Phase 62 provider). A workspace listener invalidates exactly `server(id)` (with `exact: true`),
  `jobs(id)` and `operations(id)` for frames carrying this server's id, coalesced to at most one call per 500ms, and
  once more on every reconnect.
- Fallback poll: `refetchInterval` 30s on those three queries only while a job is active; no interval otherwise. The
  three 5s intervals are removed.
- No visual loading flash on background refetch: content stays, the timeline sets `aria-busy` during refetch.

## Accessibility and Responsive Contract (WSP-03, FND-06 gate for this phase)

- Landmarks and headings: breadcrumb `nav`, `header` with the only `h1`, details `section` with label, section `nav`,
  panels with `h2`, activity day groups `h3`. No skipped levels.
- Keyboard order: breadcrumbs, header primary action, Copy address, Refresh server, notice controls, progress strip
  link, failure panel actions, section links, section content. No positive `tabindex`. Disabled actions stay focusable
  (`aria-disabled`) with the reason linked by `aria-describedby`.
- Section navigation: links with `aria-current="page"`; reachable and visible at 320 and 390 without horizontal scroll.
- Progress steps: `aria-current="step"` plus a visually hidden state word per step; icons `aria-hidden`.
- Live regions: one visually hidden polite shell region for job finished / failed announcements (only for transitions
  observed while the page is open, never at load, at most one message per refetch); the live badge state word; copy
  results. Request errors `role="alert"`. Nothing moves focus except the activity deep link and "Show more activity".
- Raw output `pre` is focusable (`tabIndex={0}`) so keyboard users can scroll it; it has an accessible name from its
  entry sentence (`aria-labelledby`).
- Targets 44px at <= 800px for every control including section links and disclosure buttons; never below 24px.
- Motion: only `--utf-motion-*` color, border and opacity transitions; `ArrowSync` rotates only under
  `prefers-reduced-motion: no-preference`; scroll-into-view uses `behavior: "auto"`.
- Verification (Playwright, English and German, 320x568 and 390x844): `scrollWidth <= clientWidth` (1px rounding
  allowance, Phase 62 rule); each of the five section links inside the viewport; the sticky header stays visible after
  scrolling the Activity section and its height is at most 190px at 320x568; Tab reaches all five links in order;
  `@axe-core/playwright` WCAG 2.1 AA scan with zero violations and at least one rule evaluated on Overview, Activity
  (with an expanded entry and the stale badge), the failure panel and the progress strip.
