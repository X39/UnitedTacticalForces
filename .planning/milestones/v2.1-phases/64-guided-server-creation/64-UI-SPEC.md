# Phase 64 - UI Design Contract

> Visual and interaction contract for Phase 64: Guided Server Creation.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Scope: `sources/ReactApp` only. `sources/WebApp`, generated Kiota output, and `sources/Common/Ui/routes.json` are not touched. No new pathnames: the create page stays at `/command/servers/create`, the workspace at `/command/servers/{id}`. No API, DTO, or database change (see Research Findings).
> Requirements covered: CRT-01, CRT-02, CRT-03, CRT-04, CRT-05, CRT-06.
> Inherits without change: `61-UI-SPEC.md` (design system, spacing, typography, color, state and cost model, cost confirmation, unavailable-action pattern, localization, token rules), `62-UI-SPEC.md` (fleet create entry, `Create server` link is `primary` on the fleet and `gold` only in the creator empty state) and `63-UI-SPEC.md` (breadcrumbs, shell notice slot, workspace landing). This file only adds or overrides what the create flow needs. Anything not stated here is exactly as in Phase 61, 62 and 63.

The create page replaces the 12-field form. A member names a server, picks a size, sees the cost, and decides whether it starts. Everything else has a sensible default and sits behind one disclosure. The page is a working tool inside the Command Center: quiet surfaces, one accent action, cost stated plainly and before commitment.

## Research Findings That Shape The Contract

Verified in code on 2026-11-19. They resolve the open items in `64-CONTEXT.md`.

| Question | Finding | Consequence |
|----------|---------|-------------|
| D-06: is there a "cannot pay" signal beyond frozen? | `CostOwner.Balance` exists in `sources/Database/Hosting/CostOwner.cs` but is not projected on `GameServerCostOwnerOptionDto` (fields: `costOwnerId`, `displayName`, `isFrozen`, `isCurrentUser`) and the lifecycle service rejects a new server only when `IsFrozen` (`GameServerLifecycleService.cs` lines 208, 353, 750). | "Cannot pay" means "frozen" in this phase. No API projection is added: showing a balance-based block that the API does not enforce would let the UI claim a failure the server would not raise. The block copy says "frozen", never "insufficient funds". Balance-aware blocking belongs with Phase 66 (cost) if ever needed. |
| D-01: is there a default flag or description on a configuration profile? | `GET /configuration-profiles/options` returns `primaryKey`, `title`, `gameIdentifier`, `latestRevisionNumber` (and `isArchived`); no default flag, no description. Mod pack options return `primaryKey` and `title` only. | A preset shows its kind, title and (profiles only) revision. No invented metadata. "Game defaults" is the built-in first preset (no profile, no mod pack). |
| Sizes and prices | `RuntimeProfileDto` carries `displayName`, `virtualCpuCount`, `memoryGiB`, `diskGiB`, `estimatedHourlyCostEur`, `estimatedMonthlyCostEur` (nullable). | Size choice and live estimate need no new data. |
| Create semantics | `GameServerCreationPayload` "creates a durable game-server record without starting a deployment". | The page may truthfully say that creating does not start a cloud machine and that cost starts when the server starts. |
| `useCostConfirmation` source union | `CostConfirmationSource` in `src/components/server/useCostConfirmation.ts` has no `create` member, although `61-UI-SPEC.md` names it. | The plan adds `"create"` additively to the union. |

## Page Anatomy (CRT-01, CRT-04, D-03, D-04)

Route `/command/servers/create`. One page, one column of content, plus the summary.

| Order | Element | Renders when | Notes |
|-------|---------|--------------|-------|
| 1 | `Breadcrumbs`: Servers › Create server | always | Scrolls away. |
| 2 | `PageHeader` h1 "Create server", description | always | Scrolls away. |
| 3 | Page state panel | capabilities loading, failed, empty, or viewer lacks the create claim | Replaces everything below (copy carried, see Copywriting Contract). |
| 4 | Section "Your server" (h2): Name, Game, Preset, Size, Billed to | capabilities loaded | The three decisions are Name, Game and Size. Game renders as a read-only fact when only one game exists (then there are two decisions). Preset renders only when the game has at least one configuration profile or mod pack, and is a shortcut, not a decision. |
| 5 | `AdvancedOptions` (Disclosure "Advanced options") | capabilities loaded | Collapsed by default. Always shows a summary line. |
| 6 | Section "After creating" (h2): `AfterCreatingChoice` | capabilities loaded | Default "Keep it off". |
| 7 | "Leave without creating" (`ghost` `ActionLink` to `/command/servers`) | capabilities loaded | In the main column at every width, before the summary in DOM order. |
| 8 | `CreateSummary` | capabilities loaded | DOM-last. Desktop: right column, sticky. Narrow: sticky bottom bar. |
| - | Visually hidden polite live region | always mounted | Announces preset applied, game changed and estimate changes (throttled). |

Heading levels: h1 page title, h2 "Your server", h2 "After creating", h2 "Estimated cost" inside the summary. The Advanced summary element is not a heading.

### Layout

| Width | Layout |
|-------|--------|
| > 800px | Two columns: main `minmax(0, 1fr)`, summary `var(--utf-create-summary-width)` (352px). Column gap `--utf-space-lg`. Summary is `position: sticky; top: calc(var(--command-header-height) + var(--utf-space-md))`, surface `--utf-surface-raised`, 1px `--utf-border-divider`, radius `--utf-radius`, elevation `--utf-elevation-1`, padding `--utf-space-md`, internal gap `--utf-space-md`. |
| 521-800px | One column. Summary is a sticky bottom bar (below). Controls 44px tall. |
| <= 520px | One column, summary bar full width, buttons full width, 44px controls, field gap `--utf-space-md`. Minimum width 320px, no horizontal page scroll. |

Main column: sections separated by `--utf-space-xl`; fields inside a section separated by `--utf-space-md`. Section panels have no card background (elevation 0, flat), a bottom 1px `--utf-border-divider` between sections, so the cost summary is the only raised surface on the page.

### CreateSummary at <= 800px (sticky bottom bar)

- `position: sticky; bottom: 0; z-index: 10`, opaque `--utf-surface-raised`, top 1px `--utf-border-divider`, padding `--utf-space-sm` block and `--utf-space-md` inline, gap `--utf-space-sm`.
- Contents in order: headline (the hourly figure at Heading 20/700 and the monthly sentence at Body 14/400 muted), the visible reason or request error when present, the submit `ActionButton` full width 44px. The repeated fact rows (size, storage, cost owner, "while it is off" note) are not rendered visibly at this width (`display: none`, they are already visible in the form above); the monthly figure stays visible.
- Height budget, verified at 320x568 in English and German with the longest reason: the bar is at most one third of the viewport (189px). Measured: padding 8 + headline 24 + monthly line 21 + gap 8 + button 44 + padding 8 = 113px enabled; with a two-line reason 113 + 8 + 42 = 163px.
- The form container sets `scroll-padding-block-end: var(--utf-create-bar-reserve)` (192px) so a focused field is never hidden behind the bar (WCAG 2.2 focus not obscured), and the main column has the same bottom padding so the last control can scroll clear of it.

## Spacing Scale

Inherited from Phase 61 without change (all multiples of 4, rem, `--utf-space-xs/sm/md/lg/xl/2xl/3xl` = 4/8/16/24/32/48/64px). Control height `--utf-control-height` 40px, `--utf-control-height-touch` 44px at <= 800px for every input, select, radio row, checkbox row, disclosure summary and button on the page.

Two additive layout tokens in `src/styles/tokens.css` (Phase 62 and 63 precedent; rem, multiples of 4px):

| Token | Value | Usage |
|-------|-------|-------|
| `--utf-create-summary-width` | 22rem (352px) | Width of the desktop summary column |
| `--utf-create-bar-reserve` | 12rem (192px) | Scroll padding and bottom padding that keep fields clear of the sticky bottom bar |

Exceptions: 1px borders, the 2px focus ring (2px offset), and the 16px icon render size inside inline markers (a multiple of 4). Radio and checkbox glyphs use the control height row for their target; the native glyph itself is 20px (a multiple of 4). No other non-multiple-of-4 values; hard-coded spacing in new CSS is not allowed.

Breakpoints (constants): `520px` compact, `800px` narrow (44px targets, sticky bottom bar).

Exactly four sizes and two weights, as in Phase 61.

| Role | Size | Weight | Line Height | Where on this page |
|------|------|--------|-------------|--------------------|
| Body | 14px (0.875rem) | 400 | 1.5 | Hints, helper text, reasons, option text, summary sentences, `dd` values, input text |

- Weights: 400 and 700 only. Field labels are Body size at 700 (not uppercase); hints and helpers are Body at 400 muted.

- Numbers and currency through `Intl` with `currentLocale()` (EUR; German renders `0,42 €`).

Accent reserved for:
1. The single primary action of the view: the submit button (`ActionButton variant="gold"`), whose label follows the "After creating" choice. It is gold at all times, including for "Create server and keep off"; there is no second gold control. The fleet header `Create server` link that leads here stays `primary` (Phase 62).
2. The keyboard focus ring (`--utf-focus-ring`: 2px solid `#dec982`, offset 2px) on every control on the page.

Accent is not used for the selected preset, the checked radio, the open disclosure, links, icons, cost figures or hover states. Checked radio and checkbox glyphs use `--utf-text`.

State color usage: validation errors use `--utf-state-danger-fg` with a `Warning20Regular`-style inline icon (never color alone, the message text is always present). The frozen-owner notice and the storage-fit warning use `StatePanel kind="warning"` (`--utf-state-warning-*`). Blocked-submit reasons use the Phase 61 unavailable-action style: Body, `--utf-text-muted`, 16px `Info16Regular`, directly under the control, `aria-describedby`. Fit "sufficient" text is `--utf-text-muted`, not green (no state badge is implied; this is a field fact).

Contrast: all pairs are existing Phase 61 token pairs, already guarded by `tests/styles/tokens-contrast.test.ts`. Control borders use `--utf-border-control` (3.86 on soft, 4.55 on surface); `--quiet` is not used for text in `components/server/*`.

## Interaction Contract (CRT-01..CRT-06)

### Defaults and generated values (`resolveCreateDefaults`, pure)

| Value | Default |
|-------|---------|
| Game | The first capability in API order |
| Provider | Alphabetically first available provider (`orderProviders`, `isProviderAvailable`) |
| Size | The cheapest size with a known `estimatedHourlyCostEur` for which the storage fit is not `isSufficient === false`; when the fit is unknown or no size has a price, the first size in API order |
| Storage strategy | `AutomaticExternal` when the provider supports external block storage, otherwise `IncludedDisk` (the current form's rule) |
| Terrain and scenario (only when required) | The item whose version matches the capability's `defaultTerrainSourceIdentifier` / `defaultScenarioSourceIdentifier`, else the first item (the current form's rule) |
| Mod pack, configuration profile | none (Game defaults) |
| Cost owner | `null` = the caller's own owner (the current form's rule) |
| Launch disabled | false |
| After creating | Keep it off, always, with or without a preset |

Defaults are re-resolved when the game or provider changes and never overwrite a value the member has chosen that is still valid.

### Preset behavior (CRT-05, D-01, D-02)

- A preset is a client-side projection of existing data: "Game defaults" (profile none, mod pack none), one entry per non-archived configuration profile of the game (`hostingService.profileOptions`), one entry per mod pack (`hostingService.creationModPacks`). No new endpoint, table or admin UI.
- Choosing a configuration-profile preset sets `configurationProfileId` and clears `modPackDefinitionId`; choosing a mod-pack preset sets `modPackDefinitionId` and clears `configurationProfileId`; "Game defaults" clears both. One preset is one starting point; the member can combine a profile and a mod pack afterwards under Advanced options, and the preset line then reads "Customized".
- Choosing any preset, including "Game defaults", sets "After creating" to "Keep it off" and announces `Server_Create_Preset_Announce`. Nothing in the preset flow can start a server.
- The Preset field is omitted when the game has no configuration profile and no mod pack. When its option queries are loading it renders the field disabled with the loading panel; when they fail it is omitted and the options error panel with Try again appears (defaults remain usable, so creation is not blocked by a failed optional list unless the capability requires it).
- Preset and Advanced options edit the same two form values; there is a single source of truth, so the select always reflects the Advanced fields and vice versa.

### Capability-Driven Field Rules (CRT-06, D-04)

Generic rendering from `hostingService.capabilities`; no component under `components/server/*` or the page compares `gameIdentifier` to a literal (a source-scan test fails on `arma3`, `aska`, `counterstrike2` in the create files).

| Field | Rendered when | Required | Data |
|-------|---------------|----------|------|
| Game | always; read-only fact when one capability exists | yes | `capabilities` |
| Preset | profiles or mod packs exist for the game | no | `profileOptions`, `creationModPacks` |
| Size | the selected provider has at least one size | yes | provider `profiles` |
| Provider | more than one available provider; otherwise a read-only "Runs on" line | yes | `runtimeProviderProfiles` |
| Storage strategy, external capacity | always; strategy options `AutomaticExternal` and `FixedExternal` only when `provider.storage.supportsExternalBlockStorage`; capacity only for `FixedExternal`, bounded by the provider's min, max and increment | strategy yes | provider `storage`, `estimateStorage` |
| Mod pack | `capability.supportsModPacks !== false`; required only when `capability.requiresModPack` is true | per capability | `creationModPacks` |
| Terrain | `capability.requiresTerrain`, label from `capability.terrainLabel` | yes | `terrains` |
| Scenario | `capability.requiresScenario`, label from `capability.scenarioLabel` | yes | `scenarios` |
| Configuration profile | always | no | `profileOptions` |
| Cost owner | always | yes | `creationCostOwners` |
| Launch disabled | always | no | n/a |
| About this game | capability has a description or actions | n/a | `capability.description`, `capability.actions` |

If a required capability field (terrain, scenario, a required mod pack) has no valid value after defaults, the Advanced disclosure opens automatically and the field shows its error; nothing required is ever hidden in a collapsed disclosure.

### Advanced disclosure

- Collapsed by default; the toggle (`aria-expanded`, `aria-controls`) is a `<summary>` of the shared `Disclosure`, 40px (44px at <= 800px), Body 14/700 title with a chevron. The summary line under the title is always visible and lists the effective values (provider when shown, storage, mod pack, configuration, required terrain or scenario), wrapping, never truncated.
- Auto-opens (and stays open until the member closes it) when: the member activates "Change cost owner", a field inside has a validation error after a submit attempt, the storage selection does not fit, or a required capability field has no value. Focus moves to the relevant field for the first two cases.
- Fields inside keep their order: Provider, Storage, Mod pack, Terrain, Scenario, Configuration profile, Cost owner, Launch disabled, About this game. Nested `Disclosure`s (Storage details, About this game) are collapsed by default.

### Early block (CRT-03, D-06)

- The cost owner is judged from `creationCostOwners`: the selected owner, or the caller's own (`isCurrentUser`) when none is selected. `isCostOwnerSelectionValid` stays the rule (frozen or unknown means blocked; the options still loading also blocks).
- When the owner is frozen: the "Billed to" line shows the warning panel `Server_Create_Owner_Frozen`; the submit is blocked with reason 1 before any request; the "Change cost owner" control is the recovery path. If the member has no non-frozen owner to choose, the reason alone remains.
- The submit uses the shared `unavailableReason` pattern: `aria-disabled="true"`, focusable, activation does nothing (including Enter in a text field, which must not submit while blocked), reason visible below and linked with `aria-describedby`.
- The server-side rejection of a frozen owner stays the real guard; if the API still rejects (for example the owner froze after the page loaded), the request error copy appears and the cost owner list is refetched.

### Field validation and submit

- Validation (zod schema from `createServerModel.ts`, messages from the keys above) runs on blur and on submit. The submit control is enabled unless one of the eight blocking conditions holds, so a missing name is reported by field, not by a silently disabled button.
- Invalid submit: no request is made; the summary shows the invalid-fields `role="alert"` message; focus moves to the first invalid field in DOM order (opening Advanced first when it lives there); each invalid field has `aria-invalid="true"` and its error linked by `aria-describedby`.
- Valid submit: payload as today (`title` trimmed, `externalStorageSizeGiB` only for `FixedExternal`, `configurationProfileRevisionId: null`). While pending: the form has `aria-busy="true"`, every field and the leave link are non-interactive, the submit shows `Spinner` plus `Server_Create_Submit_Pending`, and the selection of "After creating" is frozen.
- Request failure: the form stays editable, the `Server_Create_Error` text appears in a `role="alert"` slot above the submit, focus moves to that slot, nothing was started (no `request()` call is made after a failed create).

### After creating and the start path (CRT-04, D-07)

1. Keep it off: create, reset the form baseline so the unsaved-changes guard does not fire, invalidate fleet, notifications and the cost-owner query as today, show `Server_Create_Toast_KeepOff`, navigate to `/command/servers/{id}` (replace=false). Nothing else runs. Focus lands on the workspace h1 (Phase 63 behavior).
2. Start it now: create, reset the baseline, invalidate as above, show `Server_Create_Toast_Start`, navigate to `/command/servers/{id}` with router state `{ createdStartPending: true }`, then call `useCostConfirmation().request({ serverId, actionId: "start", source: "create" })`. The Phase 61 dialog opens over the workspace with estimate, cost owner and how to stop; confirm and dismiss behavior is exactly Phase 61.
3. Dismissed or failed start: the server stays created and off. The workspace shows the `Server_Create_Notice_NotStarted` info notice in the shell notice slot (Phase 63 slot 4) while router state `createdStartPending` is present and the derived state is `off`; it disappears when the server leaves `off` or the member dismisses it, and it never re-appears on reload (router state is not persisted beyond the history entry). A start request error stays inside the dialog with the Phase 61 request-error copy.
4. If the start action is missing or disabled on the new server (for example launch disabled, paused by the operator), `request()` is not called and the notice shows the mapped reason from `UnavailableReason` appended to the notice text.
5. Launch disabled interaction: ticking "Keep launch disabled" disables the "Start it now" radio with the `Server_Reason_LaunchDisabled` reason visible below the group and forces "Keep it off". Unticking does not re-select "Start it now".

### Live cost estimate (CRT-02, D-05)

- Hourly = `combinedHourlyCost(profile, selectedStorageBytes, strategy, provider.storage)`; monthly per the money rule above. Both recompute synchronously on every change of size, provider, storage strategy, external capacity, mod pack (via the storage estimate) and game.
- The summary headline is the first thing in the summary and the largest type on the page (Heading 20/700); the submit sits directly below the reasons. While the storage estimate is fetching the hourly line shows "Calculating…" (it never shows a stale amount as final) and reason 7 blocks the submit.
- Announcements: the hidden polite region announces `Server_Create_Cost_Announce` only when the hourly value changed, debounced to 600ms after the last change, never on every keystroke of the capacity field.
- The summary rows (size, storage, cost owner) always render; a missing value shows its fallback, never an empty cell.

### Keyboard and focus

- DOM order equals visual order within the main column: Name, Game, Preset, Size, Change cost owner, Advanced options, After creating, Leave without creating, then the summary controls (submit). The summary column is visually to the right on desktop, which is acceptable because it is supplementary and DOM-last; no positive `tabindex`.
- Enter in a text field submits the form only when the submit is not blocked; Space and arrow keys operate the radio group natively; the disclosure toggles with Enter and Space.
- Preset change, game change and size change keep focus on the control; results are announced through the live region.
- Focus ring `--utf-focus-ring` on every control; the sticky bar never covers a focused control (`scroll-padding-block-end`).

### Motion

Disclosure chevron rotation and open/close use `--utf-motion-base`; under `prefers-reduced-motion: reduce` the durations resolve to 0.01ms and the chevron does not animate. No other motion on this page; the `Spinner` in the pending submit is the Fluent component.
