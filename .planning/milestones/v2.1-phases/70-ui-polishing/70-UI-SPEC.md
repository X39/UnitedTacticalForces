# Phase 70 - UI Design Contract

> Visual and interaction contract for Phase 70: UI Polishing.
> Generated by gsd-ui-researcher (autonomous mode: `70-CONTEXT.md` has no locked decisions, discuss was skipped, every decision below is made at the researcher's discretion from the code as it stands on 2026-11-26 and recorded with its rationale).
> Scope: `sources/ReactApp` only. `sources/WebApp` (legacy Blazor) and the generated Kiota client are not touched. No API, database, worker or route change is part of this phase; `sources/Common/Ui/routes.json` and `src/app/urlParameters.ts` are unchanged (no new query parameter, one existing hash anchor is reused).
> Inherits without change: `61-UI-SPEC.md` (tokens, four type sizes, two weights, localization and copy rules, German "du") and `69-UI-SPEC.md` (closed control list, closed header kinds, dialog shell geometry, banned dismiss labels, accent reserved list, token-only CSS guard, FND-06 and L10N-03 gates). This file only adds or overrides what a visual and interaction polish needs. Anything not stated here is exactly as in Phases 61 to 69.

Phase 69 made the app consistent and provable. Phase 68 UAT test 1 answered: "Shit works but looks like shit still." The remaining defects are not structural, they are craft: checkboxes and radios are the browser's, buttons have three unfinished variants, the Settings tab is one very long page, a configuration value that gets staged moves the layout, the review and leave dialogs are cramped or lopsided, the Files panel looks like three unrelated widgets, and the weekday grid shows two days per row at 320px where the Phase 68 contract says four. This phase fixes every one of them in the shared primitives first, then composes the screens from the repaired primitives. It adds no product capability and no new color.

## Research Findings That Shape The Contract

Verified in the code on 2026-11-26 (read-only; no build was run).

| Question | Finding | Consequence |
|----------|---------|-------------|
| Checkbox and radio look | `form-fields.css` styles `.form-field__check input` and `.form-field__radio-row input` with `accent-color: var(--utf-text)` only: the browser draws the box, circle and tick. `RadioGroupField` is a plain stack of label rows. `CheckboxField` has 19 call sites in 15 files, `RadioGroupField` 6 call sites in 5 files. Three more raw `input[type=radio\|checkbox]` live in `EventObjectiveIconPicker`, `EventSlotPlanner` (2) and `EventRoleSymbolPicker` (all on the Phase 69 ratchet list). | One custom-drawn mark on top of the native input, fixed once in `FormFields.tsx` and `form-fields.css`; two new shared shapes (choice cards, switch) and one chip shape for the weekday group. |
| Boolean settings | `ConfigurationEntryField` renders a boolean configuration entry as a `SelectField` with two options (Enabled, Disabled). `AutomationPanel` (idle, maximum runtime) and `CostAlertSettingsPanel` (three channels) use `CheckboxField` for what is an on or off setting. | A switch is the right control for an on or off setting; a select with two options is the wrong one. |
| Select | `SelectField` already has `appearance: none`, a padded chevron and the control height token (Phase 69 D-09). What is still plain is the closed control surface and the popup, which are the browser's. | Keep the native select (mobile picker, keyboard, screen reader). Style the closed control and, where the browser supports `appearance: base-select`, the popup too. |
| Disclosure | `<details>` no longer exists in `src` (grep: zero). `Disclosure` is already a `<button aria-expanded aria-controls>` plus a `region` (Phase 69 D-08), but its style is a bare text row (`padding: 0`, transparent) that reads as a link, and it has no heading wrapper, no anchor id and no badge slot. | The Phase 65 UAT item "replace `<details>`" is already true structurally. What remains is visual and structural reuse: a card-like header, a heading wrapper (WAI-ARIA accordion pattern), an `id` and a `badge` slot, so the Settings panels can use it. |
| Buttons | `.button--ghost` has a 1px `--stroke` border and a gold hover (the "Stay barely visible" button; gold hover also breaks the accent list of Phase 69). `.button--primary` has no rule in `styles.css`; the only rule is `.command-shell .button--primary` in `commandCenter.css`, so primary looks like default in the community layout. `.button--danger` is a flat dark red fill (`rgb(114 38 43 / 45%)`) with a hard-coded `#ffd9d9` label (the "Discard flat dark red" button). All of it lives in legacy `styles.css` with raw colors. | The five variants are redefined once, with tokens, in a new `src/components/action-control.css`; the three unfinished ones are finished. |
| Settings tab length | `SettingsSection` renders five stacked panels (Mods, Configuration, Credentials, Automation, Server record) after the workspace header, the details strip, notices, the job strip and the section navigation. Configuration alone is dozens of fields; Automation is the fourth panel. The Phase 69 deep link `?tab=settings#server-automation` exists, but nothing else shortens the page. | Collapsible Settings panels with a one-line live summary each, so every section is one tap from the top; open state remembered; staged changes and errors force their panel open. |
| Configuration filter | `ServerConfigurationPanel` has no search or filter. It splits Common versus Advanced (a `Disclosure`) and groups by target file and group name. `SearchField` and `FilterChipGroup` exist and are generic. | Search and a three-chip filter inside the panel, reusing both shared controls. |
| Layout shift on staging | `ConfigurationEntryField` renders the "Changed" badge, the Undo button and the Reset button in a `configuration-field__actions` row that exists only while `changed` or while a Reset is possible: staging adds a row and pushes every later field down. The credentials panel already reserves fixed slots (Phase 65-19); configuration does not. | The state controls move into a row whose height depends on the field's capability, never on its staging state. |
| Review dialog | `ChangeDiffItem` is a vertical card per change (name, Before pair, arrow, After pair, extra, Remove button), under an info `StatePanel` and a heading per group. `dialog--review` re-declares ten dialog shell rules (`kicker`, `h2`, `p`, `.dialog__body`, `.dialog__error`, `.dialog__actions`, ...) instead of only the width. | Shell duplication removed (one edge by construction); each change becomes one compact scannable row. |
| Leave dialog | `ConfirmDialog` renders dismiss, confirm, then `extraAction` in one wrapping row: Stay is `ghost` (border `--stroke`), Discard is flat `danger`, Review is `gold`. The dialog closes only by its buttons and Escape; a backdrop click does nothing. | One row with a deliberate hierarchy, the three restyled variants, and backdrop click equal to Stay. |
| Files panel layout | `.next-hosting-file-content` declares `grid-template-rows: auto minmax(0, 1fr) auto` for a container with at least seven children (folder heading, announcer, immediate note, toolbar, table or state, footer, drop overlay): the `1fr` row lands on the note or toolbar and the list ends up pushed to the bottom of a `min-height: 32rem` explorer. The folder heading is `{{folder}}` (`Server_Files_FolderHeading`), so it renders empty when the folder name is empty. `Server_Files_ImmediateNote` is a permanent subheader paragraph. New folder and Upload sit in the toolbar above the list; the upload dialog has two side-by-side pickers. All of it is legacy `next-hosting-*` CSS in `hosting.css` with raw hex colors (`#2b3748`, `#0b1119`, `#101722`, `#c4a95d`). | A single file-browser card with toolbar, list and footer in it; heading never empty; the note moves to the footer; the upload dialog gets a drop zone; the file CSS moves to a token-only sheet. |
| Credentials | Rows have reserved slots already (65-19). Alignment is by flex rows, so name, status, value and actions do not share columns across rows; after Rotate the one-time value appears where it appears and nothing scrolls or focuses it. | One grid for the row, a fixed action column, and a focus and scroll move onto the one-time value. |
| Weekday grid | `--utf-automation-day-min` is 5rem (80px). At 320px the usable width of a rule is about 224px, so `repeat(auto-fill, minmax(5rem, 1fr))` fits two columns. Each cell is a full checkbox row (box plus label). | A day chip of 3rem minimum, an explicit 4-column grid at 520px and below and 7 columns above, so the Phase 68 "four to a row at 320px" holds and the German short names still fit. |
| Review leftovers | `useDrawerFocus.ts` `cycleTab` returns early only when focus is neither on body nor inside the drawer, so after a blank click inside a modal opened over the open community menu (`document.activeElement === body`) Tab is captured and sent into the drawer behind the modal. `loadMediaAsset` (`siteImages.ts`) returns `Promise<MediaAsset \| undefined>`; its only caller adds `?? null`. In `en.json` `Pages_Events_Detail_Status_ConfirmedTeam` is "Confirmed member" (identical to `_ConfirmedMember`); in `de.json` both are "Bestätigtes Mitglied". `de.json` values contain "Modpack" 35 times, "Modpaket" 16 times, "Mod-Paket" 34 times, "Gelände" 43 times and "Karte" 33 times (value counts, regex over `de.json`, 2026-11-26); the Phase 69 navigation list already fixed "Mod-Pakete" and "Karten". `.workspace-details__refresh` holds a `ghost` ActionButton whose touch size is not asserted. | Each is a named task with a test (Review Leftovers section). |

## Decisions

| Id | Decision | Rationale |
|----|----------|-----------|
| D-01 | Native inputs stay; the browser's drawing goes. `CheckboxField` and `RadioGroupField` keep a real `<input type=checkbox\|radio>` (focusable, in the form, same `register` and `ref` behavior) that is overlaid on a drawn, `aria-hidden` mark. No `accent-color` anywhere in shared CSS. | Keeps every existing test, form library hook and assistive technology behavior; changes only what the eye sees. Rejects Fluent UI `Checkbox`, `Radio` and `Switch`: they would bring a second styling system and theme into primitives that are project-owned since Phase 61. |
| D-02 | Check semantics are fixed: a checkbox chooses items in a set or records a statement (weekdays, a list selection, "I understand", publish flags); a switch sets something on or off immediately in the draft (enable idle shutdown, a channel, a boolean configuration entry); a radio group chooses one of two to four alternatives. Mapping of known call sites is in the Control Contract. | The user's complaint was "simplistic checkboxes". Using the right control for the job is half of the fix; the drawn look is the other half. |
| D-03 | `RadioGroupField` renders choice cards by default and a segmented bar for label-only groups. The radio mark stays visible inside the card. | A bare radio circle is what the owner dislikes; a card with the mark inside is selectable by the whole row, scannable and still unmistakably a radio. |
| D-04 | New shared control `SwitchField` (`role="switch"` on a checkbox input) with the visible state word next to the label ("Enabled" and "Disabled", existing keys). | A switch announced as a switch, never color alone. |
| D-05 | The weekday group is a chip group built on `CheckboxField variant="chip"`: native checkboxes, drawn as 48px minimum chips, an explicit 4-column grid at 520px and below and 7 columns above. | Satisfies the Phase 68 contract (four per row at 320px) and gives the group a designed look. |
| D-06 | `SelectField` stays the only select. The closed control gets a designed surface (control border, overlay hover) and, behind `@supports (appearance: base-select)`, the popup is styled with tokens through `::picker(select)`. Other browsers keep the padded native select. A custom listbox stays rejected. | Progressive enhancement over a native element: no new interaction code, no accessibility regression, same fallback as today. |
| D-07 | `Disclosure` keeps its API and gains `headingLevel`, `id`, `badge` and `variant="panel"`. The header is a full-width bordered row. When `headingLevel` is set the button sits inside that heading (WAI-ARIA accordion pattern). | Same primitive for the inline "Advanced" case and for the Settings panels; no second disclosure implementation. |
| D-08 | The five button variants are redefined once, with tokens, in `src/components/action-control.css`: `gold` unchanged in look, `primary` a visible neutral fill in every layout, `ghost` a 3:1 border with a neutral hover (no gold hover), `danger` a tinted outline built from the state tokens, `glass` unchanged. The `button*` rules leave `styles.css` and `commandCenter.css`. | One hierarchy everywhere. Gold hover on ghost buttons contradicted the Phase 69 accent list; the flat red fill and the invisible Stay are the two button complaints. |
| D-09 | The Settings tab becomes a stack of five collapsible panels, each with a one-line live summary: Mods, Configuration, Credentials (only for `canManageSecrets`), Automation, Server record. Panels start collapsed; open ids are remembered for the browser session; a panel that holds staged changes, a validation error or the deep-link target opens by itself and is never closed by the app. | Cuts the scrolling at its cause. Rejected: sub-tabs (hide staged changes in unrendered panels and break focusing the first invalid field), a sticky jump bar (a second sticky bar costs 44px of a 568px viewport and the page stays as long). |
| D-10 | Configuration gets a search field and a three-chip filter. The filter state is component state, not a URL parameter. | The `urlParameters` contract of Phase 69 stays closed; a filter that matters across reloads is not a requirement. |
| D-11 | A configuration field's height and the position of every other element never depend on whether the field is staged. The Changed stamp, Undo and Reset live in the field's label row, which exists for every field that can ever show them. | The Phase 65 layout-shift complaint is a rule, asserted by a bounding-box test. |
| D-12 | The review dialog keeps `ConfirmDialog` and overrides only its width. A change is one compact row: name, before to after on one line, Remove. | Scales to dozens of staged changes; ends the shell duplication that caused the misalignment. |
| D-13 | The leave dialog is a documented variant of the shell: one row, Discard at the start edge, Stay and Review at the end edge, Review in gold. A backdrop click is Stay (new `closeOnBackdrop` prop, off by default, on for the leave and discard dialogs). | One row, a clear hierarchy, and the owner's requested backdrop behavior. |
| D-14 | The Files panel is rebuilt around one `file-browser` card; its CSS moves out of `hosting.css` into `src/components/server/files.css`, tokens only. The Persistent and Live switch becomes a segmented radio group. | The layout bug is structural (a grid template that does not match its children); patching one rule would leave raw colors and three disconnected controls. |
| D-15 | Credentials use one grid per row with a fixed action column; after a successful Rotate or Generate the one-time value block receives focus and is scrolled into view. | The owner's "not properly aligned" and "should be scrolled into view or focused". |
| D-16 | The Phase 69 review leftovers WR-01, WR-02, IN-06, IN-08 and the refresh touch target are in scope as named tasks with tests. | The CONTEXT lists them as recommended before the milestone ends. |
| D-17 | No new runtime dependency and no new dev dependency. `@playwright/test` 1.62.1 and `@axe-core/playwright` 4.13.0 stay pinned. | Supply-chain rule of Phase 61. |
| D-18 | Every changed screen keeps Phase 69 gates green: axe WCAG 2.0 to 2.2 AA, keyboard walk, 320 and 390px reflow, text spacing, German walk. Visual baselines are regenerated once after this phase (all images change because the button variants change). | The milestone-end plan in `70-CONTEXT.md` and `69-UAT.md`. |

Rejected, recorded so they are not reopened: Fluent UI Checkbox, Radio, Switch, Dropdown or Combobox; a custom listbox; Settings sub-tabs; a sticky Settings jump bar; replacing the native `<dialog>`; putting the configuration filter in the URL.

Exceptions recorded: E-04 the 20px check mark, 24px switch track, 16px switch thumb and 48px day chip are control dimensions declared as tokens (Spacing Scale). The control list closed by Phase 69 is amended to include `SwitchField` (in `FormFields.tsx`) and `FileBrowser`. The earlier exceptions (E-01 `PublicHero` scale, 1px borders, 2px focus ring, 16px inline icons) of Phase 69 stay.

## Spacing Scale

Inherited from Phase 61 without change (all multiples of 4, rem, 1rem = 16px). Control height `--utf-control-height` 40px, `--utf-control-height-touch` 44px at <= 800px.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Gap between mark and label inside a chip, inset of a switch thumb (4px), gap in a configuration label row |
| sm | 8px | Gap between check mark and label, between chips, between segmented segments, between dialog actions, between review rows |
| md | 16px | Choice card padding, disclosure header padding, review row padding block, field gap, file toolbar gap |
| lg | 24px | Settings panel gap and padding, file browser card padding above 520px |
| xl | 32px | `SelectField` end padding for the chevron (Phase 69) |
| 2xl | 48px | Not used |
| 3xl | 64px | Not used |

Additive tokens (the only new values; each is a multiple of 4, each is a control dimension, E-04):

| Token | Value | Usage |
|-------|-------|-------|
| `--utf-check-size` | 1.25rem (20px) | The drawn check box and radio circle |
| `--utf-switch-track-width` | 2.5rem (40px) | Switch track width |
| `--utf-switch-track-height` | 1.5rem (24px) | Switch track height; also the minimum target of the mark |
| `--utf-switch-thumb-size` | 1rem (16px) | Switch thumb |
| `--utf-day-chip-min` | 3rem (48px) | Minimum width of a weekday chip (renames `--utf-automation-day-min`) |
| `--utf-control-height-compact` | 2rem (32px) | `ActionButton size="compact"` and the configuration label row |
| `--utf-dropzone-min-height` | 8rem (128px) | The upload dialog drop zone |
| `--utf-review-name-min` | 10rem (160px) | The minimum width of the name column of a review row above 520px and of the credential action column |
| `--utf-choice-card-min` | 14rem (224px) | The minimum width of one choice card when a group of two or three lays out in a row |

Layout rules (all values are tokens; the style guard fails on a literal):
- Settings panel header min-height `--utf-control-height-touch` (44px) at every width (it is a full-row target), padding `--utf-space-md`.
- A touch target is at least 44px at <= 800px for every control in this phase: the check row, the switch row, the chip (44px high, 48px minimum wide), the segmented segments, the disclosure header, the review row Remove control and the file row actions. Icon-only controls are at least 24px and 44px at <= 800px (Phase 69 rule).
- Text rows wrap (`overflow-wrap: anywhere`); no ellipsis on a state, label or reason string (Phase 69 rule). The closed `SelectField` keeps `text-overflow: ellipsis` for the selected value only, as today, because the popup always shows the full text.

Breakpoints (constants): `520px` compact, `800px` narrow. Minimum supported width 320px with no horizontal page scroll.

Every screen touched here stays in the Phase 69 screen registry; nothing is removed from `serverScreens.ts`, and the entries gain the states below. - A drawn mark never replaces the input: every check, radio and switch is a real input reachable by Tab and operated by Space (switch and check) or Arrow keys (radio, segmented). - Accessible names: a switch is named by its label and exposes `aria-checked`; a chip's accessible name is its visible text; a card's name is its label with the help as description; the segmented bar and every radio group have a `legend`.
- Focus is visible on the mark, card, chip or segment at 2px with the gold-bright color and 3:1 against its surface, and is not covered by a sticky bar at 320 (`scroll-padding-block-end`).
- State is never carried by color alone: checked has a glyph, a switch has a thumb position plus the state word, a chip inverts luminance (not hue), a selected card has a filled dot, a segment inverts luminance, a changed field has the Changed badge text.
- `forced-colors: active` renders every mark with system colors (asserted by a Playwright run with `forcedColors: "active"` on S-07, one screenshot-free assertion that each mark has a visible border and the checked mark differs from the unchecked one).
- Reduced motion: no transition longer than 0.01ms (tokens already collapse).
- Disclosure panels: the header button has `aria-expanded` and `aria-controls`; the content region is `hidden` when closed (its controls are not tabbable); Enter and Space toggle; a collapsed panel's controls are never in the keyboard walk.

Responsive rules (320 and 390, EN and DE): no horizontal page scroll; the leave dialog row, the review rows, the file toolbar, the chip grid and the credential rows are measured, not pixel-compared; German labels ("Verwerfen und verlassen", "Änderungen prüfen", "Hier bleiben") are asserted to fit the stacked layout and the 521px one-row layout without clipping.
