<objective>
Make a Stop job finish on the seeded UAT stack (tracer-first): the UAT worker emulator claims commands over the real worker channel and acknowledges stop commands, so the lifecycle executor reaches verified release with the emulated Hetzner provider; then generalize the emulator to several seeded servers with per-scenario player profiles.

Phase 68's UAT must show an automatic stop complete (AUT-05, success criterion 4) and the already-failing seeded check 67-7 needs the same fix. The automation scenarios later need a zero-player and a fixed-player feed.

Output: the command-handling emulator, the player-profile enum and seeder map, a small report-builder helper, Api.Tests coverage including an executor-level stop completion.
</objective>

- `WorkerProtocolService` (around lines 570-601): a successful lifecycle command must report every assigned workload's expected state (Stopped for a stop, `ProcessId` null); a deployment without `PlacementSnapshot` (the seeded UAT deployments) has no expected workloads, so an empty list is valid. `WorkerCommandPayload.Workloads` lists the assignments (`WorkerWorkloadAssignment { ServiceIdentifier, ServiceOrdinal, ... }`).

- `EmulatedHetznerRuntimeProvider.ReleaseAsync` releases any `emu-server-` identifier with `IsVerifiedNonBillable: true`; the seeder gives running UAT deployments an `emu-server-` resource.
- The emulator today resolves one session for `UatFleetScenarioSeeder.MetricsScenarioTitle`, sends heartbeats and metrics from the client end of `UatLoopbackWebSocketPair`, and discards every received frame in `DrainAsync`.
- Test harness: `UatWorkerChannelEmulatorTests` uses `HostingTestStore`, `WorkerChannelTestHost` (`CreateHostAsync`), `GatedUpdateStream`, `RecordingLogger`, `SeedAsync` and `CreateEmulator`; `LifecycleJobExecutorCloudTests.CreateExecutor(store, provider, costs, catalog)` shows how to construct and run `LifecycleJobExecutor.ExecuteAsync(job)`.
