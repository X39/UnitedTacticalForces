    Extend `IHostingAuthorizationService` with a method named `GetServerViewAudienceAsync` that takes a read-only collection of server ids and a cancellation token defaulting to `default`, and returns a task of a read-only dictionary from server id to a read-only collection of user ids. Document it fully (summary, param, returns, remarks): the result has an entry for every requested id; an empty collection means nobody may view that server; each user id appears at most once per entry; the result reflects the database at the time of the call; the rule is identical to `HasServerPermission` with the view permission.

    Rule. A user is in the audience of server S exactly when the REST fleet rule is true for that user: the user is neither deleted nor banned (the same two flags `RebuildPrincipalAsync` filters on), and the user, directly or through any role, holds (a) a claim with the identifier `Claims.Administrative.All`, `Claims.Administrative.Server` or `Claims.Administrative.Hosting` and an empty value, where a null stored value counts as empty because every principal builder maps a null value to the empty string; or (b) a claim with the identifier `Claims.ResourceBased.Server.All` or `Claims.ResourceBased.Server.View` and a value equal to the default `ToString()` text of S. Mirror `ClaimsPrincipal.HasClaim`: compare identifiers case-insensitively by comparing the lower-cased stored identifier with the lower-case constants, and compare values ordinally. Deliberately ignore `ValueType` and `IsPrefix`, because the principal ignores them. Deliberately do not exclude archived servers, because an archive change must reach viewers so that their list drops the server.

    Implement it in `HostingAuthorizationService` with three `internal static` query builders that each take a queryable of users and always start by excluding deleted and banned users: one returns the ids of users who hold a global administrative claim directly or through a role; one returns grants (user id and server value) from the users' own claims whose value is in a string array of server values; one does the same for the claims of the users' roles. Create `ServerViewGrant` as an internal sealed record in its own file with a user id and a server value, fully documented, and use it as the element type of the two grant queries. The instance method returns an empty dictionary without querying when the input is empty; de-duplicates the input; maps each server's `ToString()` text back to its id; runs the three queries sequentially with `AsNoTracking` and the cancellation token; merges the results in memory into one distinct set per server (global users plus direct grants plus role grants); ignores any returned value that is not an exact key of the map, which fails closed; and returns an entry for every requested id. Add no cache, memoization or per-instance state of any kind: every call reads current claims (T-62-30).

    Provider neutrality. The builders run on SQLite in the tests and must translate for Npgsql in production. Use only navigation `Any`, `SelectMany`, `Where`, `Select`, `Contains` over a string array, `ToLower` and null or empty comparisons. If a projection shape does not translate on both providers, choose another shape; the translation test and the behavior tests are the acceptance bar, not the shape.
