## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| lifecycle change to every connected user | a server's activity must reach only users the claim rule allows |
| audience read failure to delivery | an error must never widen delivery |
| singleton notifier to scoped data and the interceptor graph | registration must stay free of construction cycles |

T-62-33 replaces the accepted disposition of T-62-14 (the earlier acceptance of disclosing server ids and timing to server-claim holders) with mitigation, per the product owner decision at UAT test 2.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-62-32 | Information Disclosure | notifier falling back to a broadcast when the audience read fails | high | mitigate | the audience failure path sends nothing for the batch, logs one warning, never broadcasts; the notifier file holds exactly one send call site and it uses the per-user path; test 4 proves it |
| T-62-33 | Information Disclosure | delivery of a server's id and change timing to users who may not view that server (G-62-2, supersedes the acceptance in T-62-14) | high | mitigate | per-recipient delivery from a publish-time audience that equals the REST view rule; the tracer and the rule matrix prove user, role, administrative, bare-claim, other-server, banned and deleted users |
