<objective>
Close the subscribe half of gap G-62-2: register every fleet socket on a path addressed to the authenticated user, `game-servers/fleet/{userId}`, instead of the single shared `game-servers/fleet` path.

Purpose: UAT test 2 rejected the accepted disclosure of server ids and change timing to holders of any server-section claim (the product owner decision: "we must deliver messages in accordance with the corresponding claims"). The update stream service is path-addressed only and keeps no recipient identity, so claim-scoped delivery without touching it needs one path per recipient. This plan creates the recipient addressing and proves a client can neither pick nor spoof it. Plans 62-14 (audience rule) and 62-15 (publisher cutover) complete the closure; plan 62-15 Task 1 is the end-to-end tracer.

Output: the `ForUser` path builder, the controller fleet branch that registers it, and the migrated and extended gate tests.
</objective>

Gap source: `62-UAT.md` gap G-62-2 (diagnosed in `.planning/debug/fleet-signal-claim-scoping.md`) and review finding WR-01. Product owner decision: messages are delivered claim-scoped per server. This plan follows the diagnosed approach (per-user paths, publish-time audience, fail closed, no change to `UpdateStreamService` or `sources/WebSocketContracts`). The decision is recorded as D-17 by plan 62-16.

Verified facts. `UpdateStreamService.SendUpdateAsync` selects subscribers with `path.StartsWith(requestedPath)`, a raw string prefix, so a registered string that is a prefix of another registered string would receive that other path's sends. The per-user path has a fixed length (the 19 characters of `game-servers/fleet/` plus the 36 characters of a D-format GUID), so no per-user path is a prefix of another. `UpdateStreamController.SubscribeAsync` already calls `User.TryGetUserId` and passes that id as the `userId` argument of `ResolveSubscriptionPathAsync`; the fleet branch already requires exactly two segments, so an extra segment already resolves to null. `CanAccessServerSection` is a deliberate superset of the per-server view rule (it also admits `crt:sv` and bare `sv:view` or `sv`); it stays unchanged because it only decides who may open the socket. The shared prefix string constant named `Fleet` in `FleetChangeStreamPaths` is still used by the publisher (`FleetChangeNotifier`) and by `FleetSignalTracerTests`; this plan leaves its value and those two users untouched, and plan 62-15 removes it.

Architecture boundary: this plan changes neither `sources/Api/Services/UpdateStreamService` nor `sources/WebSocketContracts` nor any React or Blazor source; a guard in the acceptance criteria enforces it.

Decisions implemented: D-13 (amended by the product owner at UAT G-62-2: the premise that no per-viewer filtering is needed is withdrawn), D-14 (process-local stream, unchanged), D-15 (no polling fallback, unchanged), D-17 (claim-scoped delivery, owner decision at UAT test 2; written into `62-CONTEXT.md` by plan 62-16).
