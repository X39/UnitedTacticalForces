Justification for the global keep-alive (AGENTS.md cross-cutting rule): the fleet stream is explicitly requested by D-13 to D-16 and must not churn through a reverse proxy that closes idle connections. The deployed nginx configuration proxies `/api/` with the upgrade headers and sets no read timeout, and nginx defaults to 60 seconds (an assumed default, not verified in this environment); a 25 second ping keeps the connection alive without a proxy change. The setting is one option on the existing `UseWebSockets` call, it also applies to the existing event update streams where an extra ping is harmless, and it does not widen the API surface. The fallback if a reviewer rejects a global setting is a proxy read timeout for the update-stream location. The proxy behavior itself is a manual-only verification (idle longer than 60 seconds behind nginx).

Verified facts: the tracer notifier already serializes sends with one reader loop, coalesces with `CoalesceWindow` (default 250 milliseconds, settable internally for tests), swallows delivery failures with a structured warning and exposes `Start` and `Stop` through `IHostedService`; the tracer controller already contains `ResolveSubscriptionPathAsync` and the fleet branch; `UpdateStreamService.SendUpdateAsync` drops a socket whose send throws; `DefaultHttpContext.WebSockets` reads the `IHttpWebSocketFeature` feature, so a stub feature (with `IsWebSocketRequest` true and an `AcceptAsync` returning a fake `WebSocket`) lets a test drive `SubscribeAsync` to registration without a server; `HostingTestData.Principal` builds principals from claim type and value pairs and `UpdateStreamController` takes a logger, `IUpdateStreamService` and a `DatabaseContext`. <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client-chosen subscription path to the prefix-matching registry | the registered string decides which senders reach the socket |
| any server-section claim holder to server activity | the signal reveals ids and timing, not data |
| slow or failing subscriber to the delivery loop | one socket can stall or fail a shared sender |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-62-11 | Information Disclosure | subscription gate for game-servers/fleet | high | mitigate | claim matrix tests 1 and 2 prove only the listed principals pass; every other principal is forbidden |
| T-62-12 | Tampering | path-prefix confusion through longer, differently cased or slash-padded paths | high | mitigate | exactly two segments are required and only the canonical string is registered; test 3 and 4 prove it for extra segments, casing and padding |
| T-62-13 | Denial of Service | slow or failing subscriber stalling or ending the notifier loop | high | mitigate | writers never await delivery; one loop serializes sends; failures are logged and the loop continues; notifier tests 3 and 4 prove it; the keep-alive ping lets the transport detect dead peers |
| T-62-14 | Information Disclosure | server ids and timing visible to holders of any server-section claim | low | accept | D-13 and research choice 4: GUIDs only, authenticated viewers with a server claim only, no status, owner, cost or secret in the payload; documented as accepted; dropping the id from the message is the escape hatch |
| T-62-SC | Tampering | npm/pip/cargo installs | high | accept | no package installs in this plan |
</threat_model>
