## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser user -> `/servers` UI | User can click controls, change selected server/owner/plan state, and submit reasons. |
| `/servers` UI -> repository | UI must not talk to generated request builders or raw HTTP directly. |
| Repository result -> Razor display | UI renders only safe model fields and must fail closed on redaction-blocked results. |
| Approver UI -> API | Approve/deny actions are convenience controls; API authorization remains the authority. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-36-14 | Elevation of Privilege | `ContinueApprovedPolicyActionAsync` | mitigate | Enable only when displayed action kind, scope key, server/session/dry-run id, owner ids, decision/request id, and expiration match current state; API revalidates. |
| T-36-15 | Elevation of Privilege | Approver controls | mitigate | Show approve/deny controls only for users with approver authority signal, but rely on API `[Authorize(Claims.Administrative.Server)]` for enforcement. |
| T-36-16 | Information Disclosure | `ServersPolicyGateApproval` Razor region | mitigate | Render safe repository models only; boundary tests forbid generated DTOs, `AdditionalData`, raw JSON, headers, bearer values, provider/Steam/worker secrets, and exception bodies. |
| T-36-17 | Repudiation | Denied/expired/mismatch UI states | mitigate | Use exact UI-SPEC copy so denied, expired, missing, mismatch, and redaction-blocked states are explicit workflow states with safe next action copy. |
| T-36-18 | Tampering | Policy review action | mitigate | `Review policy decision` calls non-mutating policy-review endpoint; no provider mutation/provisioning/teardown is represented as successful in Phase 36. |
| T-36-SC | Tampering | npm/pip/cargo/NuGet installs | accept | No package installs are planned; use existing Fluent UI and Kiota packages. |
</threat_model>
