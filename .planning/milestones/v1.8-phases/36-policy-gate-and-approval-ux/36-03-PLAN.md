## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| WebApp repository -> API | Repository sends policy review and approval commands over authenticated API calls. |
| Generated/transport DTO -> safe model | Transport fields are allowlisted and redaction-guarded before Razor can consume them. |
| Razor -> repository | UI receives repository method signatures only, not generated builders or raw HTTP. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-36-10 | Information Disclosure | `CloudPolicyApprovalModels` / `CloudWorkflowResultMapper` | mitigate | Allowlist display fields and run display text through `CloudWorkflowRedactionGuard`; forbid `AdditionalData`, raw JSON, headers, bearer values, and secret markers. |
| T-36-11 | Tampering | `ReviewArma3CloudDryRunPolicyAsync` | mitigate | Pass only typed `acknowledgedDecisionId` and `approvalRequestId` to server-side gate validation; do not synthesize or cache authority in the client. |
| T-36-12 | Elevation of Privilege | `ApprovePolicyRequestAsync` / `DenyPolicyRequestAsync` | mitigate | Repository only sends commands; API authorization remains `[Authorize(Claims.Administrative.Server)]`; UI hiding controls is not authority. |
| T-36-13 | Tampering | Generated-client gap handling | mitigate | Do not hand-edit `UtfApi`; if generated builders are absent, use repository-local Kiota `RequestInformation` helper behind `IGameServerRepository`. |
| T-36-SC | Tampering | npm/pip/cargo/NuGet installs | accept | No package installs are planned; existing Kiota abstractions are already in the project. |
</threat_model>
