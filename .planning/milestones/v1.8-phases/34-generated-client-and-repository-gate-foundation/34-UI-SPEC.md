## Phase Interaction Contract

### Route And Scope

| Surface | Contract |
|---------|----------|
| `/servers` | Primary owner/operator surface. Render normalized cloud workflow results for the selected server below the server grid and inside the existing detail workflow. |
| `/servers/cloud` | Admin provider/fleet console only. Phase 34 may preserve admin result patterns there, but normal owner creation and follow-up states stay in `/servers`. |
| Generated client boundary | UI code consumes hand-written repository facade methods only. Do not inject generated request builders into Razor components and do not create raw browser HTTP bridges for cloud workflow actions. |
| Generated files | Treat `sources/WebApp/UtfApi/**` as generated. Do not hand-edit these files to satisfy UI behavior. |
| Result visibility | Pages render typed, allowlisted result view models or repository projections. Do not render raw generated DTOs, `AdditionalData`, JSON payload dumps, exception bodies, headers, or request/response payloads. |
| UAT boundary | Manual/browser/authenticated UAT, live Hetzner, Steam, Arma, provider mutation, provisioning, teardown, and Phase 30 evidence remain deferred. Do not claim them in UI copy or evidence text. |

### Result State Taxonomy

Every cloud workflow action exposed in `/servers` must resolve to one of these user-facing states. These are visual states, not transport exceptions.

| State | Visual Treatment | Required Content | Blocking Rule |
|-------|------------------|------------------|---------------|
| Loading | `FluentProgress` with body text inside the relevant `detail-section` | Action noun and selected server id/title | Disable only the action in progress and conflicting actions for the same server. |
| Success | `FluentMessageBar` with success intent plus compact `dl.meta-grid` summary | Action name, relevant ids, status, timestamp, next safe action | Never include raw provider response, secret-bearing payload, worker secret, or token reference. |
| Policy allow | `status-badge status-success` plus summary row | Decision id, action kind, scope, projected cost, expiration if present | Continue actions can be enabled only when identity, scope, owner, and expiration still match. |
| Policy warning | `status-badge status-info` plus warning message bar | Decision id, reason code, projected cost, acknowledgement next step | Continue disabled until a matching warning acknowledgement path exists. |
| Approval required | `status-badge status-warning` plus message bar | Approval request id, decision id, approver next step, expiration | Billable action disabled until a matching approval is approved and unexpired. |
| Denied | `status-badge status-danger` plus message bar | Decision id, reason code, sanitized explanation, safe next step | Billable action remains disabled. Do not show raw policy input snapshots. |
| Validation blocked | `FluentMessageBar` warning plus inline list | Field or precondition names, sanitized reasons, refresh/regenerate next step | Continue disabled until validation is resolved by repository-backed state. |
| Failure | `FluentMessageBar` error plus optional retry command | Sanitized failure summary, failure category when allowlisted, correlation/action id if available | Retry enabled only when repository result marks the action retryable. |
| Empty | `guided-empty` or compact empty state inside the same panel | Missing prerequisite and next non-mutating step | Do not link users to `/servers/cloud` as the normal creation path. |

### Result Surfaces

| Area | Contract |
|------|----------|
| Guided cloud panel | Keep Phase 33's step rail and form surface. Add normalized result feedback below the active form actions, above readiness summary. |
| Selected server details | Use the existing selected-server `detail-section` and `dl.meta-grid` for cloud runtime, policy, cost, audit, and lifecycle summaries. |
| Primary focal point | The selected-server cloud result panel below the grid, with the latest policy/result message drawing first attention. |
| Server grid row actions | Row actions may show the next repository-backed action, but detailed success/failure/policy content must appear in the selected-server details, not squeezed into the table. |
| Summary density | Show 6 to 10 high-signal rows per result. Use progressive disclosure by selected section, not nested cards. |
| Audit context | Show audit id, kind, actor id if allowlisted, timestamp, sanitized summary, and related server/session/assignment ids. Do not show raw audit payload JSON. |
| Policy continuation | Preserve decision id, approval request id, action kind, scope key, session id, dry-run plan id, billing account id, billing assignment id, and expiration when available. These are visible because they are needed to verify follow-up action identity. |

### Allowed Display Fields

Only these categories are allowed in user-visible cloud workflow result summaries.

| Category | Allowed Fields |
|----------|----------------|
| Identity | Server id/title, session id, dry-run plan id, resource inventory id, lifecycle job id, policy decision id, approval request id, audit record id, billing account id, billing assignment id. |
| Provider/resource labels | Provider identifier, resource kind, display name, provider resource id when already part of inventory visibility, location, datacenter, network zone, server type, image name, public endpoint host/port. |
| Status | Runtime state, cloud resource state, dry-run plan status, lifecycle job status, worker status label, bootstrap status label, retryable action labels, cleanup-needed/orphan-risk flags. |
| Cost | Currency, estimated cost, provider allocated cost, adjusted cost, hourly/monthly labels, billable resource count, cleanup-needed billable count, freshness, confidence, reconciliation counts. |
| Policy | Decision, action kind, decision reason code, scope key, threshold labels, current/projected cost, required next step, expiration, sanitized failure summary/details. |
| Timing | Created, updated, evaluated, expires, completed, deleted, last heartbeat, last progress, projected timestamps. |
| Sanitized diagnostics | Sanitized failure summary, sanitized failure details, sanitized diagnostic summary, sanitized reason, validation summary, high-level validation fields. |

### Forbidden Display Fields

The UI must never render these fields, even when they exist in repository models or generated DTOs.

| Forbidden Field Type | Contract |
|----------------------|----------|
| Provider secrets | Provider tokens, token values, token references that can identify a secret storage key, authorization headers, bearer tokens, provider raw credentials. |
| Steam secrets | Steam username, Steam password, Steam API key, Steam guard/session values, DepotDownloader credentials. |
| Worker secrets | Worker credentials, bootstrap credential secrets, worker hashes, worker registration secrets, private keys, SSH private material. |
| Raw payloads | Raw request/response bodies, raw generated DTO dumps, raw `AdditionalData`, raw exception bodies, raw audit payload JSON, raw input snapshot JSON, raw risk details JSON, raw validation details JSON, raw planned operations JSON, raw resource details JSON. |
| Secret-bearing evidence | Screenshots, logs, evidence notes, or downloadable files that include any forbidden field above. |

### Copy Boundary Rules

- Use "billing owner", "cost responsibility", "assignment", "internal attribution", "policy decision", "approval request", "provider teardown", and "billable resources".
- Do not use "payment", "invoice", "checkout", "charge", "customer billing", or "taxes" for Phase 34 UI.
- Do not use "live UAT passed", "Hetzner verified live", "Steam verified live", or "Arma runtime verified live".
- Do not describe runtime stop or runtime cleanup as cost stop. Provider teardown is the cost-stop action in later phases.
- Do not expose `/servers/cloud` as the normal owner workflow path.

## Layout Contract

| Area | Contract |
|------|----------|
| Page shell | Reuse `.servers-page`: flex column, 16px padding, 16px page gap. |
| Header | Reuse `.servers-toolbar`: left title/counts, right actions. Keep result/status summaries out of the page title area. |
| Main workspace | Keep `FluentDataGrid` first. Result panels appear under the grid or in selected-server detail sections. |
| Result panel | Use `section.detail-section` for one framed tool surface. Do not place cards inside cards. |
| Result summary | Use `dl.meta-grid` for ids, status, owner, policy, cost, and timestamps. Values must wrap with `overflow-wrap: anywhere`. |
| Result actions | Use a single `div.guided-actions` or existing `.runtime-actions` row. On mobile, actions stack full width. |
| Validation list | Use `.guided-validation-list` for multiple validation blockers. Use inline `.field-validation` for field-specific errors. |
| Data tables | Use existing `FluentDataGrid` or `.data-table` for repeated rows. Keep action cells compact and icon-backed. |
| Mobile | At max-width 860px, grids collapse to one column, action buttons become full width where needed, and touch targets are at least 44px for icon-only actions and checkboxes. |

## Component Contract

| Need | Component |
|------|-----------|
| Primary non-destructive command | `FluentButton` with `Appearance.Accent` and a Fluent icon. |
| Secondary command | Default `FluentButton` with a Fluent icon. |
| Refresh/retry | `FluentButton` with `ArrowSyncCircle`; label must be `Refresh cloud status` or `Retry cloud action`. |
| Policy continuation | `FluentButton` with explicit label such as `Acknowledge warning`, `Request approval`, or `Continue approved action`; never `Next`. |
| Destructive future action | `FluentButton` with `Delete` icon, danger styling if available, explicit confirmation copy before provider teardown. Phase 34 introduces no destructive action. |
| Loading | `FluentStack` plus `FluentProgress` with action-specific loading copy. |
| Page-level error | `FluentMessageBar` with error intent and sanitized copy. |
| Validation warning | `FluentMessageBar` with warning intent plus inline list. |
| Status | Existing `.status-badge` classes: neutral, info, warning, success, danger. |
| Structured result | Existing `dl.meta-grid`; do not render raw JSON. |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline label/control spacing, status badge icon gap |
| sm | 8px | Compact element spacing, row action gaps, result row gaps, validation list spacing |
| md | 16px | Default page gap, toolbar gap, result panel gap, page padding |
| lg | 24px | Empty state padding and major result group separation |
| xl | 32px | Wide desktop split-panel gap only when the page has enough width |
| 2xl | 48px | Major workflow break between server grid and selected result panels when both are visible |
| 3xl | 64px | Reserved for page-level separation; do not use inside result panels |

Exceptions: icon-only touch targets and checkboxes must be at least 44px high/wide on mobile; desktop Fluent and native controls may keep the existing 32px minimum height; status badges may keep compact density but new padding must use 4px/8px values.

## Typography

Use exactly these four sizes and two weights for new or touched Phase 34 UI. Do not introduce viewport-scaled font sizes or new rem-based sizes in touched route CSS.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 13px | 600 | 1.3 |
| Heading | 15px | 600 | 1.25 |
| Display | 22px | 600 | 1.2 |

Usage:

| Role | Usage |
|------|-------|
| Body | Result values, table cells, validation copy, sanitized failure details, empty-state body. |
| Label | Field labels, metadata labels, table headers, status captions, muted counts. |
| Heading | Section titles such as `Cloud action result`, `Policy gate`, `Cost visibility`, and `Audit context`. |
| Display | Page-level `Game servers` title only; do not use display size inside result panels. |

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Refresh cloud status |
| Success state heading | Cloud action finished |
| Success state body | The repository returned a redacted result. Review the status, owner, policy, cost, and next safe action below. |
| Policy warning heading | Policy warning requires acknowledgement |
| Approval required heading | Approval is required before this action can continue |
| Denied heading | Policy denied this action |
| Validation heading | Cloud action cannot continue |
| Empty state heading | No cloud workflow result |
| Empty state body | Select an eligible Arma 3 server and complete cloud setup before cloud workflow results are available. |
| Error state | Cloud action result could not be loaded. Refresh cloud status and try again. |
| Redaction failure state | Cloud result was blocked because it contained a forbidden field. The result was not displayed. |
| Deferred UAT note | Live Hetzner, Steam, Arma, authenticated browser UAT, provider mutation, provisioning, teardown, and Phase 30 evidence are deferred. |
| Destructive confirmation | None for Phase 34. Do not add provider teardown, local server delete, or provisioning confirmation in this phase. |

Button labels must be verb plus noun. Allowed Phase 34 labels include `Refresh cloud status`, `Retry cloud action`, `Review policy decision`, `Request approval`, `Acknowledge warning`, `Refresh cost snapshot`, and `View audit context`. Do not use vague labels such as `Next`, `Submit`, `Go`, `OK`, or `Launch`.

## Accessibility And Responsive Contract

| Concern | Contract |
|---------|----------|
| Keyboard | Every result action, retry command, field, and policy continuation command must be reachable by keyboard in DOM order matching the visual flow. |
| Focus | Use visible Fluent/default focus rings; do not remove outlines. |
| Labels | Every input/select/toggle must have a visible label. Placeholder text is not a label. |
| Errors | Field errors appear adjacent to the field; action errors appear in `FluentMessageBar`; repeated validation blockers use `.guided-validation-list`. |
| Touch | Icon-only actions and checkboxes in touched result surfaces must have at least 44px touch targets on mobile and `Title`/tooltip text for icon-only commands. |
| Text fit | Button labels wrap or full-width on mobile; no clipped labels inside toolbars, result actions, or grid action cells. |
| Contrast | Status badges must keep readable foreground on light and dark Fluent themes; never encode blocking state by color alone. |
| Screen readers | Message bars must contain the actionable text, not only color/status icons. Result summaries use semantic `dl` pairs. |

## Security And Redaction Contract

| Gate | Contract |
|------|----------|
| Repository projection | Repository facade result types must project only allowlisted fields needed by UI. Generated DTOs with sensitive or raw fields cannot be bound directly to Razor output. |
| Redaction failure | If a result contains a forbidden field, show `Cloud result was blocked because it contained a forbidden field. The result was not displayed.` and log only sanitized diagnostic context server-side. |
| Evidence | Any automated/component evidence for Phase 34 must label live Hetzner, Steam, Arma, authenticated browser UAT, provider mutation, provisioning, teardown, and Phase 30 evidence as deferred. |
| Raw JSON | UI may show parsed, allowlisted assumptions or validation labels only. Never show raw JSON text from `InputSnapshotJson`, `RiskDetailsJson`, `ValidationDetailsJson`, `PlannedOperationsJson`, `DetailsJson`, or `AdditionalData`. |
| Secrets in names | Do not render token reference values, worker hash-like identifiers, bearer strings, private key fragments, credential fingerprints, or source hashes as user-visible labels. |
