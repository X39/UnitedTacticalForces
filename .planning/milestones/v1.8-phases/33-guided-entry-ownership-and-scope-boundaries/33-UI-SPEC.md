## Phase Interaction Contract

### Route And Scope

| Surface | Contract |
|---------|----------|
| `/servers` | Primary owner/operator creation surface. Add the guided cloud entry and planning-input flow here. |
| `/servers/cloud` | Admin console only. Keep provider status, metadata sync, reconciliation, global sessions, resources, policies, and fleet cleanup risk here. Do not route normal creation through this page. |
| Navigation | Keep the existing `GameServers` nav item as the normal entry. The `Cloud operations` nav item remains visible only to users passing the existing server-admin check. |
| Provider mutation | Phase 33 controls must not create, provision, tear down, or mutate provider resources. |
| UAT | Manual, authenticated, live Hetzner, Steam, and Arma UAT remain deferred and must be labeled as deferred evidence if referenced. |

### Guided Flow Shape

Use one dense, server-oriented flow inside `/servers`, not a marketing wizard page.

| Step | UI Contract | Blocking Rule |
|------|-------------|---------------|
| 1. Choose server | User selects an eligible existing Arma 3 server from the grid or opens `Create cloud server`. Existing server rows remain dense and sortable/scannable. | Continue disabled until exactly one eligible Arma 3 server is selected or a valid new Arma 3 server draft exists. |
| 2. Choose owner | User selects an active billing owner and sees the selected billing account id plus active assignment id in the same section. | Continue disabled when no active owner exists, assignment is missing, owner is inactive, or owner is outside the user's authorization scope. |
| 3. Runtime basics | User selects modpack/runtime basics needed for Arma 3 cloud planning. If a value is intentionally deferred to later runtime setup, show it as an explicit non-blocking assumption row, not hidden state. | Required runtime fields block continue; optional assumptions must be visible before continue. |
| 4. Cloud inputs | User enters or accepts defaults for size/server type, location, datacenter if present, image if present, storage GiB, game port, Steam query port, Steam traffic port, RCON port or disabled RCON, SSH exposure, and administrative CIDR. | Continue disabled until client-side validation passes; server-side validation failures must render inline after submit. |
| 5. Ready for dry run | User lands on a compact readiness summary with selected server, owner, assignment, planning inputs, and validation state. | The CTA can move to dry-run planning only after all Phase 33 fields are complete. It must not create billable resources. |

### Layout Contract

| Area | Contract |
|------|----------|
| Page shell | Reuse `.servers-page`: flex column, 16px padding, 16px page gap. |
| Header | Use existing `.servers-toolbar`: left title/counts, right actions. Add `Create cloud server` as an accent action only for authorized users. |
| Main workspace | Keep the server grid first. Put the guided cloud panel below the grid or in the selected-server detail area; do not create a separate landing page. |
| Primary focal point | The selected guided cloud panel state below the server grid, with the active step and blocking validation drawing first attention. |
| Guided panel | Use a bordered `section.detail-section` style frame because it is a tool surface. Do not nest cards inside it. |
| Internal step layout | Use a two-column grid at desktop: left column for step list/status, right column for active form. Collapse to one column below 860px. |
| Form grid | Use `grid-template-columns: repeat(auto-fit, minmax(180px, 1fr))` with 8px gaps. Buttons align to the bottom row on desktop and full width on mobile. |
| Readiness summary | Use a `dl.meta-grid` for selected server, owner, assignment, controller, size, location, storage, ports, SSH/CIDR, modpack, and runtime basics. |
| Tables | Keep existing FluentDataGrid for server selection. Do not copy the admin `/servers/cloud` summary strip or tabbed inventory tables into the owner flow. |
| Mobile | At max-width 860px, toolbar, form grid, detail grid, and guided panel collapse to one column; action buttons become full-width only where labels still fit. |

### Component Contract

| Need | Component |
|------|-----------|
| Primary commands | `FluentButton` with `Appearance.Accent` and Fluent icon. |
| Secondary commands | Default `FluentButton` with icon. |
| Refresh | Existing `ArrowSyncCircle` icon button pattern. |
| Create | Existing `New` icon pattern. |
| Select/open | Existing `Open` icon pattern. |
| Validation and errors | `FluentMessageBar` for page-level failures plus inline validation text next to the field. |
| Loading | Existing `FluentStack` plus `FluentProgress` pattern. |
| Status | Existing `.status-badge` classes: neutral, info, warning, success, danger. |
| Form controls | Prefer Fluent controls when practical; otherwise use the existing route-scoped native `input`/`select` styling with Fluent tokens. |

### Validation Contract

| Field | Client-Side Contract |
|-------|----------------------|
| Title | Required for new server, max 120 characters, trim whitespace. |
| Controller | Must be Arma 3 for this flow. Other controllers can remain in generic server creation but cannot enter cloud planning. |
| Billing owner | Required active account plus active assignment; show both display name and ids. |
| Server type/size | Required if no recommended default is available; otherwise show the recommended value as selected. |
| Location/datacenter/image | Accept recommended values when available; otherwise require user choice. |
| Storage | Integer GiB, minimum 1, display `GiB` in label or suffix. |
| Ports | Integer 1-65535; game, Steam query, Steam traffic, and RCON ports must not collide when RCON is enabled. |
| RCON | Binary toggle or checkbox. When disabled, RCON port is null and port validation excludes it. |
| SSH exposure | Binary toggle or checkbox. When enabled, administrative CIDR is required. |
| Administrative CIDR | Required for SSH or administrative exposure; validate CIDR-shaped input before submit and show server-side validation if stricter checks fail. |
| Modpack/runtime basics | Required when the planner needs them; deferred runtime assumptions must render in the readiness summary. |

### Boundary Copy Rules

- Do not say payment, invoice, checkout, charge, taxes, or customer billing in Phase 33 UI.
- Use "billing owner", "cost responsibility", "assignment", and "internal attribution".
- Do not say "launch now" or "deploy now" in Phase 33 because provider mutation is out of scope.
- Do not describe `/servers/cloud` as the normal creation path.
- Do not display provider tokens, Steam credentials, worker credentials, worker hashes, authorization headers, bearer tokens, raw bootstrap secrets, or raw secret-bearing payloads.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline label/control spacing, status badge icon gap |
| sm | 8px | Compact element spacing, row action gaps, form label gaps, tab gaps |
| md | 16px | Default page gap, toolbar gap, section gap, page padding |
| lg | 24px | Empty state padding, guided panel inner major group gap |
| xl | 32px | Wide desktop split-panel gap only when the page has enough width |
| 2xl | 48px | Major workflow break between server grid and guided panel when both are visible |
| 3xl | 64px | Reserved for page-level separation; do not use inside the guided tool surface |

Exceptions: icon-only touch targets must be at least 44px high/wide on mobile; desktop Fluent and native controls may keep the existing 32px minimum height; status badges may keep existing compact visual density but new padding should use 4px/8px values.

## Typography

Use exactly these four sizes and two weights for new Phase 33 UI. Do not introduce viewport-scaled font sizes.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 13px | 600 | 1.3 |
| Heading | 15px | 600 | 1.25 |
| Display | 22px | 600 | 1.2 |

Usage:

| Role | Usage |
|------|-------|
| Body | Form values, table cells, validation copy, readiness rows. |
| Label | Field labels, muted counts, table header text, summary labels. |
| Heading | Section titles such as `Cloud setup`, `Owner`, and `Planning inputs`. |
| Display | Page-level `Game servers` title only; do not use display size inside compact panels. |

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` / `var(--neutral-fill-layer-rest, #ffffff)` | Page background, data grid background, guided panel background, form fields |
| Secondary (30%) | `#f7f9fb` / `var(--neutral-fill-secondary-rest, #f7f9fb)` | Table hover/selected rows, subtle readiness summaries, empty state background, inactive step rail |
| Accent (10%) | `#2563eb` | Primary CTA, active step indicator, active tab/selection border, focused selected planning field, selected-plan link |
| Destructive | `#b42318` | Destructive actions only; none are introduced by Phase 33 |

Accent reserved for: `Create cloud server`, `Continue to dry run`, active guided step, selected cloud planning panel border, focus state for the currently edited planning field, and links to the selected server/plan. Do not use accent for every button, every badge, decoration, or page background.

Status colors:

| Status | Value | Usage |
|--------|-------|-------|
| Neutral | `#475467` | Missing/not started/not applicable. |
| Info | `#2563eb` | Draft, selected, dry-run-ready, recommended values. |
| Warning | `#b54708` | Validation warnings, inactive owner, stale/missing recommended metadata. |
| Success | `#027a48` | Eligible server, active owner, valid field group. |
| Danger | `#b42318` | Blocking validation, unauthorized scope, secret-redaction failure, any existing destructive action. |

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Continue to dry run |
| Secondary CTA | Create cloud server |
| Existing-server CTA | Plan cloud hosting |
| Empty state heading | No eligible Arma 3 servers |
| Empty state body | Create an Arma 3 server with an active billing owner before cloud planning can continue. |
| No owner state | No active billing owner is available for this server. Select or create an active owner before continuing. |
| Validation summary | Cloud planning cannot continue. Fix the highlighted fields and refresh owner eligibility. |
| Error state | Cloud setup could not be loaded. Refresh the server list and try again. |
| Unauthorized state | Cloud planning is not available for this server with your current permissions. |
| Deferred UAT note | Live Hetzner, Steam, Arma, and authenticated browser UAT are deferred. |
| Destructive confirmation | None for Phase 33. Do not add provider teardown, local server delete, or provisioning confirmation in this phase. |

Button labels must be verb plus noun. Use `Refresh`, `Create cloud server`, `Plan cloud hosting`, `Continue to dry run`, `Create owner`, and `Cancel setup`. Do not use vague labels such as `Next`, `Submit`, `Go`, or `Launch`.

## Accessibility And Responsive Contract

| Concern | Contract |
|---------|----------|
| Keyboard | Every step, field, and CTA must be reachable by keyboard in DOM order matching the visual flow. |
| Focus | Use visible Fluent/default focus rings; do not remove outlines. |
| Labels | Every input/select/toggle must have a visible label. Placeholder text is not a label. |
| Errors | Field errors appear adjacent to the field and are also summarized by `FluentMessageBar` when submit is attempted. |
| Touch | Icon-only actions in the guided flow must have `Title`/tooltip text and at least 44px touch targets on mobile. |
| Text fit | Button labels wrap or full-width on mobile; no clipped labels inside toolbars or form actions. |
| Contrast | Status badges must keep readable foreground on light and dark Fluent themes; never encode blocking state by color alone. |
