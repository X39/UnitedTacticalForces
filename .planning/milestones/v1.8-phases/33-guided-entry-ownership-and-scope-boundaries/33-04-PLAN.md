<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User input to client validation | Title, owner, modpack, runtime basics, provider option names, ports, storage, SSH, and CIDR are entered in the browser. |
| Client validation to API readiness | Browser validation improves feedback but server readiness remains authoritative. |
| Owner workflow to admin console | Normal creation must remain on /servers and not expose /servers/cloud provider/fleet controls. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-33-13 | Elevation of Privilege | `/servers` guided controls | mitigate | Use `MeService` only for display; all create, owner, and readiness calls go through Plan 02 API authorization. |
| T-33-14 | Tampering | Client-side validation | mitigate | Keep `Continue to dry run` disabled for local invalid state and always call server readiness before showing ready state. |
| T-33-15 | Information Disclosure | `/servers` owner workflow | mitigate | Render only repository allowlisted DTO fields; do not show `/servers/cloud` provider/fleet controls, raw metadata, or secret-bearing values. |
| T-33-16 | Repudiation | Owner choice UI | mitigate | Owner assignment uses Plan 02 `AssignGuidedCloudEntryBillingOwnerAsync`, which delegates to audited billing ownership service behavior. |
| T-33-17 | Spoofing | Readiness state | mitigate | Readiness summary is shown only from `GuidedCloudEntryReadinessDto.IsReadyForDryRun`; local client state alone cannot claim ready. |
| T-33-SC | Tampering | Package supply chain | accept | No package-manager install is planned; use existing Fluent UI and project CSS. |
</threat_model>
