<objective>
Implement cloud worker runtime cleanup so durable lifecycle jobs can stop owned Arma processes and remove worker-local
runtime files without provider teardown.
</objective>

<tasks>
<task id="16-02-01" type="execute">
<action>
Add `POST game-servers/{gameServerId}/cloud-runtime/cleanup` that queues a cloud runtime cleanup lifecycle job only
when the runtime projection says cleanup is safe and applicable.
</action>
<acceptance_criteria>
- Unauthenticated users are rejected by existing controller auth behavior.
- Missing server returns `404`.
- Unsafe or inapplicable cleanup returns `403`.
- Accepted cleanup creates a durable lifecycle job with billing owner attribution.
</acceptance_criteria>
</task>

<task id="16-02-02" type="execute">
<action>
Handle `ELifecycleJobKind.Delete` in `Arma3LifecycleJobExecutor` as cloud runtime cleanup.
</action>
<acceptance_criteria>
- Cleanup stops a persisted or pid-file Arma process when present.
- Cleanup uploads remaining runtime log lines before file removal.
- Cleanup removes only the computed game-server runtime directory under the configured install root.
- Cleanup reports stopped runtime status and marks the lifecycle job succeeded.
</acceptance_criteria>
</task>

<task id="16-02-03" type="execute">
<action>
Add worker and API tests proving cleanup does not mutate provider deletion state and handles no-pid/stale-state cases.
</action>
<acceptance_criteria>
- Worker cleanup tests verify stop, log upload, file deletion, and redaction.
- API cleanup tests verify persisted job creation, action gating, and session/resource state preservation.
- Existing local worker compatibility tests still pass.
</acceptance_criteria>
</task>
</tasks>
