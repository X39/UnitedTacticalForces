<objective>
Add a server-scoped cloud runtime status projection and surface it in the existing server operations dashboard.
</objective>

<tasks>
<task id="16-01-01" type="execute">
<action>
Add `CloudRuntimeStatusDto` and a `GET game-servers/{gameServerId}/cloud-runtime` endpoint that composes existing
session, worker, lifecycle job, and log state.
</action>
<acceptance_criteria>
- Admins and users with the server resource scope can read runtime readiness for only that server.
- DTO includes endpoint, worker status, last heartbeat, current job, progress, recent log timestamp, and sanitized last
  failure.
- DTO does not expose provider tokens, worker credentials, credential hashes, Steam secrets, or secret-bearing command
  lines.
</acceptance_criteria>
</task>

<task id="16-01-02" type="execute">
<action>
Compute `CanRetry` and `CanCleanup` in the API from persisted lifecycle/cloud state.
</action>
<acceptance_criteria>
- Retry is visible only for retry-pending jobs or failed jobs with remaining attempts.
- Cleanup is visible only for an active provisioned cloud session with a registered worker and no conflicting active job.
- Deleted provider sessions/resources do not produce runtime cleanup affordances.
</acceptance_criteria>
</task>

<task id="16-01-03" type="execute">
<action>
Extend `IGameServerRepository`, `GameServerRepositoryImpl`, WebApp runtime models, and `/servers` selected-server
details to display cloud runtime readiness and action flags.
</action>
<acceptance_criteria>
- Selected server details show endpoint, worker heartbeat, current job/progress, recent log timestamp, and last
  sanitized failure.
- Cleanup and retry affordances are shown only from API-computed flags.
- Server-owner views can see runtime status without requiring global cloud-admin permissions.
</acceptance_criteria>
</task>
</tasks>
