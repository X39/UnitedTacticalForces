<objective>
Add worker-side Arma 3 runtime primitives for launch command construction, detached process start, stop, observation,
runtime log collection, and persisted worker runtime state.
</objective>

<tasks>
<task id="15-01-01" type="execute">
<action>
Add `Arma3RuntimeState`, `Arma3RuntimeStateStore`, `IArma3ProcessRunner`, and a process-runner implementation. Persist
process id, runtime log path, last log offset, last known status, exit code, and update timestamp under the worker state
directory.
</action>
<acceptance_criteria>
- Runtime state survives worker process restarts.
- State files do not contain Steam passwords, worker credentials, bearer headers, or full secret command lines.
- Tests can fake process start/stop/observe behavior without launching native processes.
</acceptance_criteria>
</task>

<task id="15-01-02" type="execute">
<action>
Build Arma 3 launch specs from the Phase 14 claim snapshot using the local controller-compatible argument set and the
worker path layout.
</action>
<acceptance_criteria>
- Launch spec includes `arma3server_x64`, `-pid`, `-cfg`, `-config`, `-bepath`, `-profiles`, `-port`, optional
  `-serverMod`, and selected lowercased workshop mod paths.
- Masked sensitive host configuration values are skipped.
- Additional raw host mods can be appended without sending raw command lines to the API.
</acceptance_criteria>
</task>

<task id="15-01-03" type="execute">
<action>
Add worker-side runtime log collection that uploads newly appended runtime log lines through existing worker log
reports and advances the persisted log offset.
</action>
<acceptance_criteria>
- Start/stop/collect-log flows can upload Arma process output from the detached runtime log file.
- Repeated collection avoids duplicating already uploaded log content when the state offset is present.
</acceptance_criteria>
</task>
</tasks>
