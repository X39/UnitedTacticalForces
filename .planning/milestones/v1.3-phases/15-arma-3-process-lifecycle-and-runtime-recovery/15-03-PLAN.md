<objective>
Wire `Start`, `Stop`, `Restart`, and `CollectLogs` lifecycle jobs to the worker runtime primitives and report durable
success/failure/status/log outcomes.
</objective>

<tasks>
<task id="15-03-01" type="execute">
<action>
Extend `Arma3LifecycleJobExecutor` to execute `Start`, `Stop`, `Restart`, and `CollectLogs` jobs using the runtime
state store, launch builder, process runner, log collector, and runtime-status endpoint.
</action>
<acceptance_criteria>
- `Start` reports `Starting`, launches the detached process, persists runtime state, verifies observation, reports
  `Running`, and succeeds.
- `Stop` reports `Stopping`, gracefully stops the persisted pid if present, uploads runtime logs, reports `Stopped`, and
  succeeds.
- `Restart` stops any observed process, uploads logs, starts a new process, and reports final `Running`.
- `CollectLogs` uploads available runtime logs without changing unrelated lifecycle state.
</acceptance_criteria>
</task>

<task id="15-03-02" type="execute">
<action>
Update `CloudWorkerRuntime` heartbeat creation to observe local runtime state on startup and include optional runtime
status in the heartbeat payload.
</action>
<acceptance_criteria>
- Worker restart can report an already-running persisted pid as `Running`.
- Missing or exited pid is reported as `Stopped` and does not cause claim failure.
- Runtime recovery reports remain credential-authenticated through the existing heartbeat route.
</acceptance_criteria>
</task>

<task id="15-03-03" type="execute">
<action>
Add focused tests for start/stop/restart/log/recovery behavior and redaction.
</action>
<acceptance_criteria>
- Tests verify launch argument construction and no secret command-line upload.
- Tests verify runtime status API mutation, lifetime events, update-stream broadcasts, and persisted logs.
- Tests verify worker restart heartbeat recovery from persisted runtime state.
</acceptance_criteria>
</task>
</tasks>
