<objective>
Create the cloud worker agent foundation that can start from bootstrap configuration, register or resume with a
local credential store, heartbeat, and request a bounded job claim without containing Arma 3 runtime execution yet.
</objective>

<tasks>

<read_first>

- sources/Api/Controllers/LifecycleWorkersController.cs
- sources/Api/DTO/CloudWorkerRegistrationDto.cs
</read_first>
<action>
Add a new `sources/CloudWorker` console project targeting `net9.0` and reference only `sources/Contract`. Implement
bootstrap configuration parsing for the Phase 11 `/etc/united-tactical-forces/bootstrap.json` shape with API base URL,
worker id, bootstrap credential, cloud session id, game server id, provider identifier, and expiry timestamp.
</action>
<acceptance_criteria>
- The project is included in `X39.UnitedTacticalForces.slnx`.
- The worker can load bootstrap config from an explicit path or default location.
- The worker project does not reference `sources/Api`.
- No raw credential values are written to console output by normal startup flow.
</acceptance_criteria>
</task>

<task id="13-01-02" type="execute">
<read_first>
- sources/Api/Controllers/LifecycleWorkersController.cs
- sources/Api/DTO/Payloads/CloudWorkerRegistrationPayload.cs
- sources/Api/DTO/Payloads/CloudWorkerHeartbeatPayload.cs
</read_first>
<action>
Implement `CloudWorkerApiClient` and `CloudWorkerRuntime` so the worker registers with a bootstrap bearer credential
when no local worker credential exists, persists the returned worker credential locally, resumes when the credential
store exists, sends heartbeat/capability metadata, and calls the Phase 13 claim endpoint once.
</action>
<acceptance_criteria>
- Registration reads the one raw worker credential only from the `X-UTF-Worker-Credential` response header.
- Resume mode uses the local credential store and does not require the bootstrap credential again.
- Worker credential file is created under a configurable state directory with restrictive file attributes where the
  platform supports them.
- The worker exits cleanly when there is no claimable job.
</acceptance_criteria>
</task>
</tasks>
