<objective>
Add credential-authenticated worker report endpoints for progress, logs, success, retry, and failure, then cover
authorization boundaries and redaction with focused tests.
</objective>

<tasks>
<task id="13-03-01" type="execute">
<read_first>
- sources/Api/Services/GameServerLifecycle/LifecycleJobQueueService.cs
- sources/Api/Services/GameServerLifecycle/LifecycleFailureReasonSanitizer.cs
- sources/Api/Data/Hosting/GameServerLog.cs
</read_first>
<action>
Extend `CloudWorkerDispatchService` with report methods for lease/heartbeat progress, persisted logs, success, and
failure/retry. Progress should refresh the worker heartbeat and job lease/update timestamp. Logs should persist
sanitized `GameServerLog` rows scoped to the claimed job's game server. Success and failure should delegate terminal
state transitions to `LifecycleJobQueueService`.
</action>
<acceptance_criteria>
- Reports are accepted only for the authenticated worker assigned to a running job.
- Progress and log reports do not create noisy audit records.
- Success, retry, and failure reuse the existing queue service audit behavior.
- Worker-supplied text is sanitized before persistence.
</acceptance_criteria>
</task>

<task id="13-03-02" type="execute">
<read_first>
- sources/Api/Controllers/LifecycleWorkersController.cs
- sources/Api/DTO/Payloads
</read_first>
<action>
Expose report endpoints under `lifecycle-workers/cloud/{workerId}/jobs/{jobId}` for `progress`, `logs`, `succeed`,
and `fail`. Use the existing bearer credential extraction, return `Unauthorized` for bad worker credentials,
`NotFound` for wrong job/scope, and `NoContent` for accepted reports.
</action>
<acceptance_criteria>
- Controller methods do not expose supplied credential values or detailed credential failure reasons.
- Wrong worker/job/scope reports cannot mutate job state or logs.
- Failure payload can request retry with a retry delay, but persisted state still respects attempt budget.
</acceptance_criteria>
</task>
