<objective>
Add worker-facing authenticated claim endpoints and bounded execution snapshots, with cloud worker claims constrained
to the worker's registered cloud session and game server while preserving local worker claiming.
</objective>

<tasks>
<task id="13-02-01" type="execute">
<read_first>
- sources/Api/Services/GameServerLifecycle/LifecycleJobQueueService.cs
- sources/Api/Data/Hosting/LifecycleWorker.cs
- sources/Api/Data/Hosting/CloudGameServerSession.cs
- tests/Api.Tests/GameServerLifecycle/LifecycleJobQueueServiceTests.cs
</read_first>
<action>
Update `ILifecycleJobQueueService` and `LifecycleJobQueueService` with a cloud-aware claim method. Local claims should
continue through the existing method but skip jobs whose game server has an undeleted cloud session. Cloud claims must
authenticate an enabled cloud worker and only claim queued/retry jobs for that worker's own `CloudSessionFk` and
`GameServerFk`.
</action>
<acceptance_criteria>
- Existing local queue tests pass.
- A cloud worker cannot claim jobs for another cloud session or game server.
- A local worker does not claim a cloud-session game server job when a cloud session exists.
- Attempt count, lease fields, assigned worker id, and worker `TimeStampLastClaimedJob` are still updated atomically.
</acceptance_criteria>
</task>

<action>
Add safe cloud worker snapshot DTOs for a claim response. Include lifecycle job status/attempt/lease metadata, game
server id/title/controller/status/version/mod-pack selection, cloud endpoint and placement, and active non-sensitive

</action>

</acceptance_criteria>
</task>
