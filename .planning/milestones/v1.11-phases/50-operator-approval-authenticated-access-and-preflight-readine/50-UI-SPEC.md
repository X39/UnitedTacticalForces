## Visual Hierarchy

Primary screen focal point: the selected server's `Live preflight` panel inside `/servers`.

The first visual priority is the current preflight classification and required blocker rows. The second priority is
the action strip containing `Record preflight approval`, `Refresh preflight evidence`, `Record admin access`, and
`Record owner access`. Provider mutation controls must remain visually separate and unavailable until Phase 51.

Use the existing dense operational layout: compact status rows, definition-list metadata, restrained cards/panels,
and Fluent `MessageBar` feedback. Do not add a landing-page, hero section, decorative imagery, nested cards, or
new broad visual theme.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 13px | 400 | 1.4 |
| Body | 14px | 400 | 1.5 |
| Heading | 16px | 600 | 1.3 |
| Display | 22px | 600 | 1.2 |

Use display text only for the `/servers` page title. The `Live preflight` panel uses Heading size, not display type.
Evidence row labels use Label size and values use Body size. Do not introduce additional font sizes or weights.

---

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #ffffff | Main page and panel surfaces |
| Secondary (30%) | #f5f5f5 | Evidence row backgrounds, metadata groups, inactive surface bands |
| Accent (10%) | #2563eb | Primary readiness CTA, active focus ring, selected workflow step |
| Destructive | #b42318 | Provider teardown or deletion actions only; Phase 50 must not add these actions |

Accent reserved for: `Record preflight approval`, verified readiness emphasis, active focus ring, and selected workflow
step. It must not be applied to every button or every status row.

Use Fluent `MessageIntent.Success`, `MessageIntent.Warning`, and `MessageIntent.Error` for semantic state. Warning
state is appropriate for missing operator input; error state is reserved for failed load/recording operations.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Record preflight approval |
| Secondary CTA | Refresh preflight evidence |
| Access CTA | Record admin access |
| Owner access CTA | Record owner access |
| Empty state heading | Select a server to review live preflight readiness |
| Empty state body | Choose an Arma 3 server with an active billing owner before recording approval or access evidence. |
| Error state | Live preflight evidence could not be loaded. Refresh cloud status and try again. |
| Blocked state | Live execution remains blocked until approval, access, provider, owner, dry-run, policy, reconciliation, and redaction evidence are complete. |
| Destructive confirmation | No destructive actions belong in Phase 50. Provider teardown confirmation is deferred to Phase 53. |

Copy must name the missing evidence category rather than using generic failure text. Do not use `Submit`, `OK`,
`Save`, or `Cancel` for Phase 50 actions.

---

## Interaction Contract

| Interaction | Contract |
|-------------|----------|
| Record approval | Opens or uses the existing compact approval workflow and records safe reference fields only. |
| Refresh readiness | Recomputes Phase 40 readiness and updates evidence rows without treating readiness as authorization by itself. |
| Record admin access | Records route, role/scope, timestamp, and safe visible outcome for `/servers/cloud`; no session material. |
| Record owner access | Records route, role/scope, timestamp, and safe visible outcome for `/servers`; no session material. |
| Missing prerequisites | Keep actions disabled or show a warning message that names the missing selected server, billing owner, approval, or dry-run requirement. |
| Ready classification | Show `ready-for-live-execution` only when all Phase 50 gates pass; provisioning remains a Phase 51 action. |

All icon-only controls need an accessible label or visible text. Prefer existing Fluent icons: checkmark for approval,
sync for refresh, shield-checkmark for administrator access, and person-available for owner access.
