<objective>
Add worker-facing registration and heartbeat APIs that consume bootstrap credentials and persist cloud worker health/capabilities.
</objective>

<tasks>
<task id="12-02-01" type="execute">
<read_first>
- sources/Api/Services/CloudWorkerBootstrap/ICloudWorkerBootstrapService.cs
- sources/Api/Services/CloudWorkerBootstrap/CloudWorkerBootstrapService.cs
- sources/Api/Services/GameServerLifecycle/LifecycleFailureReasonSanitizer.cs
- sources/Api/Data/Hosting/LifecycleWorker.cs
</read_first>
<action>
Create `ICloudWorkerRegistrationService` and `CloudWorkerRegistrationService`. Implement registration by consuming the Phase 11 bootstrap credential, generating a high-entropy worker auth credential, storing only its SHA-256 hash on `LifecycleWorker`, linking the worker to cloud session/game server/billing/provider metadata, persisting capability fields, and appending a sanitized `CloudWorkerRegistered` audit event.
</action>
<acceptance_criteria>
- Registration succeeds exactly once for a valid bootstrap worker id and bootstrap bearer credential.
- Wrong, missing, expired, revoked, or already consumed bootstrap credentials fail without echoing supplied material.
- Registration links `LifecycleWorker.CloudSessionFk`, `GameServerFk`, `BillingAccountFk`, and `BillingAssignmentFk` from the consumed bootstrap row.
- Audit records include worker id, cloud session id, and game server id, but no raw bootstrap or worker auth credential.
</acceptance_criteria>
</task>

<task id="12-02-02" type="execute">
<read_first>
- sources/Api/Controllers/LifecycleWorkersController.cs
- sources/Api/DTO/Payloads
- sources/Api/DTO
</read_first>
<action>
Add worker-facing endpoints under `lifecycle-workers/cloud/{workerId}`. `POST register` should accept capability payload fields only, read the bootstrap credential from `Authorization: Bearer ...`, and return a safe `CloudWorkerRegistrationDto` body while placing the one raw worker auth credential in a response header. `POST heartbeat` should read the worker auth credential from `Authorization: Bearer ...`, accept capability heartbeat payload fields, and return a safe `LifecycleWorkerDto`.
</action>
<acceptance_criteria>
- No request or response DTO property contains raw credential material.
- The registration response body serializes without credential or hash fields.
- The raw worker auth credential is available only to the worker caller through a response header and is never persisted raw.
- Controller responses use `Unauthorized`, `BadRequest`, or `NotFound` without credential-specific detail.
</acceptance_criteria>
</task>

- Capability reports include supported game controller identifiers, operating system, architecture, region/placement hints, and one-session shape.

- Targeted tests cover registration, heartbeat, credential rejection, DTO redaction, and restart persistence.
</acceptance_criteria>
