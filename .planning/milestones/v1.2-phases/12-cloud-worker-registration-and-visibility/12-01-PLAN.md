<objective>
Extend the durable lifecycle worker model so local and cloud workers can be distinguished and projected safely.
</objective>

<tasks>
<task id="12-01-01" type="execute">
<read_first>
- sources/Api/Data/Hosting/LifecycleWorker.cs
- sources/Api/Data/Hosting/CloudGameServerSession.cs
- sources/Api/Data/ApiDbContext.cs
- sources/Contract/GameServer/ELifecycleWorkerStatus.cs
</read_first>
<action>
Add `ELifecycleWorkerKind` under `sources/Contract/GameServer` with `Local` and `Cloud`. Extend `LifecycleWorker` with `Kind`, nullable `CloudSessionFk`, `GameServerFk`, `BillingAccountFk`, `BillingAssignmentFk`, `ProviderIdentifier`, `LocationName`, `NetworkZone`, `OperatingSystem`, `Architecture`, `SupportedControllerIdentifiersJson`, `IsSingleSession`, `CredentialHash`, and `TimeStampLastCapabilityReport`. Configure restrictive optional relationships to `CloudGameServerSession`, `GameServer`, `BillingAccount`, and `GameServerBillingAssignment`, plus indexes for `Kind`, `CloudSessionFk`, `GameServerFk`, and `TimeStampLastHeartbeat`.
</action>
<acceptance_criteria>
- Existing local workers can persist without cloud session or credential fields.
- Cloud worker fields survive a new `ApiDbContext` instance over the same database.
- `CredentialHash` is the only persisted worker-auth material and is not exposed through any DTO.
- Migration output adds the fields, relationships, and indexes without dropping existing worker data.
</acceptance_criteria>
</task>
