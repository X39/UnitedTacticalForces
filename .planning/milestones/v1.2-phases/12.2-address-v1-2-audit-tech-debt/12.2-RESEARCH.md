# Phase 12.2 Research: Address v1.2 Audit Tech Debt

## Research Complete

Phase 12.2 is an operational hardening and evidence phase. The milestone audit is not reporting missing backend
requirements after Phase 12.1; it is blocked from `passed` by four residual items:

- temporary raw WebApp HTTP paths for cloud admin and server cloud status;
- missing authenticated Aspire/browser UAT with representative cloud session data;
- dependency and build warning/advisory disposition;
- missing controlled live Hetzner create/delete UAT, or an explicit production gate that prevents unverified live use.

## Current State

- `.planning/v1.2-MILESTONE-AUDIT.md` records `status: tech_debt` with no open requirements, integration, flow, or
  Nyquist gaps.
- `sources/WebApp/UtfApi/kiota-lock.json` points to `https://localhost:7072/openapi/v1.json`.
- `kiota` is installed globally as `microsoft.openapi.kiota` 1.29.0, while the checked-in lock file was generated with
  Kiota 1.26.0.
- The current generated client under `sources/WebApp/UtfApi` exposes only events, game servers, mod packs, resource
  claims, roles, terrains, update streams, users, and wiki. It has no `CloudInventory`, `HetznerProvider`,
  `BillingAccounts`, cloud DTO, lifecycle job, or hosting audit generated surface.
- `CloudAdminRepositoryImpl` is the audit-relevant raw bridge for Hetzner provider status, metadata reads/sync,
  cloud sessions, session statuses, dry-run plans/details, resources, estimates, provisioning, and teardown.
- `GameServerRepositoryImpl.GetCloudSessionStatusesAsync` is the server-owner raw cloud status bridge for
  `game-servers/{gameServerId}/cloud-status`.
- `GameServerRepositoryImpl` also has earlier raw lifecycle/billing methods. These are adjacent tech debt but not the
  cloud audit item unless Kiota regeneration makes replacing them cheap and low-risk.

## Authenticated UAT Approach

Use Aspire for the local stack:

`dotnet run --project sources/AppHost/AppHost.csproj`

The WebApp reads `https://localhost:7072/` by default and the AppHost composes PostgreSQL, API, and WebApp. UAT needs
representative data for an administrator and a server owner:

- at least one active game server with billing owner;
- Hetzner provider configuration/status rows with no token value exposed;
- metadata sync status and sample metadata rows;
- dry-run plan, cost estimate, cloud session, inventory resources, bootstrap credential state, and cloud worker
  heartbeat/capability state;
- cleanup-needed/orphan-candidate and retryable action states if available without live cost exposure.

If Steam/Discord authentication cannot be completed locally, the execution phase should document the precise blocker
and produce an operator-run UAT script/checklist rather than marking browser UAT passed.

## Live Hetzner UAT Approach

The phase goal is to remove audit tech debt without accidentally creating unmanaged costs. A safe plan should require
one of these outcomes:

- controlled live UAT is run with explicit operator-provided Hetzner token reference, region, server type, and cleanup
  budget; provisioning and teardown both succeed; provider resources are verified deleted; or
- the application adds/document a production gate that keeps live provider mutation disabled until controlled UAT is
  executed, with a clear runbook and audit artifact explaining the deferral.

The plan must not ask autonomous execution to create real Hetzner resources without operator approval.

## Planning Implications

- Plan 1 should own Kiota regeneration and raw cloud bridge removal.
- Plan 2 should own warning/advisory fixes or a warning disposition ledger with build evidence.
- Plan 3 should own authenticated UAT plus live-provider UAT gating/runbook and the milestone audit refresh.
- Final verification should rerun the v1.2 milestone audit and expect `status: passed`; if any item remains deferred,
  the plan must state why it is no longer milestone tech debt or why the milestone remains intentionally gated.
