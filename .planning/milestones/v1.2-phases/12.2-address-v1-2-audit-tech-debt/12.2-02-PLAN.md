<objective>
Turn the milestone's dependency/build warning debt into either fixed warnings/advisories or an explicit committed
disposition, with no unreviewed security advisory left hidden in normal build output.
</objective>

<threat_model>
- Threat: package upgrades change authentication, OpenAPI, Kiota, Aspire, telemetry, or provider behavior outside the
  audit-debt scope. Mitigation: stay on `net9.0`, prefer compatible package-family upgrades, and run targeted API/WebApp
  tests after each high-risk package group.
- Threat: warning suppression hides defects that affect authorization or secret redaction. Mitigation: suppress only
  documented legacy warning classes with rationale; fix nullable/security-sensitive warnings in touched cloud/auth code.
- Threat: dependency advisory output is treated as static. Mitigation: use fresh `dotnet list package --vulnerable
  --include-transitive` output during execution and record the exact result date.
</threat_model>
