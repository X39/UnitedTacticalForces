<objective>
Issue and consume short-lived scoped bootstrap credentials through a server-side service.
</objective>

<tasks>

<action>
Create `ICloudWorkerBootstrapService`, `CloudWorkerBootstrapService`, and internal result type `CloudWorkerBootstrapBundle`. Implement `CreateBootstrapAsync(long cloudSessionId, User actor, CancellationToken cancellationToken)` to load a non-deleted cloud session, generate a worker id formatted as `cloud-{cloudSessionId}-{32 lowercase hex chars}`, generate a high-entropy base64url credential, store only a SHA-256 hash, set an expiry from `Constants.Configuration.CloudWorkers.BootstrapCredentialLifetimeMinutes` defaulting to 15 minutes, and append a sanitized `CloudWorkerBootstrapCredentialIssued` audit record with worker id and session id only.
</action>
<acceptance_criteria>
- Returned `CloudWorkerBootstrapBundle` contains `WorkerId`, raw `BootstrapCredential`, `CloudSessionId`, `GameServerId`, `ProviderIdentifier`, `ApiBaseUrl`, `ExpiresAt`, and rendered `UserData`.
- Persisted `CloudWorkerBootstrapCredential.CredentialHash` does not equal the raw credential.
- Audit `Summary` and `Details` do not contain the raw credential and do not include token/password/secret/authorization vocabulary.
- Creating a second active credential for the same cloud session revokes or supersedes the prior active credential deterministically.
</acceptance_criteria>
</task>

<action>
Add `ConsumeBootstrapAsync(string workerId, string bootstrapCredential, CancellationToken cancellationToken)` to validate scope, expiry, revocation, and one-time use. On success, set `TimeStampConsumed` and return the persisted credential identity. On failure, return `null` or throw a specific non-secret `InvalidOperationException` without echoing supplied credential material.
</action>
<acceptance_criteria>
- Correct worker id and raw credential consume exactly once before expiry.
- Wrong credential, wrong worker id, expired credential, revoked credential, or already consumed credential cannot be consumed.
- Failure messages and persisted failure state do not contain raw credential text.
</acceptance_criteria>
</task>
