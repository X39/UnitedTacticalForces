<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Administrator to API | Admin-supplied template definitions cross into durable state. |
| API service to audit log | Template mutation reason and metadata become durable audit records. |
| API entity to DTO | Template data becomes browser-visible through allowed projections. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-41-04 | Elevation of Privilege | Template controller | mitigate | Require `Claims.Administrative.Server` on every endpoint and resolve database actor server-side for mutations. |
| T-41-05 | Tampering | Template version service | mitigate | Validate ranges and always create a new current row for update/disable while preserving previous rows. |
| T-41-06 | Repudiation | Template mutation audit | mitigate | Append `HostingAuditRecord` with actor id, event kind, summary, details, template id, and version in the mutation transaction. |
| T-41-07 | Information Disclosure | DTO/payload/audit text | mitigate | Use allowlisted DTO fields, bounded payload fields, and audit sanitizer before persistence. |
| T-41-SC | Tampering | Package supply chain | accept | No package-manager or SDK additions are planned. |
</threat_model>
