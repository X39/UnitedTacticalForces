### Phase 29: Operator Gate Preparation And Live Plan Approval

**Goal:** Prepare the approved live UAT environment, authenticated browser roles, provider configuration, metadata, dry-run plan, billing owner, and approval record before any real provider mutation.

**Requirements:** OPS-03

**Success Criteria:**

1. UAT evidence templates exist for approval, preflight, live execution, cleanup, redaction checks, and final pass/fail classification.
2. Aspire/API/WebApp access is documented for an authenticated administrator and server owner without storing session cookies, auth headers, or bearer material.
3. Hetzner provider status is enabled and verified through a token reference only; metadata sync is fresh and recorded with source timestamp.
4. A test game server has exactly one active billing owner, a valid Arma 3 dry-run plan, a current cost estimate, and policy/reconciliation status recorded before provisioning.
5. The approval record captures approver, approved project, resource shape, budget ceiling, lifetime, cleanup window, game server, billing account, and plan identifiers before any live mutation.

### Phase 30: Live Provisioning Runtime And Cleanup Evidence

**Goal:** Execute the approved live Hetzner and Steam/Arma flow end to end, prove browser/API visibility and redaction, then tear down all billable resources with final provider-side count `0`.
**Current status:** Deferred by operator instruction until the whole change request is implemented across all milestones. Do not execute live provider mutation without a fresh approval record and completed Phase 29 preflight evidence.

**Requirements:** OPS-02, OPS-04, EVID-01, EVID-02, EVID-03

**Success Criteria:**

1. The approved dry-run plan is provisioned once, with session ID, provider IDs, public endpoint, billing owner, cost source, and audit records captured without credential material.
2. The cloud worker registers or its bootstrap failure is captured with safe diagnostics; live Steam/Arma install/configure/start/stop/log collection is executed or explicitly blocked by documented unmet operator/environment preconditions.
3. Authenticated admin and server-owner views expose lifecycle state, worker health, endpoint, logs, cost, policy, reconciliation, billing owner, and audit history without exposing provider, Steam, worker, or auth secrets.
4. Teardown deletes provider-side billable resources or records retry/manual cleanup steps; OPS-02 cannot pass until final provider-side billable resource count is `0`.
5. Failure evidence preserves ownership, cleanup risk, and next action while avoiding duplicate provisioning attempts or hidden billable resources.

**Goal:** Fix only UAT/evidence blockers that directly affect v1.7 completion or cleanup safety, then verify and audit the milestone without expanding CR-0001 scope.

**Requirements:** RELY-24, RELY-25

**Success Criteria:**

1. Every UAT-discovered blocker has severity, owner impact, cost/cleanup impact, secret-safety impact, fix/defer decision, and evidence link recorded.
