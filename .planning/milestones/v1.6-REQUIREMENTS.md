# Requirements: United Tactical Forces - Cloud Game Server Orchestration

**Defined:** 2026-06-18
**Milestone:** v1.6 Invoice Reconciliation And Cost Adjustments
**Core Value:** Authorized users can operate game servers through durable, auditable lifecycle jobs with a clearly assigned billing owner, even when the API process restarts.

## v1.6 Requirements

Requirements for the invoice reconciliation and cost adjustment milestone. Each requirement maps to exactly one roadmap phase.

### Cost Reconciliation

- [x] **COST-13**: Administrator can import Hetzner invoice/consumption export data into durable, redacted billing import records.
- [x] **COST-14**: Administrator can record explicit adjusted cost corrections after provider reconciliation.
- [x] **COST-20**: System can normalize provider billing rows into provider, resource, period, amount, currency, and source metadata facts.
- [x] **COST-21**: System can match provider billing rows to cloud resources, sessions, billing assignments, and cost snapshots with confidence and review status.
- [x] **COST-22**: Administrator can review unresolved rows and estimated-versus-provider discrepancies before accepting corrections.
- [x] **COST-23**: Reconciled and adjusted values preserve original estimated snapshots and raw import evidence.

### Visibility

- [x] **VIS-19**: Administrator can inspect import batches, parse diagnostics, matches, discrepancies, unresolved rows, and adjustments.
- [x] **VIS-20**: Server owner can see estimated, reconciled, and adjusted cost labels/history for scopes they are allowed to inspect.
- [x] **VIS-21**: Billing reconciliation DTOs are available through generated WebApp API clients and repository facades.

### Reliability And Safety

- [x] **RELY-21**: Imports, matching, review decisions, and adjustments are restart-safe and idempotent.
- [x] **RELY-22**: Billing import, review, and adjustment actions are authorization-sensitive and audited.
- [x] **RELY-23**: Tests cover CSV fixtures, duplicate imports, matching confidence, ownership transfers, adjustment immutability, visibility projection, and secret/raw-row redaction.

## Future Requirements

Deferred to later milestones. Tracked but not in the current roadmap.

### Operational UAT

- **OPS-02**: Authenticated Aspire/API browser UAT covers live cloud provisioning, metadata sync, row selection, server-admin navigation, runtime install/start/stop, cleanup, and final provider billable resource count `0`; this remains operator-gated until credentials, budget, provider approval, and cleanup window are supplied.

### Advanced Runtime And Cloud Shape

- **RUN-01**: Worker can report dynamic cloud capacity and capabilities for placement.
- **RUN-02**: Cloud workers can optionally support Arma 3 headless clients.
- **RUN-03**: Multiple game sessions can safely run on one worker when billing, ports, storage, and cleanup are proven.
- **RUN-04**: Arma 3 runtime can be packaged with Docker or Compose where networking and BattlEye constraints allow it.

### Billing Extensions

- **COST-24**: System can ingest provider billing data through a direct Hetzner billing API adapter if an official supported endpoint becomes available.
- **COST-25**: Administrator can export adjusted internal attribution summaries for treasurer or reporting workflows.

## Out of Scope

Explicitly excluded from v1.6.

| Feature | Reason |
|---------|--------|
| Payment processing, payment-provider billing, customer invoicing, taxes, or legal invoice generation | CR-0001 defines billing as internal attribution, not payment collection. |
| Claiming UTF adjusted attribution as an official provider invoice or user balance due | v1.6 reconciles internal attribution against provider-derived evidence but does not create payable customer invoices. |
| Direct Hetzner billing API integration | Current official docs found during research describe invoice/consumption CSV access rather than a documented Cloud billing API. |
| Automatic acceptance of low-confidence or ambiguous billing matches | Wrong owner attribution is worse than an unresolved row; ambiguous matches require review. |
| Mutating original estimated cost snapshots or raw imported provider rows | Estimates and source evidence must remain auditable; adjustments are explicit overlays. |
| OPS-02 live/browser/provider UAT closure without operator evidence | Live UAT requires credentials, provider approval, budget, cleanup window, and final provider-side billable resource verification. |
| Multi-session cloud workers | One server per worker remains the safe billing, firewall, port, storage, and cleanup model. |
| Multi-provider billing adapters | Hetzner remains the first real cloud target until invoice/export reconciliation is proven. |
| Removing local worker support | Existing local Arma 3 hosting must remain usable while cloud orchestration expands. |
| Kubernetes or generic cluster platform | Explicitly excluded by CR-0001 as an early target. |
