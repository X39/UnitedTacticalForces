# Phase 45 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Microsoft Fluent UI Blazor |
| Preset | not applicable |
| Component library | Microsoft.FluentUI.AspNetCore.Components |
| Icon library | Microsoft Fluent UI Icons via `Icons.Regular.Size20` and `Icons.Regular.Size24` |
| Font | Fluent UI/system default inherited from `FluentDesignTheme` |

Use the existing `/servers` operational-panel style, not a marketing or landing-page layout. The primary surface is an embedded `detail-section cloud-live-preflight-panel` in the selected-server workflow, with `FluentButton`, `FluentMessageBar`, status badges, metadata rows, and compact data grids.

---

## Visual Hierarchy And Interaction Contract

| Contract | Value |
|----------|-------|
| Primary focal point | The "Live preflight" readiness panel header and status badge for the selected server. |
| Secondary focal point | The evidence checklist rows: approval, authenticated access, provider readiness, billing owner, dry-run, template/profile, cost, policy, reconciliation, Phase 40 readiness, and redaction. |
| Tertiary content | Safe timestamps, labels, blocking reasons, and next-step diagnostics. |
| Navigation model | Stay inside the existing `/servers` selected-server details workflow; do not introduce a separate landing page. |
| Interaction density | Dense operational scanning: label, status, timestamp; avoid decorative cards and oversized copy. |
| Icon labels | Every icon action keeps visible text. Icon-only controls are not allowed for this phase. |
| Loading state | Use existing `FluentProgress` plus text such as "Loading live preflight evidence...". |
| Blocked state | Keep provider mutation controls disabled and show a warning/error message with safe blocking reasons. |

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Fluent theme canvas, `#ffffff` in light mode and dark theme canvas in dark mode | Page background, main selected-server detail surface, table rows |
| Secondary (30%) | `#f7f9fb` and `var(--neutral-fill-secondary-rest)` | Empty states, summary blocks, disabled/read-only evidence surfaces |
| Accent (10%) | `#BAA05A` theme accent and existing `#2563eb` operational info border | Primary preflight action, active/readiness emphasis, selected operational panel border, focus-visible states |
| Destructive | `#b42318` / `var(--error)` | Blocking reasons and error text only; no destructive action is introduced in Phase 45 |

Accent reserved for: `Record preflight approval`, `Refresh preflight evidence` when it is the primary available action, verified readiness emphasis, selected preflight panel border, and keyboard focus indicators.

Do not use accent for every button, every link, or decorative backgrounds. Warning and danger states keep the existing status palette: warning `#b54708`, success `#027a48`, danger `#b42318`, info `#2563eb`.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Record preflight approval |
| Secondary CTA | Refresh preflight evidence |
| Empty state heading | No live preflight evidence recorded |
| Empty state body | Record approval, authenticated access, provider readiness, owner, dry-run, cost, policy, reconciliation, and redaction evidence before provisioning. |
| Loading state | Loading live preflight evidence... |
| Error state | Live preflight evidence could not be loaded. Refresh the selected server, then review safe API diagnostics if the problem continues. |
| Blocked state | Live provider mutation is blocked until every preflight requirement passes. |
| Destructive confirmation | None in Phase 45; provider mutation remains unavailable until a later approved provisioning phase. |

Copy must not claim live Hetzner, Steam, Arma, teardown, cleanup, authenticated browser, or final billable-resource pass status without captured evidence. Error and blocked text must not include provider tokens, Steam credentials, worker credentials, worker hashes, authorization headers, bearer tokens, cookies, OAuth material, or raw secret-bearing payloads.

---

## Evidence Rows

Use the same compact row shape for each preflight evidence kind:

| Column | Contract |
|--------|----------|
| Evidence label | Short operational noun phrase, 2-5 words. |
| Status | Status badge using existing status classes. |
| Timestamp | Verified timestamp when present; otherwise last updated timestamp. |
| Diagnostics | Safe blocking reasons below the grid in a warning/error message list. |

Required evidence labels: Approval package, Authenticated admin, Authenticated owner, Provider configuration, Provider metadata, Billing owner, Dry-run plan, Template/profile, Cost budget, Policy state, Reconciliation state, Phase 40 readiness, Redaction check.

---

## Responsive Contract

At widths below 860px, the preflight row grid collapses to one column, action buttons stretch to full width, and blocking reasons remain below the evidence grid. Text must wrap within the panel; timestamps and ids must use `overflow-wrap: anywhere` through existing metadata patterns.
